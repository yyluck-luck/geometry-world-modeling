# 真实参考数据可行性：先核数据能否回答问题

本次实际核查发生于2026-09-08，精确起止UTC、输入SHA和结果见同目录`reference_time_feasibility.json`。这是**真实数据时间索引分析**，没有打开照片正文，没有生成视频，也没有测量方法效果。

当前结论：**现有本机两条TUM单RGB序列不能在现有同步规则下供应三张独立参考。C1/C2也没有合格参考，所以完整的“记忆效用”实验尚不可执行。**

| 数据 | 原始RGB索引条数 | 最小相邻间隔 | 任意20毫秒窗口内最多照片数 | 目标前后10毫秒内其他照片数最大值 |
|---|---:|---:|---:|---:|
| TUM fr1_xyz | 798 | 27.457 ms | 1 | 0 |
| TUM fr2_desk | 2965 | 23.974 ms | 1 | 0 |

fr2原目录与时间戳修正目录的RGB索引SHA完全相同，是同一次拍摄的两份索引；不能作为两份独立参考。脚本用精确整数纳秒解析，并用滑动窗口和逐项枚举两种算法核对最大窗口计数。

推导很简单：若三张参考都要在同一目标时刻的前后10毫秒内，它们必须一起落入一个长度20毫秒的窗口。已检查的索引在这种窗口最多只有一张照片，尚未考虑相机、遮挡、曝光、身份和未输入模型等更严格条件，就已不满足必要条件。

这里使用公开传感器时间戳，没有实测新的偏移/漂移校准。共同常数时钟偏移不会改变帧间距；不能用随意改时间戳或文件mtime让数据“通过”。本结论也不排除其他多相机数据，或另行论证过的静态场景参考协议。
