# 3D-Mem 与“首次消失前后帧对”：最后一项来源核对

实际核验：2026-09-10 16:12:21–16:13:01 UTC（北京时间 09-11 00:12:21–00:13:01，工具前后时钟界）。只复核 **3D-Mem 作者 v5，2025-04-04**：[原文](https://arxiv.org/html/2411.17735v5)。没有新增其他工作、读取数据、运行模型或审计仓库代码。

**结论：否决把“保留对象关系原图，后来再读取”作为新颖性主张。未核到与“首次消失前后帧对”完全相同的规则，也不能说它的选图算法必然包含该帧对；这种不相同不构成创新证据。**

已读算法每个共视对象簇选一张代表图，优先图中检测对象多者，再按检测置信度之和破同分；分配给各 snapshot 的对象簇不重叠，相同图的簇会合并。新增观察触发相关簇重建；候选帧集合按历史并集更新。原文没有在该规则里加入“首次消失”触发或前后帧成对保留条件。[算法 1、§3.1–3.2.2](https://arxiv.org/html/2411.17735v5#S3)

**直接比较（本报告的逻辑分析，未运行新玩具）：** 如果消失前一帧同时看到球和杯，消失后一帧只检测到杯，将球和杯组成一个共视簇时，后一帧不满足覆盖该簇的条件。算法可以只取前一帧，因此“保留任意共视图”并不保证保留时间上的前后对。反过来，多簇选图也可能碰巧留下两帧，不能把碰巧重合说成同一时间规则。论文已明确面向静态环境；不能把这一限制说成候选已经解决的动态问题。[§7.3](https://arxiv.org/html/2411.17735v5#S7.SS3)

成本口径也不同：检索的 K 限制相关类别数；§3.1 另用 K 表示 snapshot 数量，二者不能混淆。A-EQA 报平均 10.94 个 snapshots，筛后输入平均 3.26 张图；不是持久总字节上限。表 6 列 A-EQA 的提升到三维、聚类、预筛和 VLM 延迟分别为 2.43/0.04/1.12/3.34 秒，并讨论缓存预筛结果、降低高层查询频率。[§3.2.3、§4.1、§7.2–7.3](https://arxiv.org/html/2411.17735v5)

在上述已读范围，**没有核到**“所有旧候选/状态/缓存计入固定字节 B”或“每张旧图重读次数、累计 tokens 和完整历史处理成本”的共同上限。组件延迟及平均送入帧数不能替代这些账目；也不能据局部阅读断言整套代码一定没有其他计量。
