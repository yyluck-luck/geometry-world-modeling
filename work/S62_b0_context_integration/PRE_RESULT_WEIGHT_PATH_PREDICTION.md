## 条件结论及旧事实

若原路径与S61路径均让同一组5个合法历史来源参与投票，`context_num_frames=4`，则票重数值本身不改变候选配额；在其余调用状态、相机计算和相等距离的处理相同的条件下，最终context ID顺序及按ID读取的缓存内容应相同。

这不是新发现。[S34结果第74行](../../docs/S34_RESULTS.md)已经写明“n=min(context4+10,k)=k，每来源1，权重变化不改变配额”；[S34独立核协议第9行](../S34_consumer_numeric_review/protocol.md)已说明cos=0仍建立source、cos<0跳过、只有参与来源集合变化才改变该域候选。其实际范围为最多8个来源，最终NMS/context没有执行。本次唯一可新增的证据是：条件是否在真实B0输入上成立，以及预测是否穿过真实context/NMS/cache调用链。S61此前“权重可能影响配额/NMS”的一般边界需按本条件收窄，旧报告不改。

## 从原代码到预测

源码为`work/S20_environment/isolated_vmem_source/modeling/pipeline.py`，SHA `680da1c14db8a6780a37fca3a8bac5bb59f0aa7d395db96d4360b352eb7f2255`。

1. `process_retrieved_spatial_information:462–494`先形成字典`timestep_count`；令k为其不同来源key数，n=min(4+10,k)。因此**0≤k≤14时n=k**，不是仅在k=5时成立。
2. `get_frame_distribution:422–438`仅检查k>n分支；否则先构造`[1]*k`，当n−k=0立即返回，尚未读取任何ratio值。因此只要调用能到达该分支，每个参与来源配额恰为1。
3. `process...:494–498`把配额按原key配回，再按source ID排序。故相同合法整数来源集合即得到相同、按ID排序的候选序列；此前字典插入顺序不同也不会保留到这一序列。`get_context_info:647`还直接丢弃返回的timestep_weights，仅消费frame_count。
4. `get_context_info:655–750`依候选构造geodesic distances，随后排序、按相机两两距离设NMS阈值及补齐。该段不再读取depth/cos/weight。若候选序列、target/history c2w、translation_distance_weight、dtype/device/函数和tie处理相同，且history长度、cache长度、NMS模式/初始阈值状态相同，所选ID序列应相同。
5. `prepare_context_data:517–522`按这些ID读取c2ws/latents/encoder_embeddings/Ks。还需缓存各列表内容及索引合同未变，才能预测返回张量内容相同；“选中ID相同”本身不证明缓存内容或完整生成相同。

有限纯代数例子：5个来源的合法权重从`[.96,.01,.01,.01,.01]`变成`[.05,.05,.05,.05,.80]`，两者都给`n=k=5 → [1,1,1,1,1]`。这是对分支的直接推演，没有执行人工测试或读取实测权重。相反，k=15时n=14，原423–429行会按ratio挑top14；此时权重变化可改变哪一个来源被排除，不能推广“权重永远无作用”。

## 严格条件和例外

- **k不是几何可见点数，也不是正票重来源数。** 先取index≥0的像素，再跳过cos<0；余下像素关联的source key才构成集合。cos=0仍可建key，即使票重为0也获得该域配额。法线/裁面/栅格化改变可能增删key；相同k但不同成员不足以保证候选相同。
- 同一来源的多个像素、列表中重复source、以及原首次贡献双加会改变累积权重，却在n=k域不会创造该source的额外候选份数，因为字典key唯一。重复或不合法ID仍要按原cache合同审计；不能以这条推论承诺去重修复。
- 空集合k=0返回空配额；后续`sorted_frames[0]`仍会报错。该预测要求非空同一成员集合，不能由归一化或n=k推定永不为空。
- NaN不是可靠例外证据：NaN cos的`cos<0`为假，零总票重/非有限深度也可能产生NaN ratios，而n=k的提前返回甚至可能仍给全1。它说明原分配器不验证权重有效性，不说明该输入科学有效。两路径都须遵守既定有限值/合法index/合法source合同；若额外验证拒绝其中一路，要记为接口/输入失败，不能误写成票重驱动了NMS。
- 源码使用未声明stable的`torch.argsort`。相等或近等距离涉及tie顺序、精度和运行环境；必须核相同候选顺序和距离输入。不能把跨版本/设备或舍入差导致的变化归因于权重。NMS关闭时原码还会追加最新帧，可能形成重复；不在这里承诺结果总是4个唯一ID。
- query/history相机、目标平均姿态、NMS设置、可用缓存数或`initial_threshold`状态一旦改变，就越过本预测条件。S61仅局部单位适配应保留这些量，但那是本次集成须核的事实，而非本报告已核结果。

## 在看结果之前规定解释

**预测A：** 同一非空来源集合且1≤k≤14、其余条件成立时，两路径frame_count应逐项相同；即使权重改变，也不能据此预期实际缓存选择改变。

**预测B：** 进一步核上述camera/NMS/tie/cache条件后，最终ID顺序及对应cache条件应相同。若通过，只能说明这条成功B0输入上组件接线和缓存回归成立，不证明画质增益、C2恢复、较大来源池行为或source utility。

若配额/顺序/缓存不符，先逐项检查来源成员、n/k、实际调用的分配函数、候选序列、距离/tie、NMS状态、cache副作用和输入合同。全部前提若确实成立而仍不符，就推翻本次源码到执行路径的等价推断并报告实现/接线差异；不得事后改预测或用“票重不同”直接解释。若成员改变，则条件预测未适用，应如实记录单位适配改变了可达来源，而非宣称证伪了n=k代数。
