# When old S70 A0 can serve as the fixed-noise baseline

**Decision:** Reusing accepted A0 and generating only the proposed rotated arm can be valid. A new baseline is not automatically necessary: S70 already demonstrated A0/A1 byte replay. This is future protocol advice only; the current VAE-only diagnostic is unchanged.

**Primary-source boundary.** CamVerse v1 §3.3/§4.1 uses stochastic group rollouts and three initial SDE steps in GRPO; this is training exploration, not evidence that its illustrated different-camera clips share actual noise. Section 4.2 compares π³-estimated generated/reference trajectories after similarity alignment, separately reporting confidence coverage and appearance. A text search found no “seed”; inspected text does not establish paired actual noise. [Paper](https://arxiv.org/html/2512.02870v1).

TTM v1 §3.2–3.3 noises a warped reference and performs masked noisy-reference overwrites. Those conditions differ from S70's unconditioned initial Gaussian draw. Crucially, Appendix B.2 tunes translation scale using warped-versus-original video MSE, rejects estimated scales below 0.3, and selects the 150 lowest warp-to-GT-MSE scenes. Its reconstruction-conditioned evaluation is not target-blind camera causality. Searches found no “seed” or “same noise”; no equality of actual noise is established by the inspected paper. No official implementation was checked in this batch. [Paper](https://arxiv.org/html/2511.08633v1).

## S70 already supplies the needed replay material

The accepted execution receipt reports all three arms complete, actual shared streams true, and exact A0/A1 latent/FP32/uint8 replay. It binds complete pre-do_sample Python, NumPy legacy and Torch CPU RNG state in `execution_01/common_rng.json` (file SHA `9a4ed856fd2cffdb0f7f7720feb38ea951f562be5238f325f3170d01b74f6ea4`). The canonical state SHA is `fdeb6b7bff4162a76a083c00479f649f4dc24e5e34325766dee33d360341ad71`. Actual A0 initial-noise body SHA is `19a3d567421dd5c088f4a254dcd9c8c7effb2d02773d520830b12e9bae1d86b7`. These were read only as receipt metadata, not revalidated against state/noise bodies in this task.

Reuse A0 if all of the following are met:

1. **Same computation apart from declared camera descendants.** Keep accepted model/weight values, eval modes, runtime/backend/CPU8 FP32, sampler-0, full shape/slot order, 50 steps, decode and quantizer. The new wrapper may change bindings/output paths; its sampling computation must remain the same. Keep history/cache/K/target centers fixed and regenerate every camera-dependent field, including original MultiviewCFG camera inputs. Do not freeze these descendants to force agreement.
2. **Restore at the correct boundary.** After model construction, new conditions and sampler setup, deserialize and verify the saved common state, then restore it immediately before original do_sample. Python nested sequences must regain tuple structure; NumPy's state keys and Torch's CPU state must regain their original uint32/uint8 representations. This later authorized run must verify the file and canonical-state identities. Do not restore the *post-initial-noise* sampler-entry state before do_sample: it would draw a different initial noise.
3. **Verify actual exogenous stream during the one new arm.** Match initial-noise raw bytes, sampler-entry state, all 50 before/after step RNG-state hashes and terminal state to A0. The same original random operations, shapes/dtypes/device/layout must remain. Original do_sample draws one torch.randn; every sampler_step draws randn_like even at churn zero, because sigma_hat adds 1e-6. Matching a seed alone is insufficient. Step epsilon bodies were not archived: equality relies on the pinned RNG implementation/draw path plus matching states, not a claim of direct epsilon-byte comparison.
4. **Check model values, not addresses across processes.** Match the archived value and eval-mode signatures; retain before/after checks in the new process. Python object IDs/data pointers in the old identity signature cannot be required to equal a new process's addresses.

The inspected S69 scaling/get_cond/Plücker helper closure and original camera-distance/MultiviewCFG path contain deterministic tensor geometry, with no random draw. Setup randomness before the final restore would not shift sampling. Any new stochastic camera operation after restore would invalidate the claimed sole +5° intervention unless removed or explicitly separated before restoring. An unused utility, get_value_dict, does consume `0 * randn_like`; do not accidentally substitute it for the actual get_cond path.

**When a new baseline is necessary:** the old state cannot actually be recovered/verified; sampling, backend, model precision/values or another behavior-affecting path changes; or the new stream fails the prescribed A0 comparison. Then old A0 is not a fixed-noise causal baseline. A separately frozen fresh pair under the new shared state/path can answer a new question; retain the failed comparison and do not retry for a favorable result. Merely loading in a new process, constructing deterministic new camera arrays, or changing create-only output paths does not by itself require rerunning the already stable baseline. A restored stream supports a single-realization relative-response test, not population robustness or absolute camera accuracy.
