## 本次能问的问题

在已暴露的一个场景中，给定相同的其它 155 个改写块，改写一个低 D 独有块还是一个 confidence 独有块，哪一种产生较低的目标深度损失？两臂的完整重投影、z-buffer 和来源赢家都必须重算。这个比较识别特定集合背景中的成对替换效果，不识别“置信度的因果作用”、单块绝对价值或所有记忆选择的总效应。

相同来源内匹配可排除来源身份差异；近似匹配平均改变量和 RMS 可缩小幅度差异，但块的位置、遮挡、深度、边缘结构和改变量形状仍可不同。即使结果为正，也只能说这批候选交换在这些背景中有益，不能说已证明新增信息量机制。

## 候选与幅度：同意 root 提议，须先冻结再扫描

1. 完全沿用 S99 的 16×16 块、每源 196 块及确定性并列规则。低 D 集合 L 和 confidence 集合 H 各含 39 块；候选分别来自 `L \ H` 和 `H \ L`，只在同一 source 内组成对。
2. 仅历史 old/new 深度、历史 confidence 用于形成候选。匹配幅度为 `a_b = mean(abs(new-old))/scale` 米及 `r_b = sqrt(mean(((new-old)/scale)^2))` 米。计算时均用同一 FP64 规则。
3. 在任何候选幅度分布扫描之前冻结：`max(a_low,a_conf)/min(a_low,a_conf) <= 1.10`，且 `max(r_low,r_conf)/min(r_low,r_conf) <= 1.25`。这分别约束平均绝对改变量与 RMS，但不是完全等幅度。
4. 对零幅度明确固定边界：建议拒绝 `min(a_low,a_conf) <= 1e-12 m` 的边，避免 0/0 和无实际改写的候选；该常数也须写入冻结协议。禁止通过 epsilon 分母把零幅度候选伪装为匹配。
5. 合格边按 `(abs(log(a_low/a_conf)), low_block_id, conf_block_id)` 排序，顺序贪心且任一块不得复用。明确这是确定性贪心匹配，不声称最大基数或总体最优匹配。记录所有候选数、合格边数、实际对数、未匹配数和每对两种幅度比。
6. 匹配不到就是 `NO_MATCH_UNDER_FROZEN_CALIPER`，不放宽阈值，不扩大 top39，不改为从全部块寻找胜者。零匹配是这个干预设计缺少可比样本，不是 confidence/low D 收益的科学负结果。

## 背景与预算

root 的每对两个预定随机背景可以执行。每个背景对两臂完全一致；焦点源从排除两个候选后的集合选 38 块，其余来源各选 39 块。每臂仍是每源 39 块、总计 156 块。保存实际块身份及 mask SHA，不能只保存 seed。明确固定 RNG 算法、seed、来源遍历顺序和候选对顺序，避免新增/缺失候选无意改变所有旧背景。

建议以 `(source ordinal, low block ID, conf block ID, context index)` 构造确定性 SeedSequence，或预先指定完整 seed 表。不要用 Python 内置 hash 生成 seed。背景在所有条件下只依赖历史候选身份与冻结 seed，绝不依赖未来覆盖率、误差或目标 GT 有效域。

最大 4 对/source × 4 sources × 2 contexts × 2 arms × 4 targets = **256 次主渲染**，数学上满足 256 主预算，但没有给 exact replay/端点额外渲染留余量。若用户预算是所有渲染总数，建议最多 **3 对/source**：192 次主渲染 + 第一合格对第一个背景两臂四目标 exact replay 的 8 次 + never/all_new 两端点四目标的 8 次 = **208 次总渲染**。无合格对时不为凑预算渲染；任一结果缺失都保留并解释。独立审查如果额外重渲染，应单列计数，不藏在零模型调用中。

## 固定 GT 域及缺失安全评分

同意 primary：每个目标固定 `G={finite(gt) and gt>0}`，与两臂、候选、背景都无关。对预测有效值，定义 `ell_tau=min(abs(pred-gt)/gt,tau)`；缺失、非正或非有限预测的 `ell_tau=tau`。主 tau=1；tau=0.5、2 为预先冻结敏感性。主收益 `B=mean_G(ell_low)-mean_G(ell_conf)`，正数支持该次替换。

这个有界损失不会奖励删掉困难预测：缺失承担最高单像素损失，但它主动截断了超阈值错误的大小。必须直接称“全 GT 截断 AbsRel 损失”，不能把它写成普通 AbsRel，也不能用它证明极大错误尾部已经改善。三种 cap 一律完整展示；cap 改变结论时报告指标敏感性，不挑支持假设的一种。

同时报告全 GT 的 delta1、coverage、GT 分母、预测缺失数、两臂共有/仅 low/仅 conf/均无预测的像素数。共有域普通 AbsRel、MAE、worst5 可作补充机制诊断，域大小必须同时报告；不同对的共有域上不可直接横比并声称公平整体收益。

全 GT 截断损失的 fractional worst5 可严格定义，但当前消费者缺失可能使最高 5% 全为 tau；这时指标饱和而无法分辨，应原样记录，不能结果后丢掉缺失像素以制造尾部差别。可补充固定 GT 上 `ell_low-ell_conf` 的均值与正/负/零比例来解释改善/恶化在哪里，不把这种有符号差值尾部混同为绝对误差 CVaR。

## 两背景交互怎样解释

先保存每对 × 背景 × 目标的有符号 B。建议固定容差 `epsilon=1e-10` 损失单位，exact replay 必须逐值相同，否则先停止核查，不结果后放宽 epsilon。对同一对、同一目标，若一个背景 B>epsilon，另一个 B<−epsilon，则观察到这个比较的背景反号。另报告每对四目标等权 B 的背景反号，两者不能互相代替。

两个背景足以找反例，不能估计反号“频率”或证明对所有背景稳定。没有反号只表示这两个背景未观察到反号；若反号出现，支持在当前几何消费者中存在上下文依赖，不直接证明具体遮挡机制；可查 source-ID 变化提供定位证据。目标和背景高度相关，不做独立场景置信区间、显著性检验或把像素数量当样本量。

汇总顺序须冻结：先四目标等权、再两个背景等权、再 source 内各匹配对等权，最后对有匹配 source 等权；同时完整展示各层结果和 source 匹配数。若 source 缺失，汇总只能注明“有匹配来源的描述”，不得写成完整四源策略优势。平均正收益也不能抹去反号、某个 source 失败或 delta1 下降。
