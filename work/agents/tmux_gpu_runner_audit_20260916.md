# Persistent GPU Runner Audit (2026-09-16)

## Scope

Static and shell checks only. No training, inference, or formal Slurm submission was started. Reviewed:

- `work/remote_tmux/launch_slurm_in_tmux.sh`
- `work/remote_tmux/README.md`
- `work/S102_gate0_tum/run_tum_gate0.slurm`
- `work/S103_H800_VMEM_BASELINE_PREFLIGHT_20260915.json`
- `work/S102_gate0_tum/GATE0_CURRENT_DECISION_20260916.json`

A fake `tmux` shim captured the exact detached command generated by the launcher; `bash -n` passed for the launcher and S102 Slurm script. No remote job was submitted by this audit.

## Findings

### 1. VPN resilience: operationally sound after submission

`tmux new-session -d` keeps the submission/monitor shell alive, and Slurm owns the allocation after `sbatch` returns. Reconnection instructions and `sacct` verification are documented. This satisfies the current project requirement that long GPU work be started in a remote `tmux`/`screen` session.

### 2. The launcher is not an executable Gate0 guard (HIGH)

The launcher accepts any sbatch path and submits it. Gate0 is only a comment in the README; the launcher does not call `validate_gate0_contract.py`, verify `formal_status=PASS`, or bind a signed manifest. A future operator could accidentally submit a formal script before Gate0 passes. The current contract remains BLOCKED and no formal S103 script exists, so no accidental run occurred.

**Minimal fix:** add a separate `launch_formal_after_gate0.sh` wrapper that (a) validates the contract, (b) checks `formal_status=PASS`, (c) checks a signed manifest SHA, then (d) invokes the existing tmux launcher. Keep the generic launcher unchanged for smoke/metadata jobs. This avoids adding a hidden approval rule to every diagnostic job.

### 3. Argument quoting is fragile (MEDIUM)

The launcher interpolates session, sbatch path, and log path into one nested `bash -lc` string. The current absolute paths contain no spaces, so the captured command is valid. Paths containing spaces, quotes, or shell metacharacters could be split or interpreted. This is an operational correctness issue, not a scientific result.

**Minimal fix:** have tmux run a small remote helper script with positional arguments (or use `printf '%q'` for each value); do not interpolate raw paths into nested shell source.

### 4. Failure receipt capture is incomplete (MEDIUM)

The monitor records job ID and final `sacct`, but it does not write a structured JSON receipt, record the contract/manifest SHA, or explicitly record `sbatch` stderr when submission fails. The remote Slurm job log may still exist, but the launcher log alone is not a complete handoff artifact.

**Minimal fix:** in the formal wrapper, create a dated run directory and record `{session, job_id, submit_time, manifest_sha, state, exit_code, sacct_path}` after completion. Preserve stdout/stderr with `tee`; never auto-resubmit.

### 5. Job monitoring is persistent but not fully defensive (LOW)

The loop polls `squeue` every 30 seconds and then calls `sacct`. This is adequate for ordinary completion. If accounting is temporarily unavailable, the shell can exit without a final structured state. `squeue`/`sacct` failures are not consistently logged separately.

**Minimal fix:** retain the existing loop, but append command exit status and a final `sacct` retry (bounded, e.g. three attempts) in the formal wrapper. Do not add indefinite waiting.

### 6. S103 formal launch artifact is absent (BLOCKER, not a launcher defect)

Only the no-data smoke script and preflight metadata are present in the local/remote transport tree. There is no formal S103 Slurm script to run. Creating one before the Gate0 contract is signed would be premature; after PASS it should be created from the signed manifest and launched via the guarded wrapper.

### 7. S102 metadata job correctly requests one GPU

`run_tum_gate0.slurm` includes `#SBATCH --gpus=1` to satisfy the SuperPOD QOS, while the Python task performs metadata qualification only. This is wasteful in resource terms but required by the observed QOS policy; it is not a model experiment and must remain labelled accordingly.

## Minimal change set (ordered)

1. Keep the existing detached tmux launcher and reconnection procedure.
2. Add a formal-only Gate0/manifest guard wrapper; do not modify the generic launcher semantics.
3. Harden path passing through a helper script or shell-escaped positional arguments.
4. Add a structured receipt and bounded `sacct` retry to the formal wrapper.
5. Generate the S103 Slurm script only after the contract validator returns PASS and the signed manifest is sealed.

No change is recommended to the scientific gates, held-out isolation, or innovation criteria. This audit does not authorize S103 or GRC/SOCF scoring.
