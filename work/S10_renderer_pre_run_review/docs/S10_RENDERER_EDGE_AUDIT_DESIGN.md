# S10 渲染器独立人工边界检查设计

本设计只针对固定 `src/vmem_retrieval_kernel.py` 的完整渲染数组语义，候选通过 `renderer_function()` 返回可绑定的函数。设计阶段没有读取候选实现或真实地图。人工输入与后续实际检查时点将先写入每次新目录的 `pre_run.json`，失败结果也保留。

已直接核当前项目环境 `.venv` 为 NumPy 2.3.5。令 `x=1+3*2^-25`，其 float32 存值向上舍入；实际 `Python float x < np.float32(buf)` 与 `x < float32 array` 均为 False，`np.float64(x) < buf` 或把数组转为 float64 则为 True。不能凭“比较更精确”改写原输出。完整官方版本解释另由独立代理查 NumPy 原始文档，本测试不把其他环境的行为当作当前环境事实。

检查范围：

1. 同一精确深度先写保留；向上舍入后的重复深度不覆盖；同一 float32 桶中的略近深度仍不覆盖；跨越 float32 桶的近深度覆盖。逐 surfel 顺序必须保留。
2. 整数网格上的四边形/三角形边界、半像素偏移、圆盘被图像裁剪。原 polygon 分母的 epsilon 为 **1e-15**，直接提取原局部函数另做顺逆序、退化、重复顶点与 epsilon 尺度输入检查。
3. 零半径、微小半径、零/阈值附近法向、背面、零余弦；不擅自修正原算法的退化处理。
4. 中心 near=0.1、far=1000 的严格不等式，nextafter 两侧；左侧 margin=-50 包含与右侧 width+50 排除；圆盘部分顶点深度非正、零深度顶点与少于三个顶点。
5. float32 几何、Torch 相机参数转换、非方图像和非等焦距；固定种子 24 份各五个 surfel 的人工小混合输入补充组合覆盖。

目前共 60 个完整渲染用例，外加 6 组原 polygon 局部探针。对 depth/ID/cos 三数组检查形状、dtype 与逐字节相同，容差为零。告警记录但不作告警文本相同保证；不读取图片/GT，不加载模型，不做性能测量。

为了确认检查确实有辨别力，保留五种内存中的已知错误变体：深度比较强转 float64、将 `<` 改 `<=`、polygon 取像素中心加 0.5、删除 polygon 的 1e-15 epsilon、near plane 改为包含边界。它们必须被人工测试拒绝，不写回任何原源码。首轮 baseline 先验证前四类（不含 epsilon），随后在不看候选的条件下确认现有 diamond 边界能检出删除 epsilon；补齐此负对照后另存 baseline_v2，原结果保留。

入口：`scripts/s10_renderer_edge_audit.py --out 新目录` 先核基准与测试断言；加 `--candidate-module src.s10_vectorized_renderer` 才比较候选。每次目录必须不存在，源码/脚本/候选 SHA 在调用前后检查。有限人工测试不能证明所有输入等价；普通 NumPy 向量化不是论文创新，任何速度结论都需另行预定公平测量。
