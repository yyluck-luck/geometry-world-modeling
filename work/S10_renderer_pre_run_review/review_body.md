## 原语义与候选实现

| 环节 | 必须保留、且当前静态核对已保留的规则 |
|---|---|
| 输出和相机 | ID int32 初始 −1，深度/余弦 FP32；Torch→NumPy、R 的逆、平移、齐次除法、焦距与主点保持原 AST。 |
| 中心过滤 | 中心深度严格 >0.1、<1000；屏幕 margin=50，左边包含、右边排除。没有换成另一套整片裁剪规则。 |
| 面片顺序 | 原索引升序逐片运行；法向 1e-12 阈值、归一化、负余弦跳过（零保留）、up 轴 0.9 阈值与叉积均不动。 |
| 圆盘 | 默认16顶点、endpoint=False 的原角序；只取 depth>0 顶点，少于3点跳过。整片深度仍为有效顶点深度均值，没有换成逐像素插值。 |
| 像素范围 | floor/ceil 包围盒、裁剪、含两端整数像素坐标保持不变；没有 +0.5 偏移。空包围盒返回等同原空循环。 |
| 多边形 | 从末顶点作为 j 开始，原逐边次序、y 严格 >、x 严格 <、分母 **1e-15** 及乘减除加顺序保留。任务概述中的1e-8不能代替实际原源码。 |
| 批量化 | roll 对应原前一顶点，先选 y crossing 才算交点，保持短路条件；logical_xor.at 对重复 row 累积，避免普通高级索引赋值漏计。 |
| 遮挡比较 | FP64几何求均值后，原代码明确 float(...) 转 Python 标量。候选保留此身份，与 FP32 数组严格 < 后再写 FP32；未强制 FP64 比较、改 ≤ 或重排面片。 |
| 返回与动态输入 | 无命中 inf 深度最后置0，三个键保持。无跨查询缓存、无参考渲染读取、无输入改写；无需 query 固定或 source 不增删。 |

候选工厂限定 NumPy 2.3.5 与原文件 SHA，只替换精确匹配的一处嵌套像素循环；还原该循环后全方法 AST 必须相同。相对与顶层导入分别解析对应的同一源文件，runner 另核真实模块路径。转换身份、原文和转换后代码在计时外保存。结构守卫能排除其他语句被改，不能代替内层数学的有限边界测试或全域证明。本合同针对输出数组，不保证任意输入的告警次数、文本或跨版本异常完全相同。

独立核过四份 NumPy 官方原文并存 HTML、时间与 SHA 于 `work/s10_numpy_promotion_sources/`。[NEP 50](https://numpy.org/neps/nep-0050-scalar-promotion.html)明确规则适用于比较；[2.0迁移指南](https://numpy.org/doc/2.0/numpy_2_0_migration_guide.html#changes-to-numpy-data-type-promotion)与[2.3标量规则](https://numpy.org/doc/2.3/reference/arrays.promotion.html#detailed-behavior-of-python-scalars)说明 Python 标量与显式 NumPy 标量的精度区别；[1.26 result_type](https://numpy.org/doc/1.26/reference/generated/numpy.result_type.html#notes)记录旧 legacy 行为。保留 Python float 与保留显式 np.float64 可能改变严格遮挡胜负，“比较精度更高”不保证原语义等价。本审查未运行版本探针，不把其他代理的本机结果冒称自己执行，也不保证跨版本输出一致。

## 公平比较与证据门

A/B 在同一进程重新测量，S9旧耗时仅用于选题。六份 block kernel 在两方法间深复制，初始化状态相同且可变 kernel 不共享；每调用外核地图/来源、history、K、占位上下文、阈值与query。原 get_context_info 未插桩，两 renderer 套同一 observer；唯一替换 renderer，原票权/配额、FP64几何距离、默认FP32排序、NMS及后备分支保留。

每对先完成两次调用，再统一保存和校验，避免在两臂间插入验证。计时包含完整选图组件与共同 observer 开销；解码、工厂、深复制、绑定、校验、压缩保存均在外。占位 latent/embedding 很小，因此不是完整VMem、大上下文搬运或视频生成耗时。

先48次正确性，再48次预热，最后240次测量。120个测量对总体AB/BA为60/60；每query五次只能3/2或2/3，协议已明确并另列AB/BA统计。主比值为整数纳秒总和之比；另列分组、逐query中位数和配对比值，不选最快轮，不把重复当独立样本。最终版本的八项独立纯合同/调度核验见 `work/S10_renderer_pre_run_review/pure_schedule_check_final.json`。

原S9门先核 shape/dtype/np.array_equal，新S10另核三数组的 C 顺序 bytes，补齐正零/负零，因此最终门强制逐值与字节一致。每次保存实际三数组及内容SHA，完整官方trace/decision与旧封存参考逐值比较。验证getter只返回刚产生的当前结果，没有用参考替代渲染。只有336次全部通过且336+336份render/trace齐备才completed；失败保留，不用部分计时给速度结论。

前后核十二份源、同旧S9冻结的52份输入，以及协议/两份执行冻结。版本固定，导入前设线程环境，核实际Torch线程与默认dtype。600秒及16GiB是软守卫，Python I/O守卫不是OS沙箱；其他本机进程仍可能影响计时，AB/BA不能消除全部噪声。24查询、六图、两场景均已见且含S7 development，不能称外部泛化或新独立样本。
