# S83 保存结果独立核验计划

仅使用 NumPy 读取此次 S83 已保存的 6 个完整 NPZ、RECEIPT、STEPS 和父监督回执。先封存核验程序并由 root 核读，再运行一次核验。程序不导入 Torch、原 optimizer 或生成模型，不重开 S82 raw heads、S69 cameras、原 RGB 或真实传感器深度。

1. 按 root 给出的 RECEIPT 与监督回执 SHA 固定实际执行身份；核六份产物的路径、完整档案 bytes/SHA、每数组键/shape/dtype/有限性/完整 body SHA。原输入身份通过已冻结合同与实际读取记录核对，明确不声称重新解码了原输入。
2. 核 4 个历史 ID 与三条 star edge、固定给定 P/K、训练参数名单、100 行步号与原线性学习率。四份梯度和参数改变量逐步核 None/finite/shape/dtype/统计/SHA 格式和 leaf 身份记录；这些是运行时日志证据，未保存每步全数组，不能独立复算 400 份梯度。
3. 初始化、100 步后清理前和清理后的全部四张深度（每张 384×512）独立计算：`Xc=[(u-cx)*Z/fx,(v-cy)*Z/fy,Z]`，`Xw=R*Xc+t`。整数像素格，不做采样、挑点或删除。以 NumPy float64 与原 float32 保存点做计算一致性核验，事先固定 atol=2e-5、rtol=1e-5；只属浮点算术容差，不是几何好坏门槛，不以看到的结果调整。
4. 独立核给定相机 float64→float32、原合同名义 K、三份状态 P/K 完全一致与原给定值误差在已有合同容差内。初始化与最后 log-depth 差值独立重算到 body SHA/非零数/最大值/范数；清理前后除 confidence 外全量数组完全相同，改变的 confidence 只能变为原 clean 规定的 0。输出全量范围，零改动数也照实保留，不新增成功比例门。

本核验不会独立重算 loss 或判断它是否是物理真值，不判断收敛、强基线是否足够强、创新或生成改善。源审已明确，原 S82 raw 的三次尝试与 S83 一次优化分开记账。

执行成功后输出 `OUTPUT_REVIEW.json`（拒绝覆盖）；如有失败，保留实际报错并区分保存结果问题与核验器 schema 问题，不调计算容差隐藏失败。
