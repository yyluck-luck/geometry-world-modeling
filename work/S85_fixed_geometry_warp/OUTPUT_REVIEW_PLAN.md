# S85 独立输出复算计划

本核验器由不同作者独立编写，不导入投影器。准备阶段只完成 AST 解析与内存编译，没有读取原 NPZ 数值或执行核验。

1. 根任务先读冻结源码与检查合同，然后明确给出真实 `RECEIPT.json` 的 SHA 并授权一次运行。既有文件不覆盖，失败保留完整异常，不自动重试。
2. 从原 S83 清理前状态与原 S69 相机档案读取指定字段，以原合同逐项验证整个文件和字段身份。另核保存的 INPUT_GEOMETRY 与原始值及字节严格一致，复算参考始终使用原输入。
3. 对全部 4×4 对逐源点重建相机坐标、投影、互斥状态和四邻足迹。浮点表达保留原合同的加乘顺序；不修改边界、舍入、姿态或 K。
4. 候选完整性采用另一核验路线：保存的来源身份必须正好是全部合格足迹的无重复排列；逐相邻完整键验证排序。由该已证完整有序序列独立得到 rank、第一/第二候选、mask、孔洞、计数和原 RGB。无需调用或重跑作者的排序函数。
5. 对全部目标 31 字段及 16 对摘要逐项比较。索引、状态、资格、顺序、RGB、缺失位置和汇总严格一致。XYZ/UV/权重/Z 的数值容差固定为 `1e-10 + 1e-12*abs(reference)`，每字段保存最大绝对差；容差绝不参与资格或排序。这只是浮点核验，不能当几何质量门。

完整运行预期只读 2 份原档案、1 份实际消费副本、4 份目标档案，共 7 个 NPZ；各一次读取和解码指定字段。保存一个复核 JSON，不新建图、CSV、模型、优化或视频。300 秒闹钟与逐目标 8 GiB 自进程峰值检查是执行预算，不是质量阈值。

即使 PASS，也只支持固定状态在已暴露单场景中的数值实现与保存一致。3,145,728 行、足迹数和覆盖不能称独立场景数、准确率、物理可见性或生成改进。
