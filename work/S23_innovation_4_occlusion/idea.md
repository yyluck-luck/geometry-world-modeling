# 方向 4：遮挡、场景变化与生成条件的有效期

记录：2026-09-06；作者：/root/s15b_bonn_resolution；版本 R4-v1；状态 **proposed_unvalidated**。结论是 **revise：保留一个待证伪的问题，尚未确立新方法**。本轮仅查文献和代码，没有跑模型、解码实拍、读取 S23 新 GT、下载数据或调用 Claude 模型。

给初学者的一句话：杯子被挡住时不应被忘掉；桌面重新露出且杯子确已移走时，旧照片里的杯子也不应继续影响下一段生成。前半句已有很强研究；后半句要追到生成器真正吃进去的两种旧特征，才可能留下一个更具体的问题。

本卡使用本地 Claude scientific-brainstorming 的假设反转、反例和廉价验证流程，以及 Supervisor 全读审计的行动映射与十字段验收卡。项目事实来自当前原则、日志、S22 报告和原 proposal；本 agent 没有把 root 读完手册等同于自己读完全部 70 页，也不替用户声称理解、投入时数或导师认可。

## 1. important_failure — 重要失败及已有证据

**还没有在本项目实测到强基线的“真实物体移走后又被生成回来”。** S22 已完成 CUT3R/TTT3R/FILT3R 在同一 TUM fr2_desk 300 帧片段的真实几何基线；它是静态场景中的相机运动，不能当作自然物体变化基准。轨迹残差也不能推出动态记忆或视频失败。S23 的新 GT 诊断不在本卡读取范围。

可定位的必要接口风险是：VMem 原代码按检索出的帧 ID 直接取缓存的 latent 与 image embedding；后者在 get_cond 中先对参考帧求均值，前者进入替换条件。生成帧又保存采样器 latent 和重新编码的 image embedding。因此，**地图记录失效与实际条件失效是两个不同动作**；只改变地图或几何票数，并不由接口自动保证所有过期区域信息已撤回。这个是源码可达性推断，尚不是模型会画错的实验结果。[原 VMem 固定源码](https://github.com/runjiali-rl/vmem/blob/39291e4f272f6b4f270691d930926ab5930f942e/modeling/pipeline.py)

实际读取行段：173–177（初图编码）、505–522（取缓存）、1123–1155（mean embedding/latent 条件）、1286–1295（生成后缓存）。本卡没有声称原 VMem 已有一个被我们发现漏更新的“删图功能”；研究对象是将动态几何更新接入此固定消费接口后是否产生失配。

与 proposal 的连接是“遮挡/重观察时的持久性和视觉一致性”，需要最终比较场景变化后的物体残影、错误复现、稳定区域质量及计算成本，不能只优化 ATE。

## 2. falsifiable_hypothesis — 一句可证伪假设

**在旧物体所在空间已被当前可见观测明确否定、而旧参考帧仍有可用静态区域时，让几何区域的失效事件同时约束 VAE latent 和全局图像 embedding 的实际构造，比只撤回几何或只遮一条条件通道更少保留过期物体条件；它必须在纯遮挡时不提前失效，并在对照已同时重建两条条件时不再有优势。**

这里“永久变化”操作化为“旧位置/旧外观版本不再有效”，不等于证明物体永远不会回来。空间状态、物体身份及历史记录分开；本卡不提出新的物体跟踪器或占据衰减规律。

正条件：真实变化已被看见，旧参考帧仍被检索，且原有条件通道含该旧区域。零条件：物体仅被遮挡；旧帧本来不被选；变化区域与所有被用条件无关；或简单基线已经同时正确刷新两个通道。

## 4. mechanism_difference — 可能的实质区别与致命反例

要修改的是**从地图区域到最终条件张量的依赖关系**，而非重命名一个动态分数。建议描述接口状态为：

- 区域版本 v：旧位置的几何/外观假说，保留历史，不自动宣判物体死亡。
- 观测事件 e：visible-consistent / occluded-or-unobserved / visibly-contradicted；判断器首先复用强现有方法，不把它算贡献。
- 条件构造器 C：为被选择帧输出 latent 和 embedding，同时给出它们实际依赖的区域版本。新显露证据若否定某版本，所有使用该旧版本的**实际条件**要重构或舍弃；遮挡本身不触发此操作。

任何对象级、空间级依赖都必须通过真实编码器成立。全局 CLIP embedding 混合了整图，不能凭二维 mask 宣称它已被局部清空；VAE 的有效依赖也不能假定恰好是 8×8 图块。最保守的全局依赖可能迫使整条 embedding 重编码或整帧退出。这是本假设的关键成本和失败风险，不是隐藏细节。

**去掉新部件会退化为**普通可见性更新 + 既有 frame retrieval；**最强简单替代**是 GaME 式 mask 后同时重新计算 latent 与 embedding、或者整个旧帧退出。若两者中任一个在相同条件/预算下已实现完全同一输出与成本，则候选整体是移植/缓存一致性工程，应 Reject 方法新颖性。即使发现 stale dependency，也不自动说明存在值得发表的新算法。

**更根本的反例**：一物体留在遮挡物后，另一物体已被移出但遮挡物不动；两种世界给相机的全部已见历史完全相同。被动算法不可能从相同信息判断哪一个会重现。此时只许保留未知/多种可能；不能用等待时长或 confidence 伪造永久消失证据。物理外推的额外假设必须明示。

## 6. minimal_discriminating_test — 最便宜且有否证力的实验

**M0：先做 0 模型的条件路径否证，不先跑新视频。** 在独立目录 AST 提取固定 VMem get_cond/取缓存必要函数，构造 2 个参考帧、2 个物体区域、一个 foreground occluder，给两条条件通道人工可区分标记；固定四个事件序列：仅遮挡后复现、显露旧位置为空、只移走对象 A 但 B 不变、不可区分的遮挡中移动/未移动。原图像/GT均不必打开。该实验只是软件必要条件，不测图像质量。

对照全部保留：

1. 原 frame 缓存；2. 同一可见性判断仅改变几何/检索；3. 仅 latent mask 但保留 embedding；
4. 同样的 mask + 两条通道一起刷新（GaME 式移植强对照）；5. 整帧退出/等预算新帧替换；
6. 候选依赖约束，必须具体实现后冻结，不能只给它正确人工标签而让对照猜。

所有方法使用相同事件输入、候选帧数及判断结果。M0 只用人工混合编码器验证依赖契约，**不能以人工编码器证明真实 VAE/CLIP 存在信息泄漏或提高生成质量**。若为避免这点仅做类型/来源 trace，就把结果写为接口检查。

固定输出：每次查询两条条件的来源版本/完整 hash、显露矛盾后过期依赖数、纯遮挡误失效数、保留的稳定区域/帧数、完整 4 序列 trace 和运行时间/RSS。硬门：纯遮挡误失效必须为 0；未知事件不可作确定删除；两通道仍残留旧依赖则实现 FAIL。**若对照 4 或 5 在同预算下与候选完全等价，停止此版本的新颖性开发。**

**M1：仅 M0 未被简单对照覆盖时，进入真实编码器/真实事件。** 先固定自然变化样本与同场景无变化样本，冻结匹配的帧预算、视角、预测几何和编码成本；计算被判旧区域对实际 latent/embedding 的干预敏感性（只作机制量），同时比较稳定区域保留。没有可用原编码器/自然事件就 Defer，不能反复做 toy 占据主线。

**M2：最终生成消费者。** 同权重/随机种子/目标相机运行全部被冻结对照，报告变化对象错误复现、重现对象身份/外观保持、稳定区域破坏、完整轨迹质量及时间。需要自然独立事件与无变化零条件，不能靠单张挑图。没有实际视频不得跨到 G3/G4。

## 7. fairness_and_completeness — 公平性与完整性

M0 固定原 VMem commit 39291e4f272f6b4f270691d930926ab5930f942e；本轮仅源码读取，无 patch。后续若采用 GaME/MoPe 必须固定具体 commit、配置、原公式与允许的 CPU 适配；此时的 main 分支网页不等于可复现 seal。

强几何前端应先用已经真实复现的 CUT3R/TTT3R/FILT3R pair/result 路线；不能因 RayMap3R 论文较新就宣称它本机已成功。比较时共享前端输出才可隔离条件失效机制；同样还须做完整强基线，以免人为给原法留下没有维护的缓存。

GT 不能驱动部署式候选选择；若 oracle 可见性作为上限，所有对照同享且分栏。不能把删除更多上下文导致的变化，误说成更好的状态判断。匹配保留上下文预算和重新编码次数；若不能同时匹配，报告完整质量—成本曲线，不选有利单点。

空支持、识别错、透明/反光面、深度空洞、camera-pose 错误以及超时都保留。S22 原 FP32/FP16 兼容失败不能消失；本卡不改这些旧结果，也不把读完论文称作新实验。

## 8. decision — 当前裁决和退出条件

**Revise，而非 Continue 为已成立创新。** 泛化的“遮挡记忆 + 遗忘门”由 GaME/MoPe/PersistGS 覆盖；空间可见性更新本身不能作为贡献。收窄的双条件依赖问题有固定原接口依据，但**缺自然事件上的强基线失败，且最强简单对照很可能已足够**。当前只到 G0 的明确验证计划与 G1 的条件性审查，没有 G2 实验冻结、G3 效果或 G4 生成确认。

立即退出/降级为工程的条件：两通道同步刷新就是全部机制；全局依赖让方案退化为整帧舍弃而无可解释额外收益；合适自然事件中 baseline 不发生所担心的过期条件使用；几何误判损失超过处理过期条件的收益；需要未来真值才分出事件。

不以“查到旧组件”为由否定所有可能新方法；但必须有比这些对照更具体、可实测的机制再保留方法主张。

## 9. local_feasibility_and_downstream — 本机动作及生成主线

最先可执行的接口（**本卡仅提案，脚本尚未实现，不提供伪可运行命令**）：

run_condition_validity_probe --source-manifest ABS --synthetic-events fixed-v1.json --output FRESH

预算建议 CPU 1 线程、60 秒、1 GiB，0 权重、0 图像。输出全来源 trace/数组 hash/资源回执。这是廉价淘汰试验；不应花数天扩成测试框架。它与静态 TUM 的实际模型结果分开记。

接回原项目的明确链路：现有几何预测 → 可见性/变化证据 → 区域版本 → 原 surfel frame retrieval → 原 latent/embedding 条件 → 原视频采样器。S18 已打通的几何/检索组件可复用，但本轮没有读取其数组。主生成权重及指定原 VAE 的访问问题沿 S17/S20 已记录边界，本轮没有重新请求，也不能拿另一生成器冒充完整 VMem。

GaME、MoPe 的官方安装含 CUDA 自定义组件；PersistGS 本文用 GPU 物理/渲染链。此卡不承诺三者可直接 CPU 忠实复现。局部移植只能叫机制对照；完整方法复现需独立资源和精度审查。

## 10. independent_confirmation — 独立确认

本卡是文献和源码探索，不是盲测。已见 TUM/Bonn只用于 null/control，不参与独立确认优劣。M0 人工规则由另一作者在运行前逐项核对，特别检查两种隐藏世界同观测时输出不能不同；对真实编码器的结论必须用它本身验证。

M1 的场景、事件起止、评价视角、是否移走/复现由未调该方法的人先登记，只查看该登记所需内容并与方法开发分离；自然变化和纯遮挡各完整保留。先在一个探索场景确定规则，再用预先固定的另一场景确认，不回看选最好帧。M2重复的次数由生成随机性而定，确定性接口不机械重跑。任何后验调参另立版本并保持失败/零结果。

本卡尚未由另一作者复核；交 root 后再记录独立审查意见。所列最近工作并不构成“全球无重复”的保证。
