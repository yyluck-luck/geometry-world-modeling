## 旧三数组为何仍可作为参考

固定文件 `src/vmem_retrieval_kernel.py` 的 renderer 是第 61–179 行。AST 与 Python 符号表核得：读取的形参恰为 `surfels, poses, focal_lengths, principal_points, image_width, image_height, disk_resolution`；**没有读取 `self`**。surfel 对象只读取 `position, normal, radius`。整个 `RetrievalKernel` 对 `self.surfel_to_timestep` 的唯一读取在第 229 行，属于 renderer 返回后的投票方法。实际 Surfel 类第 15–27 行是普通属性存储，未借属性 getter 隐式访问来源。

renderer 的 Python 全局名为 `abs, float, int, isinstance, len, math, max, min, np, range, torch`；局部嵌套多边形检查也不读来源。完整属性表达式、AST 哈希、8 份源码哈希与 32 份旧输入哈希已存静态回执。结论限定于这些固定源码、普通 Surfel 对象与固定运行环境，不推广到有自定义属性副作用的任意对象。

`get_context_info` 第 265–268 行先从固定 query、固定 Y/Z 轴翻转和 `surfel_Ks` 均值构造 render 实参。来源编辑不改变这条路径。因此，在本设计中，原地图和相机的旧三数组仍是原 renderer 在同一渲染输入下的参考。这里是依据代码依赖和封存身份做 **buffer replay**，不是原 renderer 新跑过一次。

回放必须有实参守卫：绑定完整渲染几何（值、类型/形状、surfel 顺序）、相机 pose、focal、principal point、宽高、disk_resolution 和固定环境/源码身份；接到调用时逐项核对，返回独立副本。参考 buffer 自身的形状、dtype、字节哈希必须与旧封存完全相同。buffer 身份的依赖摘要不包含来源映射；来源映射另以本条件的**新有序列表摘要**核验，不能用旧全 memory digest 错判为所有输入应不变。颜色/counts 等额外保持项也须另核未变。

## 两臂、调用数与正确性判据

先对每块运行一次原完整 `get_context_info`，只将 renderer 绑定为上述守卫回放器，来源仍为原映射，共 **6 次 baseline replay**；完整 trace 必须复现旧 query20 原记录。这一步不调用实际原 renderer，也不重复 S10 候选运行。

每个新条件，两臂各有独立、同样编辑后的输入副本：参考臂仍运行未改完整 `get_context_info`，renderer 只守卫回放原三数组；候选臂运行 S10 固定真实 renderer 和未改完整 `get_context_info`。共 **30 次参考回放选图 + 30 次候选实际选图**，加上述 6 次 baseline，共 66 次选图入口调用，其中真实候选渲染 30 次、实际原 renderer 0 次。不能把参考回放延迟拿来做原/新速度比较。

判据依次为：输入与绑定身份合格；候选实际三数组对旧参考 shape/dtype/C 顺序 bytes 全等；参考与候选的完整票权、配额、展开候选、姿态距离与排序、NMS 阈值轨迹/后备补入、最终有序 ID 及上下文输出完全相同；调用后两臂输入保持。不得仅比较最终四个 ID 或运行器自报 PASS。候选实际输出须保存，不能以旧 buffer 替代。新的参考完整 trace 应在同一来源条件下重新计算，不能直接复制旧来源 trace。

**来源逆序不预设 trace 或选图等于未改来源。** 第 219–233 行按像素顺序处理、按列表顺序首次插入来源字典；首次出现的来源在第 232–233 行还会双加首个贡献，必须保留原语义。第 234–239 行先按插入顺序归一化和分配，第 240–241 行才按帧 ID 排序。列表逆序可能影响归一化求和顺序或同票截断，不能擅自排序列表或集合化再声称严格等价。只要求两臂对同一编辑完全一致；相对未编辑结果是否改变另行如实计数，不作为选例依据。

## 来源不足与空检索的边界

原第 237 行令 `n=min(14,k)`，`k` 为可见来源数。`k≤14` 时第 197–200 行每来源配额 1；`k>14` 时第 191–196 行选择 14 个来源，各配额 1。因此这些正常来源列表条件不会触发 helper 中 `n>k` 的按比例重复展开分支。

`only_0` 与 `only_0_1_2` 若原 buffer 有有效投票像素，分别提供 1 和 3 个可见来源。第 279 行把 `max_frames` 限为 1 或 3；NMS 后备第 319–324 行只从已有候选补入，不补其他历史照片，故分别应返回 **1 或 3 个 ID**，不能强行要求四张。执行前须核封存 buffer 确有适用投票像素；若不符则停止，不换 query。十二个条件单列为人工来源数边界，不作为一般真实来源更新的现象。

**记录工具需先适配，原选择器不用改。** `src/s7_event_replay.py` 的 `decision_trace` 第 133 行虽计算 `maximum=min(4,候选数,历史数)`，第 169–170 行却硬要求四个唯一 ID；直接复用 S10 验证器会误拒合法的 1/3 来源结果。S11 必须另存记录适配器：将该末尾长度/去重检查中的 4 换为 `maximum`，同时保留合法历史 ID 条件，并把回放记录的 `selected` 逐值核对真正 `get_context_info` 的返回。可用 AST 恢复证明只改了记录器的适用域守卫，完整排序/NMS 语句保持；必须冻结新适配器源码，不修改 S7/S10 旧文件或原 `get_context_info`。这项事前发现不能在正式执行失败后隐去。

空检索没有成功 fallback。裸 kernel 缺失可见 surfel 的映射键会在第 229 行 `KeyError`；有空来源列表或完全空可见 buffer 最后会在第 300 行索引空 `sorted_frames` 而失败。桥接 `_check_history`（`src/s6_memory_bridge.py` 第 179–187 行）会更早拒绝缺键、空列表、重复或非法 ID。以上非法输入不进入 30 个应成功条件；也不覆盖一张历史图、五张历史图的特殊分支或 NMS=False。

## 负对照及保留失败

执行器应在运行前固定负对照位置与数量，并保存每次拒绝原因；不得看通过情况后更换扰动。

1. **几何与相机守卫。** 对封存回放实参的独立副本，固定改变一个位置坐标，另一个副本固定改变相机平移坐标；每次须使实际数值/字节发生变化。回放守卫必须在返回 buffer 前拒绝。建议每块各两个检查，共 12 次纯守卫检查；它们不是额外选图或实际渲染。保持其余实参不变，明确被拒项目是几何或相机。
2. **陈旧来源参考。** 将每块未编辑 baseline replay 的完整 trace 故意当作编辑后的参考，按与正式条件相同的严格 trace 门比较。对全部 **18 个 append/drop/reverse 条件**报告拒绝/未拒绝数量，预先要求至少一个被拒绝，否则此次来源敏感性诊断不报通过。十二个只有 1/3 来源的边界条件不得替代这个 1/18 门。陈旧 trace 不影响候选计算，也不得修改后续正式结果。

陈旧 trace 不一定让最终 ID 改变，完整票权或配额差异同样应被严格门发现；反过来，某个逆序条件与旧 trace 完全相同也不是错误。负对照与正式结果全部保留，无自适应选“最明显”的例子。首次失败应先记录，不改 S10 候选或旧数据来满足本设计。
