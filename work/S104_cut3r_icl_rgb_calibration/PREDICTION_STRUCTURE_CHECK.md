### 2.1 关键正面结果：预测张量无数值异常

**全部 4 帧的 `pts3d_in_self_view`、`pts3d_in_other_view`、`conf`、`conf_self`、`rgb` 均为 `nan=False, inf=False`。**

这是这次前向一个真实的正面事实——四帧预测**没有出现 NaN 或 Inf**，不是「日志写 SUCCESS 就算成功」。

### 2.2 位姿编码：`(q, t)`，与真值文件顺序**不同**

`camera_pose` 是 7 维。第 0 帧为 `[~0, ~0, ~0, 1.0, ~0, ~0, ~0]`，即单位旋转 + 零平移（参考帧）；第 3 帧为 `[0.0573, -0.0412, 0.0232, 0.9567, 0.00142, 0.2563, -0.1376]`。

**推断**（尚未核验）：编码为 `(qx, qy, qz, qw, tx, ty, tz)`——**四元数在前、平移在后**。

而 ICL-NUIM 真值文件 `livingRoom0.gt.freiburg` 是 `(tx, ty, tz, qx, qy, qz, qw)`——**平移在前、四元数在后**。

> **两者顺序相反。** 直接按列对读会静默出错。此推断需在评分前用代码核验（见协议 P2），**不能只靠肉眼**。

### 2.3 `pts3d` 处于 CUT3R 自身坐标系与尺度

`camera_pose` 第 0 帧为单位阵，说明输出在**首帧参考系**下。但 `pts3d_in_self_view` 的数值范围（约 -2 到 +5）**不等于**真值米制范围（由资格验证知约 0.74–3.37 m）。因此预测处于**任意尺度**，与真值比较前**必须做尺度对齐**。

## 3. `views[i]`：输入与占位符

| 键 | 形状 / 值 | 判读 |
|---|---|---|
| `img` | (1, 3, 384, 512)，范围 [-1, 1] | 真实输入图像（640×480 → 512×384） |
| `ray_map` | (1, 6, 384, 512)，**全部 NaN** | **预期行为，不是缺陷** |
| `true_shape` | (1, 2) = [384, 512] | 缩放后尺寸 |
| `camera_pose` | **(1, 4, 4) 单位阵，四帧全同** | **输入占位符**，不是预测位姿 |
| `img_mask` / `update` | 全 1 | 四帧均作为图像输入并更新状态 |
| `ray_mask` / `reset` | 全 0 | 无 raymap 输入、无重置 |

### 3.1 `ray_map` 全 NaN 是正常的

`demo.py: prepare_input()` 在只提供图像（`raymaps=None`）时，会用 `torch.full(..., torch.nan)` 填充 `ray_map` 占位：

```python
"ray_map": torch.full((..., 6, H, W), torch.nan),
"ray_mask": torch.tensor(False),
```

本次运行是 **RGB-only**（`--rgb` 四个路径，无 raymap），所以 `ray_map` 全 NaN、`ray_mask` 全 0 是**脚本设计的预期状态**。

> **不要**把「ray_map 全 NaN」读成前向失败或数据损坏。

### 3.2 `views` 里的 `camera_pose` 是单位阵，也不代表预测

`prepare_input()` 把每个 view 的 `camera_pose` 写成 `np.eye(4)`。真正预测的位姿在 `pred[i]["camera_pose"]`。

> 两处同名不同义：**`views[i].camera_pose` = 输入占位符（恒为单位阵）；`pred[i].camera_pose` = 模型预测。** 混淆二者会得出「四帧位姿完全相同」的错误结论。

## 4. `state_args`：循环状态确实在演化

`list[5]`，每项为 5 元组 `(state_feat, state_pos, init_state_feat, mem, init_mem)`：

| 槽位 | 形状 | dtype | 变化 |
|---|---|---|---|
| `state_feat` | (1, 768, 768) | float32 | **逐帧演化**：[-2.784, 5.171] → [-9.639, 14.635] → … → [-9.852, 15.310] |
| `state_pos` | (1, 768, 2) | int64 | 恒定 [0, 27] |
| `init_state_feat` | (1, 768, 768) | float32 | 恒定 [-2.784, 5.171]（冻结初态） |
| `mem` | (1, 256, 1536) | float32 | **逐帧演化**：[-0.587, 0.550] → [-1711.5, 2030.2] → … → [-2646.9, 3164.1] |
| `init_mem` | (1, 256, 1536) | float32 | 恒定 [-0.587, 0.550]（冻结初态） |

共 5 项 = 1 个初态 + 4 帧各一个（与 `_forward_impl` 的 `all_state_args` 一致）。

**可读出的正面事实：** `state_feat` 与 `mem` 逐帧变化、`init_*` 保持不变，说明**循环记忆确实在四帧间传递并更新**，而不是四帧各算各的。这**不等于**记忆有效或几何正确。
