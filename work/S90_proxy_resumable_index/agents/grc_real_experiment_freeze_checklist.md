**用途：** 在实现任何 GRC selector 或读取测试答案以前，逐项冻结第一轮真实实验。

**研究问题：** 在相同可用历史、目标相机、记忆/计算预算和输出随机性下，历史几何风险是否能预测并改善未见未来视角的几何误差？

## 0. 一句话验收标准

只有同时满足“数据可评分、选择只看 past、预算公平、场景级独立测试、强基线齐全、原始数组可复算”六个条件，实验结果才可以用于判断 H1。否则只能写成工程检查或探索性诊断。

H1（在看测试答案之前冻结）：

> 在同一候选历史和同一预算下，风险感知策略选出的集合，在未见场景的未来几何误差上不劣于最强非风险基线；历史可用的风险分数与未来几何误差有预注册方向的关系。

H0：风险分数与未来误差没有稳定关系，或任何改善可由最近帧、相机距离、coverage、confidence、utility 或 Fisher/EIG 基线解释。

这里的“未来几何误差”是独立的目标深度/位姿产生的几何评分，不把 RGB MSE、图像好看或支持率单独当成世界模型质量。

## 1. 数据资格门（Data Qualification Gate）

### 1.1 每个实验单元必须有的字段

一个查询单元定义为

\[
u=(\texttt{scene\_id},\texttt{trajectory\_id},t_q,h),
\]

其中 (t_q) 是查询时刻，(h) 是预先固定的未来跨度。每个 (u) 至少要有：

- 历史观测帧 ID、时间戳、RGB（若该方法需要）、深度或明确的几何输入；
- 每帧的内参 (K)、外参/位姿 (T_{w\leftarrow c})，坐标系和单位说明；
- 查询相机 (K_q,T_q)（它可以作为部署时已知的请求条件，但不能带目标深度/RGB）；
- 至少一个未来目标帧 (t_q+h) 的独立深度和位姿，用于评分；
- 有效深度规则（正值、有限值、无效值编码、深度单位、截断范围）；
- 同步容差、去畸变/像素中心约定、时间排序规则；
- 数据集版本、下载来源、许可证、文件 SHA-256 和采样脚本版本。

若目标只提供 RGB 而没有可核验深度/位姿，则只能做 RGB/生成探索，不能验收 H1 的几何部分。若只取得 RTMV tar 头或相机 JSON，也仍是数据路径准备，不是合格评分单元。

### 1.2 最低场景独立性

- 训练（如需学习 utility 或标量化）、校准（如需 CRC）和测试必须按**物理场景/房间/模拟 scene ID**切分，不能按帧随机打散。
- 同一房间的另一段轨迹只能作为“跨轨迹但非跨场景”附加分析，不能冒充未见场景。
- 最终方法结论至少需要一个真正未见 scene ID；只有一个场景时，结果标为 pilot/探索，不写泛化或顶会结论。建议在正式主张前准备 `>=3` 个独立 scene ID，具体数量须在数据可得性核查后冻结。
- 同一目标帧不得同时出现在训练、标量化、阈值调参、校准和测试文件中；任何重复或近重复帧都记录并剔除或单列。

### 1.3 数据资格的逐项拒绝条件

出现以下任一项，停止“方法验证”标签：

1. RGB、深度、位姿不能由稳定 frame ID 和时间戳一一配对；
2. 坐标系/尺度/内参无法由原始说明或独立投影检查确定；
3. 未来目标在选择、特征归一化、阈值或模型选择阶段被读取；
4. 无效深度被删除后没有保存原 mask 和分母；
5. 测试 scene 与校准/训练 scene 共享物理房间或缓存状态而未标记；
6. 许可证、来源或文件身份无法追溯；
7. 只有模型生成的深度/位姿，没有独立测量或明确 oracle 标识。

## 2. Past-only 特征合同

### 2.1 选择阶段允许读取的内容

对查询 (u)，每个候选 (i\in H_u) 的特征只能由

\[
\mathcal F_{i,u}=\{x_{\le t_q},K_{\le t_q},T_{\le t_q},K_q,T_q,\text{固定模型参数}\}
\]

计算。允许的例子：

- 历史帧之间的重投影残差、过去深度一致性、历史可见性/FOV 和来源覆盖；
- 候选相对查询相机的位姿距离、时间年龄、历史观测质量；
- 只从过去建立的地图/feature cache，以及目标相机请求本身。

所有特征需写出来源帧集合和计算时间点。若使用查询相机投影，必须明确这是“已知请求条件”，不能使用查询目标的 RGB、深度、future pose 或评分 mask。

### 2.2 明确禁止读取的内容

选择器、风险标量化器、utility 模型和阈值禁止读取：

- 目标 RGB、目标深度、目标分割/物体位置、未来位姿（若它不是部署时请求的一部分）；
- 目标图与候选图的事后像素 MSE、未来支持 mask、生成后质量分数；
- 测试 scene 的未来误差、测试标签或测试结果来挑权重/阈值；
- 运行完整策略后才产生的后代 latent/attention，除非该量在部署时本来就是选择前状态并且合同中明确。

### 2.3 风险和校准的最小定义

先冻结尺度 (s_r,s_d) 和标量化函数

\[
a_i=\phi(r_i^{\rm reproj}/s_r,r_i^{\rm depth}/s_d,r_i^{\rm vis};\theta_\phi),
\]

所有参数只在训练/校准 split 学习。不要把一个三维向量直接写成 (Q_{1-\alpha}(r_i))。

若采用 CRC，校准对象是“完整策略在一个查询上的集合级损失表” (L_j(\lambda))，不是独立候选残差；保存交换性/时间稳定性假设，并只声称边际期望风险控制。若只用 (a_i) 排序，称为风险启发式，不写 conformal 保证。

## 3. 固定历史、预算和计算

### 3.1 候选集合和时间方向

- 每个查询使用同一个 eligible history：默认只含时间 (<t_q) 的帧；窗口长度、是否允许重复观察、是否包含首帧必须一次冻结。
- 不同方法不能获得不同数量的候选、额外 future context 或事后 oracle 候选。
- 记录候选缺失、无效深度、重复帧和平局处理；不静默补帧。

### 3.2 记忆预算

在正式运行前固定：

- 记忆帧数 (k)（若沿用项目四张参考图，写成 `k=4`）；
- 最大 token/latent 数、分辨率、通道数和任何压缩规则；
- 若使用成本预算，固定 `Cost(S)` 的字节、token、模型调用次数和 wall-clock 统计方式；
- 选择时间是否算入总预算；建议把预处理、feature、排序、生成和解码都计入，并同时报告分项成本；
- 硬预算 `Cost(S)<=B` 与 Lagrange 罚项二选一，或明确二者关系，不能让某方法超预算后仍比较。

### 3.3 随机性和同目标配对

- 所有策略在相同目标查询顺序、相同输出分辨率、相同生成步数和相同 seed 列表上运行。
- 若方法改变随机数消耗，保存完整 RNG state/噪声数组，而不能只写“seed 相同”。
- 几何消费者若是确定性的，也要保存程序版本和输入数组；端到端生成至少预先固定多次 seed（建议至少 5 个，若资源不足须在协议中写明并降级为 pilot）。
- 目标和 seed 的配对单位是 query × seed；统计时先在 query/scene 层聚合，不能把像素数或中间步数当独立样本。

## 4. 必须运行的强基线

所有基线共享同一 eligible history、同一 (k)、同一输入特征可见范围和同一总预算。至少包括：

1. **Recent-k：** 最近时间的 (k) 帧；
2. **Nearest-pose-k：** 目标相机位姿距离最近的 (k) 帧；
3. **Random-k：** 固定预注册 RNG，至少多次重复并保存每次 ID；
4. **Coverage-k：** 只用 past 几何的覆盖/可见性最大化；
5. **Confidence-only：** 只按已有 confidence/深度质量排序；
6. **Utility-only：** 去掉风险项但保留同一 utility 和预算；
7. **Fisher/EIG 或其可运行等价物：** 作为信息选择强基线，必须记录其额外模型/预处理成本；
8. **原始 VMem/项目已有 selector：** 若输入契约可对齐，保留其原始规则和版本；
9. **GRC 消融：** 无 risk、无 utility、无校准、静态阈值和完整版本。

使用未来真值直接选择的 oracle 只能作为上限，必须单列，不能与可部署基线比较或用于调参。

## 5. 场景级实验拆分和执行顺序

### 5.1 四个锁定阶段

1. **开发：** 允许检查历史结构和非测试结果；确定 feature、标量化、候选实现和日志 schema。
2. **校准：** 在独立 calibration scene/trajectory 上运行完整策略，选择全局阈值或 CRC 参数；封存校准产物。
3. **冻结：** 写入代码、配置、数据 manifest、split、seed、预算、指标、停止规则和 SHA；独立审查后禁止改动。
4. **测试：** 先运行所有选择器并保存 selected IDs/预测；再解锁未来深度/位姿读取器进行评分。任何先读答案再改参数的运行都标成 invalid，保留但不计入主结果。

### 5.2 先做便宜的几何消费者，再做生成消费者

第一轮建议先执行 CPU 可承受的几何消费者：把选中的历史几何投影/融合到未来目标相机，计算未来深度/3D 点误差。只有风险关系和基线差异通过，才把相同 selected IDs 接入昂贵的视频生成；几何消费者通过不等于视频质量通过。

每个 query 至少保存：目标有效点集合、选中集合预测、对应的独立目标深度/位姿误差和覆盖率。若使用 RGB，RGB MSE 作为次要指标，不能替代几何主指标。

## 6. 指标、统计和最小否决规则

### 6.1 主指标和辅助指标

主指标在冻结文件中只选一个：

- 未来有效目标点的 3D position error（米），或明确由深度+相机反投影得到的 position error；
- 若无法得到 3D 点，使用目标深度绝对误差并明确这是替代指标。

辅助指标：median、90th percentile、最差 query/scene、有效覆盖率、支持率、重投影残差、RGB MSE、选择延迟、峰值内存、token/latent 数和失败/空值率。

报告 paired difference（GRC−每个基线）、scene-level bootstrap/置信区间、完整分母和缺失值。像素数量、候选数量、seed 数和日志行数不能直接称独立场景数。

### 6.2 最小否决/降级规则

下列任一项发生，不能把第一轮写成 GRC 方法验证：

- 数据资格门任一项失败，或发现选择阶段读取 future/target；
- 风险分数与未来误差方向不稳定，或只在一个 scene/一个 query 有效；
- GRC 不优于最强的 recent/pose/coverage/confidence/utility/Fisher 基线，且增益可由预算或候选数差解释；
- 平均误差下降但预注册的最差 query/scene 明显恶化，或 S87 类似的难例被平均数隐藏；
- CRC/校准的策略级边际风险在独立测试中超过预注册阈值，或交换性/漂移假设明显不成立；
- 总计算或记忆成本超过预算；
- 结果依赖事后调阈值、挑 seed、删无效点、删困难场景或只展示成功图。

“无显著差异”应写成不支持/证据不足，并保留所有数据；不能为了保住创新改名或改主指标。

## 7. 必须保存的原始数组和回执

每个运行目录都要有 `MANIFEST.json`、代码/配置 SHA 和以下不可逆删减的原始文件（格式可按实现替换，但语义必须保留）：

### 7.1 输入与候选

- `scene_ids`, `trajectory_ids`, `query_ids`, `history_frame_ids`, `timestamps`；
- `K_history`, `T_history`, `K_query`, `T_query`，坐标系/单位说明；
- `eligibility_mask` 和所有无效/缺失 mask；
- RGB/depth 文件路径、字节 SHA-256、深度单位、原始尺寸和预处理后的尺寸；
- `candidate_feature_matrix[n_query,n_candidate,d]`，每个维度的名称、单位、来源时间；
- 原始三项 (r^{reproj},r^{depth},r^{vis})，归一化尺度和标量化参数。

### 7.2 选择、校准与预算

- 每个方法/每个 query 的原始 `utility`, `risk`, `score`, `selected_ids`, 平局顺序和拒绝原因；
- `lambda_grid`, `calibration_loss_table`, 校准 scene/query IDs、CRC 参数和选出的全局 \hat{lambda}；
- `cost_breakdown`（预处理、特征、排序、生成、解码、峰值内存、token/模型调用）；
- 配置文件、Git commit、依赖版本、Python/torch/硬件、开始/结束 UTC 时间；
- 每个 seed 的初始 noise、完整 RNG state、采样步数和调度器状态。

### 7.3 预测、答案和评分（分阶段写入）

- `predicted_geometry_before_answer_release`：解锁 future 前的选中集合和预测点/深度；
- `target_depth`, `target_pose`, `target_valid_mask` 及其读取时间和 SHA（答案释放后才写入）；
- `per_point_error`, `per_query_metrics`, `per_scene_summary`，包括 NaN/空集和分母；
- 若运行生成：原始输出 RGB/latent、视频帧、解码参数、生成失败日志和每帧几何指标；
- 独立复核器的重算数组/差异表、结果接收票和可追溯日志。

### 7.4 最低回读检查

独立作者或独立脚本需从保存数组重新计算：候选数、选择 ID、预算、主指标、分母、至少一项 paired difference 和所有 checksum。只读回日志“SUCCESS”或编译通过不能作为科学复核。
