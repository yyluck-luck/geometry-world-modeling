## Reuse boundary

The sealed S39 loading evidence is reused only as evidence that the five named component files and declared ft-mse variant loaded successfully under the S40 model/config structure before generation. The C2 gate proves that its YAML equals the sealed S40 YAML after the single `seed: 42` to `seed: 44` substitution plus one declared terminal LF; that newline is formatting only and is checked byte-for-byte. Image preprocessing is not part of model construction, so the prior `changi.jpg` identity is not reused as C2 input evidence. The C2 gate separately binds and hashes the exact `living_room.jpg` bytes before model construction. It must never claim that S39 loaded or generated the C2 image.

The C2 launcher is an AST-derived copy of the frozen S35 supervisor with a reversible, counted security transform in addition to the gate/factory routes and fixed schema/status labels. The transform replaces the external worker spawn with one direct `fork` from the monitored parent and replaces the worker ticket/receipt reads with same-descriptor snapshots; reversing every declared edit must recover the exact S35 AST. The public wrapper parses the complete argument vector once, accepts only one split-form occurrence of each exact option, rejects equals forms, abbreviations, repeats, unknowns and every worker marker, and passes a sanitized namespace directly to the derived parent. There is no public or fresh-interpreter worker dispatch. Both parent and worker require the literal canonical `execution_01` path. Immediately before the single fork, the parent creates a 256-bit secret and an opaque object token held only in the derived launcher's closure. The child inherits their exact in-memory identities through `fork`; a one-byte anonymous pipe only delays the child until the parent has published the create-only digest record and never transports either credential. The child must present the inherited object by identity and match the inherited secret to a record binding parent PID, child PID, launcher, manifest, output and execution identities. It consumes the record create-only before any worker gate. A caller-controlled argv, environment variable, pipe, secret, or disk ticket cannot enter this route, and the issued/consumed state forbids a second use.

The C2 runtime adapter is an AST-derived copy of the exact S35 runtime factory. It changes the gate import, four evidence labels, the four exact seed literals used by `random.seed`, `numpy.random.seed`, `torch.manual_seed`, and the config guard from 42 to 44, plus two reversible security sites: the factory receives the detached manifest snapshot already verified by the full gate instead of reopening a path, and every loading-receipt save uses a fixed create-exclusive no-follow temporary file relative to one held output-directory descriptor with inode checks and atomic same-directory publication. Reversing every declared edit must recover the complete S35 AST. All candidate-bound source and JSON parsing or execution uses bytes read, hashed, parsed or compiled from one `O_NOFOLLOW` regular-file descriptor snapshot with before/after identity checks; bound Python is compiled directly, never reopened through `SourceFileLoader` or cached bytecode. The freeze, authorization, and launcher sources embed the independently reviewed exact generation-gate SHA, so an untrusted manifest cannot choose the verifier that authenticates that manifest. The S35 integration, archive, trace, model, geometry, renderer, and navigation sources are otherwise reused byte-for-byte.

## Freeze and review sequence

0. Before the freeze tool may run, two different non-root reviewers must independently bind the same eight V4 production-candidate hashes (`PROTOCOL.md`, `FREEZE_PROTOCOL.md`, `generation_gate.py`, `runtime_adapter.py`, `launch_generation.py`, `freeze_c2_manifest.py`, `create_launch_authorization.py`, and `inference_seed44.yaml`). The required source verdicts remain `PASS_S47_C2_FREEZE_TOOL_SOURCE_REVIEW` and `PASS_S47_C2_FREEZE_TOOL_SOURCE_REVIEW_ADVERSARIAL`, but they must be issued in new V3 review files over this V4 source set and must independently reproduce the dual-interpreter negative matrix; any candidate edit invalidates both. This external orchestration gate creates no formal path. All earlier source reviews, including the original seven-file PASS and both eight-file V3 BLOCKED reviews named above, are preserved but superseded and have zero authority for V4.
1. After both source reviews pass and root re-hashes all eight files, the standard-library-only freeze tool may run exactly one `prepare`. It completes command/source/parent/input/config/freshness preflight before consuming an attempt, treats broken symlinks as occupied, and then claims only the fixed `.freeze_attempt_01.staging` lease. Success atomically publishes one immutable `freeze_attempt_01/manifest_core.json` plus its receipt. Any failure after the lease is claimed writes a fixed failure receipt and publishes or retains that same fixed lease at the fixed output, so no alternate staging name can retry it. The tool never imports scientific packages or decodes pixels.
2. A source-core reviewer and a runtime/freshness-core reviewer, both different from the core author and from each other, independently bind the actual core file SHA and review-excluded canonical core SHA. They issue no PASS if any non-allowed difference, path reuse, source mismatch, missing resource, output collision, or scope ambiguity exists.
3. Only after both core reviews pass may the freeze tool run its unique create-only `attach`. It checks that the two exact reviews did not change the review-excluded core hash and validates the exact future manifest only at the fixed `.review_attachment_01.preflight/manifest.json` path. The general gate API has no unpublished-bypass flag; this dedicated preflight requires every later formal path absent, rejects canonical/alternate/symlink paths, and returns `UNPUBLISHED_ATTACHMENT_PREFLIGHT_ONLY` with `execution_authorized=false`, never a PASS status. A failed fixed preflight remains occupied for audit. On success it is removed before the tool claims only `.review_attachment_01.staging`. The tool writes the preflight metadata and terminal receipt before the canonical manifest and atomically publishes the complete `review_attachment_01` directory without replacement. Any post-claim failure publishes or retains that same fixed failed attempt and cannot be retried under another name. Only a successful attachment containing exactly three regular files, `manifest.json`, `metadata_gate.json`, and `receipt.json`, can pass the canonical gate; any retained failure receipt closes it.
4. Two further non-root reviewers must independently bind the same five-value object: final manifest SHA, frozen core file SHA, review-excluded canonical core SHA, successful attach-receipt SHA, and staged metadata-gate SHA. Each review uses schema `s47-c2-final-launch-review-v1`, records its fixed kind (`final_attachment` or `launch_readiness`), `author_role=/root`, a distinct non-root reviewer role, `executed=false`, zero scientific imports/pixel decoding/generation calls, `quality_status=NOT_EVALUATED`, `method_or_novelty_status=NOT_EVALUATED`, and no blockers. Their required statuses are `PASS_S47_C2_FINAL_ATTACHMENT_REVIEW` and `READY_TO_LAUNCH_S47_C2_SINGLE_ATTEMPT`. Both timezone-aware UTC `reviewed_utc` values must be strictly later than the attachment receipt's `completed_utc`.
5. Only after both reviews exist may the separately reviewed standard-library tool `create_launch_authorization.py` run once. It accepts the five exact hashes and two exact review hashes and completes all read-only validation first. Its first mutation atomically claims the fixed `launch_authorization_attempt_01` directory. The sole staging file lives under that lease at the fixed name `authorization.staging.json`; every ordinary failure writes a create-only terminal failure receipt, while an uncatchable interruption still leaves the claimed lease. The lease is never renamed or deleted, every later invocation rejects it, and a success receipt binds the final authorization SHA with `retry_permitted=false`. The tool publishes the fixed read-only `launch_authorization_01.json` with macOS `RENAME_EXCL`; the canonical gate requires both it and the lease's successful terminal receipt. Its timezone-aware UTC `created_utc` must be strictly later than both reviews. A missing, reused, partial, redirected, predated, same-reviewer, root-reviewed, blocked, executed, hash-mismatched, failed, or merely claimed lease closes the gate permanently pending human review.
6. `prepare` and `attach` require the authorization, authorization-attempt, execution, result and fixed-preflight paths to remain absent and never create authorization or execution state. For the canonical published manifest, both metadata and full resource gates require and reconstruct the exact authorization, its successful fixed attempt lease, its two reviews, and all five bindings before returning PASS. Only that exact manifest SHA, literal manifest path and literal `execution_01` path may be passed once to the launcher. The public route rejects any missing, alternate, repeated, equals-form or abbreviated execution option and every caller-supplied worker marker. The derived parent alone may fork the capability-authenticated worker; neither the CLI nor a second interpreter has a worker dispatch. Parent and worker independently assert `execution_01`; the scientific output root must still be absent.

Review PASS is permission to attempt the frozen baseline once. It is not evidence that generation completed or that C2 supports a failure hypothesis.

## Required terminal evidence and boundaries

The launcher preserves actual start/end times, process-tree monitoring, trace boundary, return code, capability issuance/consumption, worker receipt, resource gate, runtime loading, and partial evidence on failure. The full gate carries a detached copy of the exact parsed canonical manifest and fixed output root; the runtime factory and adapter route only from that snapshot and never reopen the manifest. Runtime-loading updates use one held output-directory descriptor, reject an occupied or symlinked fixed temp, verify the path still names the same directory inode before and after atomic publication, and parse the published bytes from a no-follow descriptor. A returned process is still pending independent archive/readback review. Later work must independently verify the full archive, second-batch consumption of first-batch generated history, camera-condition closure, authoritative nine-frame pixel identities, blind scoring, and all-nine visual QA before C2 becomes a technically valid row.

C2 completes the mandatory generation queue only after later independent archive/readback, blind scoring, and visual-QA guards make B0, C1, and C2 technically valid. No infrastructure repair, successful run, metric difference, or visual impression is an innovation claim.
