# C2 manifest freeze protocol (V4 source candidate)

The freeze tool is standard-library only. Before creating any protocol-compliant directory, it must validate the mode/output pairing and all mode-specific arguments, verify its pinned sources, including the separate `create_launch_authorization.py`, and load the independently pinned gate by compiling the exact bytes hashed from one no-follow regular-file descriptor. The authorization and launcher independently embed that same reviewed gate identity rather than accepting a verifier hash chosen by a manifest. The freeze tool then verifies the exact S40 and S42 parents, the five row-specific production-source hashes, the seed-44 YAML as exactly the S40 bytes after one `seed: 42` to `seed: 44` substitution plus one terminal LF, the full C2 JPEG hash without decoding it, and every reserved output location is unoccupied. Bound JSON is hashed and parsed from the same descriptor snapshot. Freshness uses `lexists`, so a broken symlink is occupied. The authorization, fixed authorization-attempt lease, execution, scientific-result, and fixed attach-preflight paths must also remain absent throughout both modes.

After preflight, the tool claims exactly one mode-specific hidden lease: `.freeze_attempt_01.staging` or `.review_attachment_01.staging`. On macOS it publishes that directory with `renamex_np(..., RENAME_EXCL)`, which cannot replace an existing file, directory, or symlink. A post-claim failure writes a fixed failure receipt and publishes that same bundle at the fixed mode output when possible; otherwise the same fixed staging lease remains occupied. It never selects a PID/time/random alternate name, so a staging failure consumes the attempt. In `prepare` mode only a successful atomic publication contains exactly one `freeze_attempt_01/manifest_core.json` plus its terminal success receipt. It may not create the scientific result root or an execution directory.

The immutable core excludes only `review_receipts` from its canonical core hash. It carries the exact allowed-difference policy: input changes from `changi.jpg` to `living_room.jpg`; seed changes from 42 to 44 in the manifest, the uniquely substituted YAML with one declared terminal LF, and all three RNG calls; while the output path, row labels, source identities, review bindings, and timestamps are administrative isolation fields. Every other component, config field, runtime, generation budget, trajectory, sampler, geometry, archive, and trace condition must equal S40.

After preparation, two different-author JSON reviews must independently bind the same exact core hash:

- source review status `PASS_S47_C2_GENERATION_SOURCE_REVIEW`;
- runtime/freshness review status `READY_TO_ATTEMPT_S47_C2_BASELINE_GENERATION`.

Both reviews must record `row=C2`, the exact variant object, `core_sha256`, `executed=false`, `model_or_scientific_imports=0`, `pixels_decoded=0`, and an empty `blocking_findings` list. Reviewers may statically execute the launcher's `compile_only=True` proof only in a source-isolated standard-library process; they may not invoke `main`, load a model, decode the C2 image, create the result root, or create an execution directory.

In `attach` mode the tool verifies the two exact review snapshots, requires distinct non-root reviewer roles, rechecks all parents/sources/input and output freshness, inserts only `review_receipts`, and verifies core-hash equality. It creates exactly the fixed `.review_attachment_01.preflight/manifest.json` path with no replacement and invokes the dedicated `check_attachment_preflight` API. The general `check_manifest` API has no unpublished switch and always requires canonical attachment plus authorization. The dedicated route rejects every other path, symlink or existing later formal state and returns `UNPUBLISHED_ATTACHMENT_PREFLIGHT_ONLY`, `execution_authorized=false`, `unpublished_attachment_check=true`, and `launch_authorization=null`; it cannot emit a PASS. A successful preflight is removed before staging, while a failed fixed preflight remains occupied. The staged preflight record and terminal success receipt are written before the canonical manifest; `review_attachment_01/manifest.json` is the last file added. Attach neither creates authorization state nor launches generation.

After atomic attachment, two new fixed-path reviews must use schema `s47-c2-final-launch-review-v1` and independently bind the exact final-manifest, core-file, canonical-core, attach-receipt, and metadata-gate SHA values. `FINAL_ATTACHMENT_REVIEW.json` must have status `PASS_S47_C2_FINAL_ATTACHMENT_REVIEW`; `LAUNCH_READINESS_REVIEW.json` must have status `READY_TO_LAUNCH_S47_C2_SINGLE_ATTEMPT`. They require different non-root reviewer roles, empty blockers, zero execution/scientific imports/pixel decoding/generation, and UTC review times strictly after attachment completion.

The separately reviewed `create_launch_authorization.py` then rechecks the attachment and both reviews from same-descriptor snapshots. After all read-only checks, its first mutation claims fixed directory `launch_authorization_attempt_01`. It uses only `launch_authorization_attempt_01/authorization.staging.json`; every catchable post-claim failure writes a fixed terminal failure receipt, and an interruption still leaves the lease occupied. No code path deletes or renames the lease, so another invocation cannot choose another staging name or retry. Success publishes exactly one read-only `launch_authorization_01.json` with `RENAME_EXCL` and writes a create-only success receipt binding its SHA with `retry_permitted=false`. The canonical metadata/full gate reconstructs the authorization and also requires that successful lease receipt before PASS. A missing, malformed, merely claimed or failed lease closes both launch paths.

Every freeze post-staging failure is terminal at its fixed stage or fixed output; the fixed attach-preflight path prevents an alternate-name retry after a failed unpublished validation. A canonical attachment is accepted only when its directory has exactly the three regular success files and no failure receipt. No output is overwritten. The launcher separately accepts only one exact split-form public argument vector and has no external worker dispatch. The monitored parent creates one opaque object token plus a 256-bit secret immediately before one direct fork; only that child inherits their in-memory identities, while a one-byte pipe provides ordering without transporting credentials. The child consumes a create-only record that binds both PIDs and every launch identity before entering the worker gate. The runtime consumes the full gate's detached manifest snapshot and writes loading evidence relative to one stable output-directory descriptor through a fixed create-exclusive no-follow temp and atomic same-directory publication. A PASS from the freeze tool means only that the atomically published bundle is ready for the two final reviews; it does not authorize launch by itself and is not generation, readback, quality, method gain, or novelty evidence.
