# C2 manifest freeze protocol (V7 source candidate)

The freeze tool is standard-library only. Before creating any protocol-compliant entry, it validates the mode/output pairing and all mode-specific arguments, verifies its pinned sources including `create_launch_authorization.py`, and compiles the exact independently pinned gate bytes read and hashed from one no-follow descriptor. It verifies the exact S40 and S42 parents, five row-specific runtime source hashes, the seed-44 YAML as exactly the S40 bytes after one unique `seed: 42` to `seed: 44` substitution plus one terminal LF, the complete C2 JPEG SHA without decoding it, and freshness of every reserved location. `lexists` treats a broken symlink as occupied. Authorization, authorization-attempt, execution, result, and fixed attach-preflight paths remain absent throughout both modes.

After preflight, the tool first create-exclusively writes the mode-specific outer sentinel `.freeze_attempt_01.claimed` or `.review_attachment_01.claimed`, then creates only fixed staging `.freeze_attempt_01.staging` or `.review_attachment_01.staging`. It holds no-follow descriptors for the project directory, every ancestor, and the staging directory. Every child write is relative to the held descriptor. On macOS it publishes the still-held staging inode with `renameatx_np(..., RENAME_EXCL)`, then proves the published name refers to that inode. A post-claim failure writes a fixed failure receipt when possible and publishes or retains the same failed inode. The sentinel remains even if staging is renamed, so no alternate-name retry is possible.

The only successful prepare terminal shape is exactly two read-only regular files: `freeze_attempt_01/manifest_core.json` and `freeze_attempt_01/receipt.json`. The receipt completely binds mode, status, core path, core file SHA, canonical core SHA, tool/protocol identities, source closure, zero-execution fields, ordered UTC times, outer sentinel, and `retry_permitted=false`. Attach and the canonical gate independently revalidate that exact success-only bundle. A coexisting failure receipt, staging file, symlink, writable file, partial receipt, or extra entry is terminal failure and cannot advance.

The immutable core excludes only `review_receipts` from its canonical core hash. It carries the exact allowed-difference policy: input changes from `changi.jpg` to `living_room.jpg`; seed changes from 42 to 44 in the manifest, the uniquely substituted YAML with one declared terminal LF, and all three RNG calls; while the output path, row labels, source identities, review bindings, and timestamps are administrative isolation fields. Every other component, config field, runtime, generation budget, trajectory, sampler, geometry, archive, and trace condition must equal S40.

After preparation, two different-author JSON reviews must independently bind the same exact core hash:

- source review status `PASS_S47_C2_GENERATION_SOURCE_REVIEW`;
- runtime/freshness review status `READY_TO_ATTEMPT_S47_C2_BASELINE_GENERATION`.

Both reviews must record `row=C2`, the exact variant object, core-file SHA, canonical core SHA, successful prepare-receipt SHA, `executed=false`, `model_or_scientific_imports=0`, `pixels_decoded=0`, and an empty `blocking_findings` list. Reviewers may execute the bundled source-only selftest, including its disposable temporary derived-parent to private-spawn to watchdog dependency-injection regression, and may statically execute the launcher's `compile_only=True` proof. They may not invoke `main`, use the candidate's canonical execution/result paths, load a model, or decode the C2 image.

In `attach` mode the tool retains the exact prepare directory inode, verifies its success-only receipt and both core reviews, requires distinct non-root reviewer roles, rechecks all parents/sources/input and output freshness, inserts only `review_receipts`, and proves core-hash equality. It creates only fixed `.review_attachment_01.preflight/manifest.json` and invokes the dedicated non-PASS preflight. A successful preflight is removed before claiming the attach sentinel/staging; a failed preflight remains occupied. The tool writes metadata and terminal receipt before the canonical manifest, holds the staging inode throughout, and publishes it with relative `RENAME_EXCL`. The only successful attachment shape is exactly three read-only regular files: `manifest.json`, `metadata_gate.json`, and `receipt.json`.

After atomic attachment, two new fixed-path reviews use schema `s47-c2-final-launch-review-v1` and independently bind six SHA values: final manifest, core file, canonical core, successful prepare receipt, successful attach receipt, and metadata gate. `FINAL_ATTACHMENT_REVIEW.json` has status `PASS_S47_C2_FINAL_ATTACHMENT_REVIEW`; `LAUNCH_READINESS_REVIEW.json` has status `READY_TO_LAUNCH_S47_C2_SINGLE_ATTEMPT`. They require different non-root reviewer roles, empty blockers, zero execution/scientific imports/pixel decoding/generation, and UTC review times strictly after attachment completion.

The separately reviewed `create_launch_authorization.py` rechecks the attachment, successful prepare receipt, and both reviews from same-descriptor snapshots. After all read-only checks it retains the prepare/attachment directory chains, then claims fixed `launch_authorization_attempt_01` and holds that directory plus all ancestors. It creates `authorization.staging.json` with `O_EXCL|O_NOFOLLOW`, retains that FD through relative `renameatx_np(..., RENAME_EXCL)`, and proves the published authorization name is the same inode before writing success. The only accepted terminal attempt shape is exactly read-only `attempt_started.json` and `success_receipt.json`; success plus failure, a staging remnant, symlink, partial state, or any extra entry closes both metadata and full gates. Success reporting happens outside the failure-recording region.

Every freeze post-claim failure is terminal at its fixed stage or output; no output is overwritten. The launcher separately accepts one exact public vector, claims and retains canonical execution/output inodes, and has no external worker route. Its private monitored closure mints one capability, first creates an independent watchdog, and lets that watchdog directly fork, own, and reap the separate-session worker. The S35 early ticket write becomes only a pending request. A readiness channel withholds capability release until the watchdog has reported both PIDs and the supervisor has published a create-only ticket with separate supervisor, watchdog, and worker identities. The worker validates the watchdog as its actual PPID before its full gate.

The AST-derived spawn call passes the inherited parent's local reviewed `psutil` object through a required `process_api` keyword to the private closure. The normal watchdog and its exceptional cleanup both use that one injected binding and never fetch `psutil` from the derived module namespace. The watchdog recursively discovers the worker's process tree and durably retains each PID plus creation time. It keeps scanning every registered live ancestor, so already observed descendants remain authoritative after `setsid`, process-group changes, closed standard descriptors, or reparenting. Normal completion and monitor loss require both the original worker group and every matching registered identity to be gone; cleanup targets both sets with TERM then KILL and rejects PID reuse. A fresh source review must separately rule out unreviewed native spawn routes designed to appear and escape between every observation point.

The supervisor writes a fixed non-success provisional record before parent entry. Its terminal commit is a separately create-only file whose body declares that it is never standalone success. The commit FD stays open through file sync, directory sync, complete canonical ancestor/control/output revalidation, and a second file/name identity check. A sync fault or path swap makes zero return impossible and records a fixed root-level supervisor failure through the held project descriptor. Later success interpretation requires the exact commit candidate, externally observed zero return, absence of both root-level watchdog and supervisor failures, and fresh canonical identity validation. The full gate holds the five component files, YAML, JPEG, control-plane files/directories, and all ancestor identities through worker terminal evidence. Runtime scientific loaders consume duplicate descriptors; immutable runtime journal entries use direct create-only writes and never rename over prior evidence. These controls assume reviewed source, reviewed psutil, a trusted kernel and invoking account and do not claim protection from hostile same-UID ptrace/FD injection, simultaneous destruction of monitor and watchdog, an unreviewed native process that deliberately escapes between every observation point, kernel/storage compromise, or host power loss. No lone commit-candidate file or such event permits success or automatic retry.

A freeze or authorization PASS means only that its exact evidence bundle may advance to the next named review. It is not generation, readback, quality, method gain, novelty, or publication evidence.
