# 给导师汇报的路线对照与问答准备（只读材料）

整理时间：2026-09-10（基于当前 `RESEARCH_MEMORY.md`、`RESEARCH_LOG.md`、原始 proposal 文本和 S70--S77 的已存证据）。

用途：供主汇报文档取用。这里把“已实际执行”“保存结果复算”“源码/合同检查”“文献或模型建议”严格分开。它不是导师评分、工时证明、论文录用预测，也不把任何阶段编号当作完成周数。

## 0. 先用一句话讲清项目

原 proposal 的问题是：现有世界模型在长时间、相机移动、遮挡、稀疏观察和重访后，能否仍生成与同一三维场景相容的画面；先找出**哪种失败真实存在**，再只针对该失败设计一个轻量的几何一致性机制。

截至本材料，项目已经从“能不能接上基线”推进到“已有 VMem 生成图在一个真实室内序列上为何不服从指定视角”的可复核诊断；但**尚没有一个被选定、实现并证实有效的新方法**。当前正式状态是 `NO_METHOD_SELECTED / novelty_authorization=NONE / new_method_validated=false`。

## 1. 原 proposal 路线与现状对照

因此，如果导师问“做到 proposal 的哪里了”，最稳妥的回答是：**已经完成了较扎实的基线接线、局部真实数据测量和失败诊断；正处于 proposal 的“失败刻画→选择机制”关口，创新方法及其全面评测尚未开始验收。** 历史上的粗略交付成熟度估计约为四分之一，不能当作正式百分比或投入工时。

## 2. 从开始到现在：可复核工作和测试数据地图

### 2.1 早期基础与几何基线

1. **源代码和接口审计（S0--S20）**：固定 VMem 的历史写入、清理、合并、检索和读取路径；建立冻结合同、输入/输出身份、失败保留、独立算术复核和研究日志。早期合成诊断的用途是排查代码与几何接口，不可报成真实视频质量实验。
2. **真实 RGB-D/相机几何测量**：在 TUM RGB-D 的 **Freiburg2 desk (`fr2_desk`)** 室内序列上使用真实 RGB、深度/位姿相关输入做局部几何检查。早期把 Freiburg1 的标定说明延伸到当前数据的错误已经更正；后续报告明确当前生成条件沿用了近似 ROS 内参，未把它伪装成精确物理标定。
3. **三种已有几何方法的 300 帧比较（S21/S22）**：同一 300 帧序列上，CUT3R、TTT3R、FILT3R 的位置 RMSE 分别为 **8.254 / 2.848 / 1.858 cm**。这是已有方法的基线比较，表明本机几何测量链可运行；它不是视频生成质量或新算法结果。原生 FILT 的 CPU 兼容问题被保留，统一精度控制后才完成对应运行。
4. **工程/检索工作**：历史选择、渲染和地图接口做过回归与性能分析。例如 S10 在固定的 24 个已见查询上维持同一输出，原选择组件平均时间由约 **1335.811 ms** 到 **171.767 ms**。这只是一组受限工程测量，不是 VMem 全系统加速，更不是创新方法。

### 2.2 从“可运行”转向“实际生成失败”

5. **保存上下文与条件链（S61--S69）**：完成单位适配、已保存上下文/缓存、五张真实历史参考的编码，以及 GT 光学相机和原条件接口的身份检查。这里有真实输入和部分真实网络前向，但不少结果是保存量消费/接口证据；必须与“新视频生成”区别。
6. **S66 固定评分与视觉检查**：已有九帧结果的真实评分、独立复算和图像查看完成；主误差为 **0.0006382446123931144**，预注册严重差异事件为 false。它和后面的 S70 使用不同任务/指标，不能横向比较高低。
7. **S70：一次真正的固定上下文 VMem 生成对照**：在同一个已见 `fr2_desk` 场景，保持四张历史 `[19,18,13,12]` 和四个目标 20--23，运行三臂、每臂 50 步的生成；A0/A1 的 latent、原始 RGB 与 uint8 输出精确重放。真实外部运行累计 **4439.151532 s**。A0/A1 的四目标平均 MSE 都是 **0.13116666776908745**，B 为 **0.12528866263799618**，预定“几何支持的 A 优于 B”事件为 **false**。这反驳了该固定例子中一个简单收益预测，且 A/B 同时改动内容顺序、规范化等条件，因果归因不能成立。

### 2.3 相机/几何诊断：已做什么、得出什么、不能得出什么

8. **S71：已生成图的取景偏差诊断**：对 S70 的已存图做固定 SIFT 双向匹配。A/B 与真实参考的中位特征位移（像素）为目标 20：39.49/43.07，21：107.86/115.83，22：200.69/196.77，23：373.00/297.01；最后一帧仅 3/7 匹配点，不足以拟合。结论仅为“局部内容位置存在显著偏差，且最后一帧证据稀疏”，不是确定的相机标定错误。
9. **S72：先做真实照片对照**：同一真实历史图 19 与真实目标 20--23 的 638 个匹配点，在固定相机/K 下的极线误差中位数为 **1.34、3.16、1.41、4.22 px**；目标 23 的 p95 为 **121.10 px**、最大 **422.45 px**。125 项不同公式复算通过。它证明观察器对多数点有参考价值，也暴露尾部和错配风险；不构成真实相机真值。
10. **S73：已存生成图与指定相机的对照**：8 张 A0/B 生成图共 1150 个可接受匹配，所有这些已接受匹配的误差都超过 10 px；例如 A0/B 在目标 20 的中位极线误差为 **21.655/27.668 px**，在 22 为 **146.125/124.604 px**。三臂共同支持仅为 **92/48/6/0** 个点（目标 20--23），因此“四目标都更差”的共同支持事件是 **UNKNOWN**。这支持“生成图与该固定几何关系不相容”的诊断，不足以定位根因。
11. **S74：真实照片的错误标签灵敏度控制**：把目标标签固定互换 20↔23、21↔22，不重找匹配、不重拟合，638 个真实匹配的错误标签减正确标签的配对中位残差为 **+105.665、+35.394、+40.807、+93.932 px**。146 项独立算术通过。这说明该观察器能区分本组真实相机标签；不证明生成器相机准确。
12. **S75：五张真实历史图的 VAE 往返**：真实执行一次 `ft-mse` VAE 加载，对缓存的历史 12、13、14、18、19 做五次解码（17.499437 s）。MSE 为 0.00236--0.00449、接受匹配的中位位移为 0.4735--0.5385 px，但原图特征匹配率只有 **31.52%--51.83%**，有 25 个 >10 px 离群点，最大 **480.846 px**。这只削弱“所有历史 latent 都严重扭曲”的解释；原 SD2.1 VAE 的精确身份仍 UNKNOWN。
13. **S76：唯一新增的相机扰动生成臂**：复用 S70 A0，只给每个目标加局部 +5° yaw，保持历史、相机中心、K、外观条件和随机流，完成 50 步真实生成（**1469.889 s**）。在可匹配点上，“按预定相机变换 H”相对“画面原地不动”的配对中位优势为 **53.274、51.421、38.173、5.622 px**（目标 20--23），但目标 23 仅 10 点、5 正 5 负，且图像构图严重变化。结论是有限的相对方向响应，**不是相机准确、整图几何正确或创新有效**。
14. **S77：生成图的错误相机标签反证**：不再生成、不读图片/深度，只复用 S73 保存的二维匹配，对同样的 20↔23、21↔22 标签交换计算残差。A0 的“错误−正确”配对中位数为 **+110.835、+41.927、−41.597、−114.821 px**；B 为 **+111.154、+41.697、−41.065、−118.925 px**。也就是说，对目标 22、23，生成匹配反而更接近错误标签。25109 项独立标准库算术检查无失败。这个负结果把结论收紧为：目前的相机条件/观察器/内容之间仍有混杂，不能以它支撑相机控制成功或方法创新。

### 2.4 动态记忆创新：目前只有严谨的问题筛选，不是实验结果

15. **已查近邻与反例**：WorldMem、ReMind、VideoTree 已分别覆盖固定预算历史选择、旧状态/事件锚和任务相关关键帧分配的大部分宽泛想法；Physion++ 与 PHYCINE 已覆盖“早期诊断交互揭示持久物理状态”的宽泛动机。因此“记住旧事件”“选重要帧”“加入变点/卡尔曼/事件锚”不能直接作为新颖性。
16. **保留的窄问题**：当被查询对象的早期诊断交互揭示持久状态、之后出现与该对象无关的新事件时，在相同历史预算 k、相同可见输入、相同 consumer/denoiser 预算下，是否有选择器能保留真正有预测价值的证据？它必须先被“对象身份 + 紧凑状态估计 + 任务相关选择”这种简单强基线击败；否则没有复杂机制的理由。
17. **真实动态数据现状**：Perception Test 是最有希望的公开真实录像候选，官方文档和 cutoff mapping 已读取（69,884 B；cutoff mapping 2,185 keys），但样例 annotation ZIP 两次 TLS 失败、没有获取 annotation body 或视频。Ego4D 需要许可和凭据，Phys-AD 不是已证明的长历史配对任务。Coffee Martini 只看过 cam06 前 5 秒的十张截图，画面是人操纵容器，不满足当前被动遮挡/碰撞假设。FloWM 仅完成源码/配置 CPU 准备，未加载权重或运行模型。故目前没有真实动态记忆实验。

## 3. 建议向导师说明的下一阶段路线

这不是承诺式时间表，而是每一步都必须通过前一步证据门的研究路线。

1. **先关闭当前静态相机诊断的普通解释**：把 S77 的反证作为边界，确认 VMem 的相机条件、坐标约定、近似 K、匹配选择和内容漂移各自能解释多少；不在这条证据上强行发明机制。
2. **建立动态问题的合法数据与 consumer 合同**：只在能核实对象 ID、时间 cutoff、训练/测试隔离以及未来可评分目标的真实视频上继续；没有符合条件的样本就停止，不把合成 Physion++ 说成真实录像。
3. **冻结一个可证伪假设**：例如“对象特定的早期证据在无关近期事件之后对预测仍有增益”。需要事先固定：可见前缀、k、特征、计算量、目标、强基线、失败判据和独立确认集。
4. **先跑最小公平对照**：最近帧+覆盖、最近可靠事件 anchor、对象身份+状态 tracker、任务相关后验/变点基线，均使用相同输入和总成本。若简单 tracker 已足够，放弃复杂选择器。
5. **只有最小对照有明确剩余效应，才实现机制并接入生成器**：再评价视觉质量、几何一致性、长时一致性和速度/显存；至少使用多场景、重复种子、消融、失败例与独立未见确认。

## 4. 导师可能提出的 20 个尖锐问题与诚实简答

1. **你的核心研究问题到底是什么？**  
   不是泛泛地“给视频加几何”。当前问题是：固定历史预算下，世界模型是否会因丢掉与目标相关的早期状态证据，而在长程重访/遮挡后产生几何或状态不一致；先验证这个瓶颈真实存在，再选择机制。

2. **你为什么选 VMem 和 CUT3R？它们分别承担什么角色？**  
   VMem 是生成 consumer 的候选基线，CUT3R/TTT3R/FILT3R 用于独立几何测量与轨迹基线。几何模型可运行不等于生成模型已经被完整复现；这两条证据在报告中分开。

3. **你真的做过生成实验，还是只做了模拟？**  
   两者都有，但会分开说。S70 和 S76 是本机真实 VMem 路径的实际 50 步生成；S72--S77 多数是对真实照片或已保存生成图的几何计算；还有源码/缓存身份检查。合成或保存量复算不会被称为生成实验。

4. **目前最可靠的实证发现是什么？**  
   在一个已见的真实室内序列上，生成图的已接受外观匹配与指定相机的固定极线关系存在大偏差；真实对照对正确/错误相机标签有明显区分。这是一个受限失败诊断，不是整体模型结论。

5. **S76 不是已经显示相机转动有响应了吗？为什么还说失败？**  
   S76 只表明部分匹配点更接近预定的相对变化；目标 23 点很少且构图严重变化。S77 又显示生成的 22、23 在错误标签下残差更低，因此不能把 S76 升格为“相机服从正确”。

6. **S70 的 B 分数更低，是否说明 B 更好？**  
   不足以。它是四目标平均 MSE，A/B 的内容顺序、规范化等也不同；预定的几何支持 A 受益事件为 false。像素 MSE 较低也不代表几何或视觉质量更好。

7. **你的相机/极线测量是地面真值吗？**  
   不是。它使用固定相机关系、近似 K 和自动匹配；真实照片对照有低中位数但也有很大尾部。它是有边界的观察器，不是物理标定或整图真值。

8. **生成图为什么会更接近错误相机标签？**  
   目前不能唯一归因，可能包括内容形变、重复纹理/错配、相机接口或坐标约定、近似内参、生成器对条件的部分忽略。S77 的价值正是排除“当前诊断已经证明相机正确”的过强说法。

9. **VAE 往返误差很小，能否排除 VAE 问题？**  
   不能。五张缓存历史的粗结构能重建，但只约三到五成原图特征得到接受匹配，存在大离群点，且生成 latent 的分布不一定等于历史 latent。它只削弱一种“普遍严重解码扭曲”的解释。

10. **真正的创新点是什么？**  
    目前没有可宣称的创新方法。正在严谨筛选一个更窄的问题：对象特定的早期证据能否在不增加历史预算与生成成本的条件下，帮助无关近期事件之后的预测。创新是否成立要由最近邻排重和公平结果决定。

11. **为什么不直接用事件锚、变点检测、Kalman/BOCPD 或注意力？**  
    这些都是必须比较的已有强基线或工具，不是自动创新。若简单身份+状态 tracker、最近可靠事件或变点基线已达到同样效果，复杂方案将被放弃。

12. **WorldMem、ReMind、VideoTree 与你的想法有什么关系？**  
    它们已经占据历史选择、旧状态记忆和任务相关关键帧的宽泛空间。项目只有在输入、固定 k、生成 consumer、可观测性和可证伪预测上有清晰差异，并且简单基线不够时，才可能形成窄贡献。

13. **你如何避免 future leakage 或为新方法提供额外信息？**  
    在实验前冻结可见前缀、split、k、特征和计算预算。未来 RGB、答案、未来框和状态标注只用于评价，除非每个基线都显式、等价地得到它们。不能事后按结果选择帧或样例。

14. **你如何区分“历史信息丢失”与“读出器能力不足”？**  
    不会用一个受限线性/核读出器的风险差证明信息论丢失；已有精确数学反例。只能说在固定任务、数据划分、训练预算和预注册读出器族下，某种历史选择的预测效用较高或较低。

15. **为什么目前没有动态实验？**  
    现有 VMem 路径是静态多视角/相机条件，不能把改变视角当成时间预测。真实动态候选的 annotation/时间/对象身份/未来评价合同尚未完整可用；Perception Test 标注样例两次 TLS 失败，Coffee Martini 不符合当前假设，所以没有把准备工作说成动态结果。

16. **有哪些真实数据，数据泄漏风险如何处理？**  
    静态诊断主要用 TUM RGB-D `fr2_desk`，它已被用于方法选择，故只能算探索场景。动态候选 Perception Test 要按官方 `(script_id, participant_id)` split 分组，不能按帧重分；Ego4D 至少按原视频分组，具体协议需由官方元数据再核实。

17. **算力需求是什么？为什么当前本机不够？**  
    当前机器是 M3 Max、64 GB 内存、无远程 GPU；小型几何、缓存和一次 50 步生成可做，系统多场景、多 seed、完整长视频生成与训练/微调不现实。需要确认可用 GPU 型号、显存、队列/时限、存储、网络与允许使用的 checkpoint/数据许可；没有资源前不承诺大规模数字。

18. **当前最大的风险和最可能的负结果是什么？**
