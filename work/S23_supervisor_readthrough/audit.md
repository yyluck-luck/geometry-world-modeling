## 2. 项目事实与原 proposal 的连接

已读主项目 `AGENTS.md`、`RESEARCH_PRINCIPLES.md`、`RESEARCH_MEMORY.md`、最新 `RESEARCH_LOG.md`、`S21_RESULTS.md`、`S22_RESULTS.md`、`PAPER_LOGIC_CURRENT.md` 和原 proposal 全文提取。原 proposal 的目标是 **Geometry-aware World Modeling**：围绕生成式视频／4D 基线，对相机运动、物体运动、遮挡与再出现、稀疏观察或长时程一致性中的明确问题提出几何机制，评价视觉质量、几何和时间一致性及成本。只把轨迹估计做好，尚未完成这个目标。

当前可用证据如下。这里引用项目报告，没有重新打开所有预测数组，也没有冒称独立作者复核。

| 事实 | 当前证据 | 允许得出的结论 |
|---|---|---|
| 三个已有方法已真实运行 | [S21](../../docs/S21_RESULTS.md)、[S22](../../docs/S22_RESULTS.md)：同一段 300 张 TUM fr2_desk 实拍输入 | 本地已经能够比较 CUT3R、TTT3R、FILT3R 的真实几何预测 |
| 更强现有基线已减少误差 | 位置 RMSE：CUT3R 8.253931 cm，TTT3R 2.847830 cm，FILT3R 1.858154 cm | 仅围绕旧 CUT3R 漂移设计普通门控，可能解决的是已有方法已处理的问题 |

原 proposal 的 14 周结构是计划，不是计时器；12 小时/周是原文预期投入，不能当用户已经投入的工时，更不能把多 agent 的并行计算相加为学生学时。阶段判断依交付物成熟度，不能从 S22 推断已经做了 22 周。

## 4. 12 个 skill 的适用阶段和执行要求

以下为针对本项目的应用解释。完整入口文件均已读；上游文件路径和哈希见机器清单。

| Skill | 适用阶段 | 当前可执行步骤 | 当前缺口或使用边界 |
|---|---|---|---|
| idea-evaluator | 已有具体候选、决定是否投入前 | 先审致命缺陷，再以更高／更快／更强／更省／更广及成熟度评价；近邻按对象、机制、输入粒度、设定四轴比较；给继续／修订／否决理由 | 该 skill 明确不负责从零生成点子；先按 handbook 找候选。机制可行性评分不是实验结果，也不是 CCF A 认证 |
| deep-research | 为候选定位最接近工作和争议 | 冻结问题、独立搜索支持与反对视角、追原始论文／官方代码、核实引用、按适用条件综合证据 | 本次只完成技能阅读，未冒称完成整个领域的系统综述；五路结果最后需串行综合去重 |

| vibe-research-workflow | 每次 AI 辅助研究执行 | 使用任务匹配工具、代码审查与局部验收、保留上下文和中间产物、每 30 分钟核查真实性与记录 | 不把作者判断转嫁为自动认证，不强迫用户逐步审批已授权工作，不将 agent 数量当科研贡献 |
| figure-designer | 失败实例、方法图和结果图 | 分别确定图要证明什么，选布局与工具，检查最终尺寸和可区分编码 | 当前应画强基线失败证据；没有新方法时不画虚构 Ours |
| drawio-reconstruction | 需要复原或编辑结构图时 | 按真实参考重建对象、文本与连线，导出预览核对 | 本轮无图重建任务，阅读但未执行；不应为了“用 skill”制造一张无实质信息的架构图 |
| intro-drafter | 有成立的问题与方法、需 Introduction 时 | 先做内部六段逻辑、匹配技术或新问题类型、只使用已核实引用 | 当前可整理技术进展，尚不可写承诺创新有效的成稿 |
| paper-writer | 有作者材料和证据、开始写段落或报告 | 逐事实绑定输入／原始来源，引用独立核查，写清验证范围，不留假数据与占位引文 | 可写真实复现报告；新方法正文须等待其实际形成 |
| paper-polish | 对已有文字做语言修改时 | 保持原意、消除夸张、按证据强弱校准语气、标记可能改变科学含义的编辑 | 不能将“可能”“单段观察”润色为普遍有效或首次 |
| pre-submission-reviewer | 已有完整草稿、投稿前 | 按逻辑、写作、语法、LaTeX 和图逐项列严重度及定位证据 | 当前只适合逻辑缺口诊断，不能宣称已通过投稿前完整审查 |
| rebuttal-guidance | 已收到具体审稿意见时 | 分类关切、匹配回应策略、把新增证据对应到评论 | 当前无审稿意见，未运行该流程；未安装不是当前推进阻碍 |

## 5. 五路创新探索共用验收表

五路可以并行提出独立解释，使用同一证据接口；计算重任务由 root 根据实际并发和内存安排。五个研究方向不等于已经同时启动了五个模型进程。共享输入协议不强迫五路使用同一方法，也不在看完测试结果后共同调参。

每路先交以下研究卡，机器版本见 [five_route_acceptance.json](five_route_acceptance.json)。没有数据的条目允许明确写“待验证”，不得为了通过表格补造结果。

| 字段 | 必须回答的具体问题 | 可核验交付物 |
|---|---|---|
| 重要失败 | FILT 或本方向最接近强方法在什么必要条件下仍失败？对生成主线有什么后果？ | 至少一个真实输入与时间点、完整相关曲线、失败定义；仅轨迹残差暂记现象 |
| 一句假设 | 改哪个对象、用何种允许信息、以何机制影响什么输出，预计何时有效／无效？ | 能被否证的因果句，分开现象、解释、方法 |
| 最近工作 | 最近 3–5 个真正相近的方法已做到什么？ | 原论文／官方代码的定位，四轴差异表；未找到重合不能证明首次 |
| 机制差异 | 去掉新部件后退化为什么已知方法？普通调参、更多数据或预算是否也可解释收益？ | 状态／动作／公式／接口的明确差别，至少一个简单竞争解释 |
| 信息边界 | 推理时能否获得方法用到的信息？是否读到 GT、未来帧或测试标签？ | 输入白名单、因果时序、GT 仅评分的位置；oracle 单独标记 |
| 最小区分实验 | 哪个最便宜的干预可以区分本解释和简单替代解释？ | 预先写假设、比较、变量、控制、指标、选择规则与停止条件 |
| 公平与完整 | 基线是否同输入、权重、适配、允许信息和合理预算？是否报告全部冻结条件？ | manifest、源版本、补丁、兼容回执、运行时间／内存、失败和 null |
| 决策 | 若结果为零或相反是否还支持原假设？为何继续／修订／否决？ | 原结果封存，不以新名字重启相同已否证机制 |
| 可行与下游 | 本地最低实验能执行什么？何时需要生成基线／额外资源？ | 命令或清楚实验接口、资源上限、到生成消费者的接续路径 |
| 下一轮确认 | 如何避免在已看过的单场景上挑条件？ | 冻结探索与确认划分；至少一个独立条件的确认计划，未执行明确标记 |

共同执行次序：

1. **先找问题证据。** S22 已见片段用于探索，不能充当新盲测；对更强 FILT 做整段和按预设条件的失败分析。相机轨迹残差不等于地图错误，更不等于生成视频失败，必要时增加深度／重投影／消费者输出证据。
2. **在生成点子后做评价。** 每路先提出一句机制假设；再查近邻和代码。遇到直接机制重合、非法输入或已被数据推翻的核心假设，应记录并否决该版本；未验证但有合理机制的候选可以进入廉价区分实验。
3. **先冻结再运行。** 在新实验前存输入、基线、阈值选择来源、主要指标、全条件列表和决策准则；确认集不得参与选规则。确定性实验无需为了表格机械重复；随机过程、采样或环境噪声影响结论时才安排相应重复并报告变化。
4. **把观察升级为机制证据。** 至少一个针对性干预、关键模块消融和简单替代解释控制，验证收益来自声称的新机制而非额外算力、特殊样本或实现差异。
5. **合并与反驳。** root 汇总五路的公共发现、互相重叠、矛盾与可区分预测；优先执行信息价值高且本机可完成的实验，不按文字华丽或 agent 自评最高分选冠军。
6. **回到 proposal。** 有局部机制证据后，在几何相关指标与生成消费者中检查是否有效；跨场景、动态／遮挡／长时程等确认规模依研究主张确定。当前完整生成尚未完成必须持续列为缺口。

三个层级不能混淆：**可测试的新假设 → 局部实验证实的新机制 → 能支撑 PhD／CCF A 级论文的完整贡献**。一级通过只授权继续研究，不代表三级完成。独立作者审计、最强近邻对比和最终外部评审也不能由自评分代替。

## 6. 每 30 分钟研究审查应检查什么

此表是对现有用户要求的执行内容，不代表本 agent 已创建或核验了定时任务。调度状态由 root 检查。每次实际审查应记录 UTC、北京时间、审查对象和下一步，不补写未执行时段。

| 审查项 | 留下证据 | 出现问题时的动作 |
|---|---|---|
| skill 是否匹配当前阶段 | 所用文件与 commit、采取的具体步骤、未适用条目 | 改用匹配流程；不追求阅读或调用数量 |
| 是否推进研究问题 | 本轮改变了哪条假设、机制或证据判断 | 如果只是文档堆积，转向一个真实的最小区分实验 |
| 是否用检索帮助判别创新 | 新核实的近邻、原文定位、反例及其影响 | 对未读来源保留待核验；不把搜索摘要当机制证据 |
| 是否用了合适的本地工具 | 命令、输入、输出与退出状态，或为何无需工具 | 先解决实际依赖，再运行；不得把导入通过写成完整模型成功 |
| 是否记录且可交接 | 更新主账的时间、结果路径、哈希、状态、失败与下一步 | root 合并子 agent 产物；子 agent 不并发覆盖主账 |
| 是否守住真实性与资源边界 | 真数据／合成／oracle／真实推理标签、活跃进程与成本 | 修正文案和状态；停止重复已否证假设或无信息增量任务 |

导师汇报可按讲义 p62 准备一页：原 proposal 目标、已完成的真实结果、一个尚未解释的强基线失败、候选机制及近邻差异、下一项决定性实验、当前资源缺口。可以自主准备本地材料；本任务没有授权替用户给导师发消息，也不能声称用户已理解或导师已批准。

## 7. 上游存在的适用性问题及本次处理

严格遵循科研原则需要识别语境和内部冲突，不能机械照抄。以下解释不构成新的审批要求。

- **致命缺陷的计数规则矛盾。** `idea-evaluator/references/fatal-flaws.md` 一处将两个以上 MAJOR 升为 CRITICAL，另一处对应 Accept with Revisions。这里不以矛盾的数量公式自动裁决，按实际是否不可修复、是否被数据否证及修复路线写理由。明确反证与直接重复版本依然应拒绝。
- **工时、幅度和数量是语境化经验。** handbook 2.1 的高工时建议与较新的 lifecycle reference 的能力／时间匹配并不完全一致；handbook 3.5 的 DB 领域提升幅度、数据集数和速度启发式不是本项目普适定律。用户 proposal 的投入计划和当前真实投入须分开。
- **Benchmark 参考主要使用 LLM 例子。** 模型数量、温度、人评和极低准确率困难子集等应按研究对象转换；本项目不能靠人为筛出极难子集或凑模型数量制造“新评价空白”。
- **AI 初稿的历史措辞与新技能不同。** 2023 年讲义 p61 及部分手册写作意见较为保守，而当前 `paper-writer`、`intro-drafter` 明确支持证据约束下的起草。用户已授权自主执行；这里采用当前任务匹配技能、真实引用和作者责任边界，不新增“AI 写一句也需批准”的规则，也不声称已经查验用户学校全部政策。
- **模板不要求凑结构。** 手册、技术模板及案例对挑战呈现和贡献数量有差别。统一要求是问题—机制—实验连贯，不是固定章节数、模块数或贡献数。
- **作图规则需区分真实照片与结构图。** 曲线和文字宜用清晰可编辑的矢量；照片本身是栅格数据，复杂视觉可按 `drawio-reconstruction` 保真保留。不能为了“全矢量”重绘实验事实，更不能生成伪实拍。
- **学习案例不等于原论文独立核验。** 本次通读了 Alpha-SQL、AFlow、LEAD 的教学剖析，没有因此宣称全文核实这三篇原论文。LEAD 案例已说明部分原 Word 截图无法恢复；其缺失部分保持缺失。
