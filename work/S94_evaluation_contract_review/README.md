# S94：GRC-Memory 最小评价合同审查

本目录保存一份独立的实验架构审查。它不是 S91 的结果，也不证明 GRC-Memory 有效；它定义了在 Gate0 通过后，什么样的运行才可以被称为一次公平的最小评价。

## 当前结论

- `S91` 仍然是 `BLOCKED_ON_GATE0`；S93 只取得 TUM 的位姿文本和 AVI 前缀，没有同步 RGB-D PNG 帧，因此本合同目前不能启动。
- S92 的尾部现象只来自已保存预测的回顾性复算，不能替代未见场景评价。
- 本合同要求把 source identity（历史记忆的稳定身份）一直传到消费者和评分端；没有这个链路，只能评价系统输出，不能解释“某条记忆是否被安全使用”。

## 文件

- `EVALUATION_CONTRACT.md`：可执行的冻结合同、指标、基线、成本和停止规则。
- `EVALUATION_CONTRACT.json`：机器可读版本，便于运行前检查。
- `VULNERABILITIES_AND_REPAIRS.md`：独立审查发现的协议漏洞和具体修复。
- `validate_contract.py`：离线合同完整性检查；它不读取未来答案，也不运行模型。

离线检查结果：`S94_CONTRACT_OFFLINE_PASS`（14 个方法条目、4 类主/尾部指标字段）。Python 编译产生的 `__pycache__` 仅是本地工具缓存，不是实验结果。

## 证据边界

通过合同检查只说明协议完整，不能说明数据已下载、模型已运行、GRC 已优于基线或创新已成立。正式运行必须另外保存 Gate0、冻结清单、运行日志、原始输出和独立复核。
