## 2. 哪类误配仍会留下

这些是从规则推出的可能机制，**不是本轮对 18 对图像的观察结果**。S78 正在独立开展实际视觉检查，本任务没有预先替它定性。

- **重复纹理中的稳定错位。** 相似桌边、格纹、键盘或重复图案可能使错误位置在两方向都排名第一。当真正对应更模糊、被遮挡或没有被检测，而某个错误重复块比其他候选更相似时，ratio 与互选仍可能同时通过。比值检验可拒绝一部分近乎打平的歧义，不能保证所有通过者都正确。
- **局部外观相似、结构位置不同。** 生成器可能保留一个物体局部纹理，却移动、拉伸或复制物体。SIFT 仍可能找到局部相似，极线残差却很大。此时既可能是错配，也可能是视觉上可解释但不满足共同静态三维场景的对应，不能笼统归为匹配器错误。
- **只保留容易匹配的区域。** 模糊、低纹理和外观改变可能让困难区域没有匹配，而留下小范围清晰重复细节。更少点上的中位误差下降不说明原图几何更好；它也可能只是观察器改变了所看区域。
- **二维互选不检验物理条件。** 当前规则没有物体身份、运动/非刚性 mask、深度、遮挡、相机时间或跨帧联合约束。两端点互选只是描述子关系，不能替代这些条件。

## 3. 唯一替代候选：SIFT + LightGlue，仍按固定请求 F 评分

只提出一个现成对照：使用固定版本的 SIFT 特征接口接 LightGlue，保存它的全部匹配/拒绝结果，再用同一份请求 F 做原定几何评分。LightGlue 是学习型局部特征匹配器；这里把它作为已有较强观察器候选，没有在当前生成图上验证它优于 BF ratio。

依据是项目已存官方源码 `work/S76_relative_camera_response/innovation_sources/response_selectivity/lightglue.py`，对应 commit `eb42fee2d71449efb0aa5c10549752b5d75384d8`。本轮定向读取 258–380、461–535 行及输出恢复相关代码位置；未导入或执行。既有笔记记录的是 ICCV 2023 官方元数据与部分源码阅读，论文全文当时未读，PDF/HTML访问失败已保留；本轮没有新网络检索，不能声称检查了最新上游版本。

| 接口方面 | S73 当前 BF ratio | 已存 LightGlue SIFT 路径 | 对下一合同的影响 |
|---|---|---|---|
| 输入 | OpenCV SIFT 的描述子数组，通过 L2 近邻配对 | `image0/image1` 各含 keypoints `[B,M,2]`、descriptors `[B,M,128]`；SIFT 配置 `add_scale_ori=True`，还读取 `scales` 与 `oris`；应显式给 image_size | 只提供保存的 xy/ID 不够。特征归一化、尺度与方向单位必须核官方特征适配器，不能仅凭维度相同就直接喂入 |
| 配对机制 | 每个描述子独立按距离排序，两方向比值和互选 | self/cross attention 后的匹配分数；双 softmax 与两端可匹配性项，再互选并按分数门槛接收（258–318 行） | 能利用点集上下文及学习到的拒绝机制；仍可能错配或域外失效，分数不是物理正确概率 |
| 运行参数 | 固定 ratio 0.75，未加载匹配网络 | 已存默认 `filter_threshold=0.1`、深度提前停止 0.95、宽度点裁减 0.99；SIFT 使用 `sift_lightglue` 权重名 | 这里只报告源码默认值，不将它们自动批准为新实验设置。需冻结实际权重 SHA、裁减/提前停止、精度、设备和费用 |
| 输出 | 保存已接受坐标对及匹配数；未匹配数由 N−M 记录 | `matches0/1`、matching_scores、matches/scores、stop、prune 等 | 必须保留原 slot 到输出的映射、−1 未匹配、拒绝与裁减。不能用 score>0 冒充接受：低于过滤阈值的未匹配点仍可能带非零分数；接受应按匹配索引判定 |

**当前的保存量接口不足以直接运行这个候选。** S73 源码落盘的是 anchor 全坐标、描述子 SHA/shape、各臂已接受坐标与 ID，并没有保存完整 descriptor 数组和各点 scale/orientation，也没有保存所有目标的完整特征对象。因此不能“对 S77 的二维坐标加一个 LightGlue”就宣称完成替代观察器实验。下一次若开展，必须把新增特征提取和学习匹配实际运行单独记账；若用官方提取器更换了 detector/描述子预处理，结论只能称提取器加匹配器整条观察器的差异，不能声称只换 matcher。

几何验证要避免把答案用来挑点：本候选主统计仍保留所有 LightGlue 接受匹配，以固定请求 F 评分。不能先删掉不符合请求 F 的点，再以剩余低误差证明请求 F 正确。若以后另做 RANSAC 自拟合几何，它回答的是“能否拟合某种关系”，不是“是否遵从请求关系”；必须另作标明、保留全部候选分母，不能代替固定 F 主判定。本文件没有另提第二套 RANSAC 实验。

## 4. 改变观察器后必须另立全目标合同

S73/S77 的数值仍是原规则在原匹配上的真实记录。新观察器无论使残差升降，都不得覆盖原数组、把旧 false/UNKNOWN 改成 true，或事后宣称旧结果由某一唯一原因造成。最多新增一条“结论对观察器选择是否稳健”的证据。

若 S78 视觉记录给出明确开展理由，下一合同须在新匹配/分数出现之前冻结：

1. 使用相同的 source19 与原评分图，完整覆盖 real/A0/B × 目标20–23 的 12 对；图像身份/576坐标、固定请求 F 与既有一次错误标签交换保持可追溯。不因为 target22 已看起来有问题就只跑它，也不按 S78 18 对评级选新匹配。
2. 冻结官方特征适配器的描述子、scale/orientation 语义、索引和预处理；若希望研究纯 matcher 差异，两观察器须消费同一份新冻结的特征。实际无法保持同输入就明确改为整条观察器比较。当前这项兼容性审查尚未做完。
3. 冻结代码/模型权重 SHA、接收阈值与全部运行配置、主/次统计、缺失处理和资源上限；不得看过新图像结果后调门槛寻找赞同原叙事的设置。已有 scene/图像曝光不能逆转，仍称探索性再测量。
4. 每对保留 N、M、匹配覆盖、未匹配、裁减/拒绝与原始匹配 ID/分数/坐标。原始支持变化是结果的一部分，不能仅比较两个不同幸存子集的残差中位数并宣布相机能力改善。若 N 或 source ID 改变，旧三臂交集也不能原样继承；新交集另存并明确身份规则。
5. 主结论仍是观察器条件下的匹配/几何关系；低误差、可匹配性分数或独立算术通过都不能代替三维真值、相机准确性、生成器改进或方法创新。未来执行及结果须另由不同作者核查；本文件不授权下载权重或启动模型。

**当前最小决策：先读完 S78 全18项的实际观察，再决定是否做 LightGlue 特征接口的 source-only 兼容性预检。** 若样例主要是局部视觉歧义，这个替代观察器值得用于检查测量依赖性；若对应清楚但结构发生变化，换匹配器也不能自动修复对生成器的解释。这里不给任何“多少项通过”的科学阈值，不预判 S78 结果。
