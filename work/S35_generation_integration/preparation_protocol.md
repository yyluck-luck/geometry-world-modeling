# S35：原始两批生成的记录接线准备

本文件是代码准备与人工接口检查的规则，**不是完整视频实验的执行许可，也不是创新方法实验**。原始生成协议仍为 `docs/S20_MINIMAL_VIDEO_PROTOCOL_DRAFT.md`；真实模型组件齐备后，另外生成并独立审查绑定完整身份的实际运行文件。

## 这一步解决什么

S20 的 TraceWriter 已完成模块检查，但回执明确写了 `NOT_INTEGRATED`：它尚未接入原循环，也没有保存所有实际条件和返回张量。S34 的普通尺度实验已经完成，不能通过重复短窗几何实验证明视频提升。因此现在补齐原始生成的观察和完整归档，使未来第一批产生的图像是否被第二批真正消费可以直接核查。

这落实 Supervisor handbook 2.2 的基线优先步骤。Claude 本地 scientific-critical-thinking 用于区分“写了观察器”“运行了人工接口”“真实模型生成”“获得创新收益”四类证据。既有尺度约束没有因此获得新颖性。

## 五个新模块的职责

| 文件 | 职责 | 本阶段不能据此宣称 |
|---|---|---|
| resource_gate.py | 先检查所有资源与冻结文件是否存在，再核完整身份；缺件在科学模块导入前终止 | 资源已获得、模型已加载 |
| runtime_factory.py | 使用原始加载器与原配置，只将已验证的原组件路径映射到本地 | 已验证完整 CPU 性能 |
| integrate_original.py | 在原始控制流程前后同步记录；移除新增观察节点后须恢复原 AST | 原模型已经运行 |
| archive_outputs.py | 完整保存实际条件、噪声、返回、图像、缓存与几何量，保留失败前缀 | 归档完整等于算法正确 |
| launch_original.py | 单次新进程、分批时间、进程树内存和磁盘外控；无自动重试 | 进程退出成功等于生成质量通过 |

原源代码目录保持不变。观察器安装必须恢复原绑定，包装后的函数只调用一次原函数；输入会被原算法原地修改的地方，须在调用前同步保存，调用后再记录。第一批返回列表可能与后续缓存共享对象，不能拿最终长度冒充当时返回长度。

## 只针对新接线的人工检查

源码前审通过后，在现有科学 Python 中运行一次新检查，`evidence_kind=synthetic_test`。使用脚本内明确标注的小模型、几何和渲染替身；不加载原模型、旧预测数组、GT、真实照片或网络资源。其目的有且只有三类：

1. 保留原 Navigator、原 trajectory 控制流程及原 CPU do_sample；相同随机种子运行无观察与有观察两种路径，逐值比较返回、PIL 像素、缓存、选中来源、全部随机数状态、调用次数与钩子恢复。原尺寸/槽位和首批填充结构保留；人工解码器小图与两步采样不得标成真实 50 步生成。新归档逐个读回，与记录时的人工原值比较。
2. 在第二批人工采样器注入明确异常，核原异常不被替换、首批产物保留、记录和归档的失败前缀完整、钩子恢复。
3. 资源回调先拒绝，核 trace、archive、runtime 三个工厂均未调用。另用当前 DRAFT 配置验证实际 launcher 不启动 worker；这仅证明草稿拒绝路径，不证明缺失资源已补齐。

单次人工检查预算：CPU 1，120 秒，进程树采样 RSS 2 GiB，独立新输出目录。采用既有外控函数，检查结束后核返回码和落盘输出。出现失败保留原源身份、输出和回执，修正代码或检查定义后才可新版本重跑；不重复旧的 15 项记录器编解码测试。运行前另写精确源码 SHA 与上述规则的冻结文件。

## 将来真实原基线的范围

作者初始图、原配置、CPU FP32、8 线程、seed 42；H/W 576、T=8、50 步，context/target 均 4。原 Navigator 初始化后 left(5)、right(5)，同一 worker 不重新播种。保留原默认 NMS 在历史长度 5 初始化，历史 1→5→9，第二批必须实际消费第一批生成的 ID。原相机、采样、几何优化和原 focal 缓存行为均不偷偷修正；S33 的尺度控制不带入原基线。

原组件为 VMem、指定 SD 2.1-base VAE 的 config 与权重、CLIP ViT-H/14、CUT3R 512 DPT。当前 VMem、指定 VAE、完整 CLIP 未在项目验收；VAE 实际 revision/config/weight 身份尚未知。已有 CUT3R 不重复下载。资源来源沿 S34 有界检查，不读取 token、不代申请账户权限、不自动替换 VAE。

将来单批建议上限 1800 秒、进程树采样 RSS 45 GiB，第一批包括加载，总计 3600 秒，空闲磁盘至少 10 GiB。首批完成边界必须来自哈希链中的实际 cache/map/batch 事件；第二阶段保守起点使用上次 trace 读取开始时刻。0.5 秒是轮询目标，实际间隔另记，瞬时峰值可能未采到。预算尚未由完整生成验证，失败不可抬高上限后追认成功。

即便两批返回，也只标为待独立核验；真实加载、全部原始张量、槽位、两批缓存消费、资源用量需实际审查。视频质量、跨场景改善、新方法和最终 PhD／CCF A 目标另行验收。
