# S60：C2纯旋转输入是否留下尺度缺口？

**结论：有明确的尺度基准缺口，但“400步优化把深度压塌”不是现有证据支持的结论。** 本次首个几何调用没有固定深度，五个给定相机中心均为零；已知姿态路径关闭pairwise尺度归一化。MST之后的相机相似对齐又用最短为1e−6的人工朝向辅助点确定尺度，它可以选择很小的非零尺度。原深度getter的已知梯度断链进一步使“初始化带入小深度”成为比“Adam更新深度造成塌缩”更具体的解释。实际C2初始化尺度和初末深度差尚未存证，不能把这一解释写成已完成数值归因。

本审计只新增源码/已有元数据核对及一个人工数学例子；0真实张量或图像体读取、0Torch/模型、0MST/PnP/优化器重放、0修复启动。原C2失败、near=0.1及所有评分规则保持原状。

- **借用且未独立重算的下游证据。** S60另一作者有限读数回执报告515个surfel的相机z在2.17234e−6至7.40533e−6，全部低于原near=0.1；本报告读取该回执并固定SHA，但不替代root和其他作者的终态/截锥复核。新的问题是这条真实C2失败与上游尺度语义的连接。
- **不是新发现。** [S27](../../docs/S27_RESULTS.md)已在TUM真实重放确认注册深度梯度断开、初始化与400步深度逐位相同；[S29](../../docs/S29_RESULTS.md)已确认初始化公共尺度传播到全部深度；[S34](../../docs/S34_RESULTS.md)已确认固定较强旧深度能改变优化行为，普通公共尺度控制不是创新。这些历史实验不能直接冒充本次C2数值重放，也不能再包装为新方法动机。

## 源码链条：哪些量真正约束尺度

所有下列源码SHA均与实际C2冻结manifest
`caa6d7c04d7784e731165e05c07ff4e358322d14c8e76f08c2337b7f4dc641ac`
一致；完整路径、SHA和读取行号在`SOURCE_READ_SCOPE.json`。源码根为
`work/S20_environment/isolated_vmem_source/`。

1. **本次没有depth anchor。** `modeling/pipeline.py:980–988`传入已有surfel_depths；首次为空则传None。`extern/CUT3R/surfel_inference.py:174–196`仅在depths非None时调用preset_depth，再调用preset_pose，最后MST初始化及GA。本次seq46排除了固定旧深度作为首轮尺度约束。后续若有非零固定深度，`optimizer.py:213–250`会设置并冻结那些深度，初始化setter也不覆盖冻结项：它们能保留一个数值尺度，但不保证该尺度具有物理真值。
2. **纯旋转姿态不是长度基准。** `optimizer.py:102–122`固定相机位姿后无条件设`norm_pw_scale=False`。`base_opt.py:266–285`于是令归一化因子为1，而不是把每个pair scale固定为1；pair scale仍为可变的指数参数，且同时乘到3×4旋转和平移块。给定非零、相异的相机中心能约束共同长度；本次共中心旋转不能提供同样的信息。
3. **MST提供初始化，未必保住模型名义尺度。** `init_im_poses.py:96–139`在多个给定位姿时，先将MST点图/估计相机共同做相似变换，再注册pair poses、初始化深度。其`align_multiple_poses:367–382`对齐的是相机中心和`center + eps*z_axis`；两边分别取`eps=max(median(center_distance)/100,1e−6)`，并进行允许缩放的RoMa配准。目标共中心时eps=1e−6。这是人工数值支撑，不是传感器长度。只有`abs(s)<1e−6`才回退到1，故略大于此界的小尺度不会被回退。MST最强边起点的名义尺度还会被这个相似变换重标，不能把“MST存在”当作持续尺度锚。
4. **目标收缩路径与实际更新路径不同。** `optimizer.py:286–310`的目标匹配世界点与缩放后的pair预测；`commons.py:78–79`的l1_dist实际是加权三维欧氏距离。共中心且所有深度自由时，保持R、K、权重不变，共同取`depth→λ depth`、`pair scale→λ pair scale`，得到`L(λ)=λ L(1)`。像素投影不变；但目标不是尺度不变，而是允许朝零缩小残差。固定非零深度会破坏这一共同缩放族。更关键的是，本次原`get_depthmaps:252–258 → ParameterStack:329–344`先detach再新建Parameter，使注册深度不在前向梯度链中。`base_opt.py:533–575`只把原注册参数交给Adam；clean_pointcloud:349–360仅改置信度。依照这条未改源码，不能把loss下降解释为注册深度收缩；本次真实初末参数没有单独记录，实际逐位证明仍缺失。

## 一个有限数学反例及真正未知的部分

`finite_math.py`只执行一次人工5相机NumPy相似配准：两边朝向均为0、1.25、2.5、3.75、5度，源中心x为0至0.004、步长0.001，目标中心全零。按相同center-and-z公式，源eps=2e−5、目标eps=1e−6，独立最小二乘相似尺度为**1.3399297569e−5**，不会触发`abs(s)<1e−6`回退。这证明“有朝向/MST/极小值回退，所以不会初始化到很小尺度”是错误保证。它不估计C2真实尺度，也不是原Torch/RoMa执行；另一个直接公式计算确认共同半尺度的该欧氏目标为原值的一半。

仍需区分的原因是：①本次相机相似初始化选到小s；②CUT3R/MST输入点图本身已小；③点图到surfel的下游转换/保留造成小范围。旧getter事实反对“注册深度经Adam逐步缩小”，但不能仅靠一份终点或很低loss排除所有数值问题。焦距更新能改变x/y和清理结果，不会自行给轴向深度提供尺度真值。
