## 只需要的非结果字段

先由 root 固定一个 sample video ID，只检查该样例。最低字段为官方 split、video_id、object track id、is_cup_game、frame_rate、num_frames，以及各对象的 frame_ids/timestamps 和对应官方 cutoff。cutoff 只用于界定可观察前缀；它不是目标答案。各字段目前仅有 README 语义，顶层容器、关联键、类型、单位及缺失表示必须映射到实际 JSON schema 后才能使用。不能猜字段名或从答案内容反推对象身份。

这一阶段不看 question、options、answer_id、answers、对象标签/属性、未来框/状态、未来动作语义、视频尾段或任何预测。报告只保留资格判断必需的 ID、split、时间信息和存在性。对象 ID 是同一视频内身份，不自动代表跨视频物理实例。

## 预先筛选规则

1. 样例必须明确属于官方 train，并在已存 training cutoff mapping 中有唯一同名键。这里只做前缀可行性，不把训练样例称为独立测试；不重分帧或自行拼接视频。若 root 选择 valid，必须另有身份核实的官方 valid cutoff，不能套用 train mapping。
2. is_cup_game 必须明确为 true。video ID、对象 ID 与时间轨迹必须能无歧义关联；至少一个对象具有两个不同的前缀时间记录。这个最低条件只证明存在跨时身份记录，尚不能证明早期信息、干扰事件或记忆需求。
3. fps 必须为有限正数；帧数、frame_ids 与微秒 timestamps 必须类型及范围合理，时间顺序可检查，单位和起点由文档/样例 schema 确认。不能暗中修正帧率、插值时间或填补缺失对象轨迹。
4. cutoff 必须是有效且严格位于视频内部的帧边界，并明确官方截断的包含/排除语义。只允许使用已确认属于 cutoff 之前的记录；边界语义未知则停止，不靠经验选择。记录存在非空前缀及尾段长度即可，不查看尾段内容。
5. 任一关键字段缺失、类型/单位未知、ID 冲突、split 不明或 cutoff 不可核实，输出“资料不够”。此轮不自动换另一条样例、不放松规则、不新增诊断族。一个合格样例也只通过可行性门，不构成方法证据。

## 先核实预测模型，再讨论 k 帧

实际 consumer 的文档和代码必须显示它如何区分同一物理场景的不同时间、如何接收目标物理时间或未来时距，以及相机姿态与物理时间的独立语义。还要明确目标是视频未来、对象状态还是其他量，哪些输出可实际评分。仅有帧顺序、扩散采样步数或“video”名称不足以证明上述能力。
