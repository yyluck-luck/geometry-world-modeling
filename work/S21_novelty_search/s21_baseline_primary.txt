L173: ## cite87†FILT3R: Latent State Adaptive Kalman Filter for Streaming 3D Reconstruction†arxiv.org L174: 
L175: #####
L176: 
L177: cite88†Seonghyun Jin†jinotter3.github.io , Jong Chul Ye
L178: 
L179: KAIST AI
L180: 
L181: TL;DR: FILT3R is a training-free latent filtering layer that stabilizes long-horizon streaming 3D reconstruction by replacing heuristic state updates with a Kalman-style token update.
L182: ## News
L183: 
L184:   * FILT3R is accepted to ECCV 2026.
L185: 
L186: _{Inline 4x preview. Full MP4: cite89†assets/highlight.mp4 .}
L187: 
L188: FILT3R builds on the public CUT3R/TTT3R-style streaming reconstruction codebase. This release keeps the public surface focused on the three update rules used in the paper:
L189: 
L190:   * `cut3r`: the original overwrite-style recurrent update.
L191:   * `ttt3r`: the TTT3R confidence-aware update.
L192:   * `filt3r`: the FILT3R adaptive latent filtering update.
L193: 
L194: ## Getting Started
L195: ### Installation
L196: 
L197:   1. Clone FILT3R.
L198: 
L199:     git clone https://github.com/jinotter3/FILT3R.git
L200:     cd FILT3R
L201: 
L202:   2. Create the environment.
L203: The public release was tested with CUDA 12.8. Install PyTorch with pip wheels:
L204: 
L205:     conda create -n filt3r python=3.11 cmake=3.14.0
L206:     conda activate filt3r
L207:     pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
L208:     pip install -r requirements.txt
L209:     # issues with pytorch dataloader, see https://github.com/pytorch/pytorch/issues/99625
L210:     conda install 'llvm-openmp<16'
L211:     # for evaluation
L212:     pip install accelerate evo open3d
L213:   3. Compile the CUDA kernels for RoPE, following CroCo v2 / CUT3R.
L214: 
L215:     cd src/croco/models/curope
L216:     python setup.py build_ext --inplace
L217:     cd ../../../..
L218: ### Download Checkpoints
L219: 
L220: FILT3R uses the official CUT3R 4-64 view checkpoint: cite90†`cut3r_512_dpt_4_64.pth`†drive.google.com .
L221: 
L222: Download the weights into `src/`:
L223: 
L224:     pip install gdown
L225:     cd src
L226:     gdown --fuzzy https://drive.google.com/file/d/1Asz-ZB3FfpzZYwunhQvNPZEUA8XUNAYD/view?usp=drive_link
L227:     cd ..
L228: 
L229: You can also use a different compatible checkpoint by passing `--model_path` to the demo or setting `MODEL_WEIGHTS=...` for evaluation.
L230: ### Inference Demo
L231: 
L232: Run FILT3R on a video or an image folder:
L233: 
L234:     CUDA_VISIBLE_DEVICES=0 python demo.py \
L235:       --model_path src/cut3r_512_dpt_4_64.pth \
L236:       --size 512 \
L237:       --seq_path examples/demo.mp4 \
L238:       --output_dir tmp/filt3r_demo \
L239:       --port 8080 \
L240:       --model_update_type filt3r \
L241:       --frame_interval 1 \
L242:       --downsample_factor 100 \
L243:       --vis_threshold 6.0
L244: 
L245: A small wrapper is also provided:
L246: 
L247:     bash run_demo.sh examples/demo.mp4 tmp/filt3r_demo
L248: To compare the supported update rules, change only `--model_update_type`:
L249: 
L250:     python demo.py --model_update_type cut3r  ...
L251:     python demo.py --model_update_type ttt3r  ...
L252:     python demo.py --model_update_type filt3r ...
L253: 
L254: For `filt3r`, the public hyperparameters are applied automatically. Override them with repeated `--model_hparam KEY=VALUE`, for example:
L255: 
L256:     python demo.py --model_update_type filt3r --model_hparam kalman_fixed_r=0.8
L257: ### Evaluation
L258: 
L259: The public evaluation entrypoints are:
L260: 
L261:   * `eval/relpose/run_tum.sh`
L262:   * `eval/relpose/run_scannet.sh`
L263:   * `eval/video_depth/run_bonn.sh`
L264:   * `eval/video_depth/run_kitti.sh`
L265:   * `eval/mv_recon/run.sh`
L266:   * `eval/mv_recon/run_nrgbd.sh`
L267: 
L268: Example long-horizon pose run:
L269: 
L270:     CUDA_VISIBLE_DEVICES=0 \
L271:     MODEL_NAMES="cut3r ttt3r filt3r" \
L272:     MODEL_WEIGHTS=src/cut3r_512_dpt_4_64.pth \
L273:     bash eval/relpose/run_tum.sh
L274: Example 3D reconstruction run:
L275: 
L276:     CUDA_VISIBLE_DEVICES=0,1 \
L277:     MODEL_NAMES="cut3r ttt3r filt3r" \
L278:     FRAME_BUDGETS="300 500" \
L279:     bash eval/mv_recon/run.sh
L280: 
L281: Dataset layout, environment variables, and additional commands are documented in cite91†eval/eval.md .
L282: ### Dataset Preparation
L283: The preprocessing scripts accept explicit roots and do not assume a local machine layout:
L284: 
L285:     python datasets_preprocess/long_prepare_tum.py \
L286:       --input-root /path/to/tum \
L287:       --output-root data/long_tum_s1
L288: 
L289:     python datasets_preprocess/long_prepare_bonn.py \
L290:       --input-root /path/to/rgbd_bonn_dataset \
L291:       --output-root data/long_bonn_s1/rgbd_bonn_dataset
L292: 
L293:     python datasets_preprocess/long_prepare_scannet.py \
L294:       --input-root /path/to/scannetv2 \
L295:       --output-root data/long_scannet_s3 \
L296:       --sample-interval 3
L297: 
L298:     python datasets_preprocess/long_prepare_kitti.py \
L299:       --input-root /path/to/kitti/val \
L300:       --output-root data/long_kitti_s1/depth_selection/val_selection_cropped
L301: For acquiring the raw datasets and matching the long-horizon protocol, follow the public TTT3R dataset instructions.

L44: # TTT3R: 3D Reconstruction as Test-Time Training
L45: 
L46: Xingyu Chen Affiliation: Zhejiang University Affiliation: Westlake University    Yue Chen Affiliation: Zhejiang University Affiliation: Westlake University    Yuliang Xiu Affiliation: Westlake University    Andreas Geiger Affiliation: Uni of Tübingen, Tübingen AI Center    Anpei Chen Affiliation: Westlake University
L47: ###### Abstract
L48: Modern Recurrent Neural Networks have become a competitive architecture for 3D reconstruction due to their linear-time complexity. However, their performance degrades significantly when applied beyond the training context length, revealing limited length generalization. In this work, we revisit the 3D reconstruction foundation models from a Test-Time Training perspective, framing their designs as an online learning problem.
L49: Building on this perspective, we leverage the alignment confidence between the memory state and incoming observations to derive a closed-form learning rate for memory updates, to balance between retaining historical information and adapting to new observations.
L50: This training-free intervention, termed TTT3R, substantially improves length generalization, achieving a $2\times$ improvement in global pose estimation over baselines, while operating at 20 FPS with just 6 GB of GPU memory to process thousands of images. Code is available in cite32†rover-xingyu.github.io/TTT3R†rover-xingyu.github.io .
L51: cite33†Image: [Uncaptioned image] L52: Figure 1: Left: CUT3R [cite34†89 ] encodes observations into a state (memory) $\mathbf{S}_{t-1}$, then interacts with new observation $\mathbf{X}_{t}$ and retrieves 3D information by reading out the output token $\mathbf{Y}_{t}$. However, it suffers from the forgetting problem and degrades significantly as the number of input views increases.
L53: Right: We treat the state $\mathbf{S}_{t}$ as a fast weight updated via gradient descent, where the learning rate $\beta_{t}$ and the gradient $\nabla_{t}$ are predicted by the frozen slow weights. These slow weights are learned from training datasets and act as a meta-learner, enabling the fast weight to serve as an associative memory. In addition, TTT3R makes online state updates by balancing the retention of historical information ${\mathbf{S}_{t-1}}$ with a confidence-aware learning rate $\beta_{t}$.
L54: This visualization also incorporates a state reset process, please see cite23†Appendix B for details.
L55: ### 1 Introduction
L56: 3D reconstruction foundation models aim to predict camera poses and scene representations from a set of input RGB images. Building on the sequence modeling [cite35†76 ], recent advances [cite36†91 , cite37†87 , cite38†101 ] successfully map sequences of images into pixel-aligned pointmaps [cite39†11 , cite40†12 ]. Among these methods, the Transformer [cite41†82 ] has emerged as the dominant architecture, owing to its training efficiency and ability to capture long-range dependencies.
L57: However, a fundamental limitation lies in the quadratic growth of computational and memory costs with respect to sequence length. Despite various engineering optimizations, such as KV-cache compression [cite42†44 ] and flash attention [cite43†22 ], the softmax attention remains unchanged and continues to face limited scalability for long contexts [cite44†45 ].
L58: Figure 2: GPU memory cost for inference.
L59: Real-world applications often require handling an arbitrary number of images. As Figure cite45†2 shows, recent feed-forward methods (e.g., VGGT [cite37†87 ], Point3R [cite46†95 ]) suffer from high memory consumption. Notably, only CUT3R [cite34†89 ] achieves constant memory usage with RNN-based design. However, as illustrated in Figure cite47†1 , CUT3R fails to generalize to long sequences due to training on most 64-frame sequences.
L60: Motivated by these observations, we ask ourselves if there are lessons from modern RNNs that can be used as design principles for 3D reconstruction.
L61: Recent advances in Recurrent Neural Networks (RNNs) demonstrate performance on par with Transformers on language tasks [cite48†37 , cite49†34 ]. Recurrent architectures compress the history context into a fix-length memory state, with each output depending solely on the current state and the incoming observation. This recurrent mechanism offers two benefits: efficient processing of long sequences with linear computational complexity, and the ability to scale to longer sequences by simply rolling out the state.
L62: Nevertheless, these benefits often come at the cost of substantial performance degradation, particularly when the sequence length exceeds the training context [cite50†84 , cite51†62 ].
L63: This naturally raises two questions: (1) why do these models fail to provide robust length generalization? and (2) how can length generalization be achieved? To answer these questions, several studies [cite52†8 , cite53†99 , cite51†62 ] have investigated the length generalization of RNNs, identifying correlations with state overfitting [cite54†90 ], state forgetting [cite55†17 , cite56†36 ], and unexplored state distributions [cite51†62 ].
L64: Solutions such as training on longer sequences and employing Truncated Backpropagation Through Time (TBTT) [cite57†75 , cite58†94 , cite51†62 ] have been proposed to improve length generalization. While these techniques have been incorporated into recent 3D reconstruction foundation models, such as CUT3R [cite34†89 ], they still struggle to generalize to sequences comprising hundreds of images.
L65: In this work, we revisit the state update rule of recurrent 3D reconstruction models through the lens of Test-Time Training (TTT) [cite59†73 , cite60†88 , cite61†7 ], and systematically investigate the factors that hinder their ability to generalize across varying sequence lengths. Specifically, inspired by recent findings that recurrent models struggle with length generalization due to state overfitting [cite51†62 ], we reformulate state updating as a TTT-style online learning process [cite44†45 , cite60†88 , cite61†7 ].
L66: In our framework, the historical information is compressed into a state online. We interpret the state as a fast weight [cite62†64 , cite63†65 ] learned at test time from the input in-context tokens, rather than from the training dataset.
L67: This perspective provides a principled understanding of state overfitting, suggesting that associative recall [cite64†9 , cite65†60 ] over long contexts, combined with gradient-based updates using adaptive learning rates to balance forgetting and learning [cite66†74 , cite67†97 , cite68†5 , cite49†34 , cite44†45 , cite62†64 , cite69†6 ], can substantially enhance length generalization.
L68: Furthermore, we find that CUT3R [cite34†89 ] can be interpreted as a test-time training mechanism, whereas simply extending the sequence length during training leads to extremely low FLOPs utilization. Therefore, we propose a simple yet effective inference-time state update rule, termed TTT3R, derived as a closed-form state transition for online associative recall in CUT3R.
L69: This transition function explicitly defines the learning rate required to update the state at test time, thereby enabling length generalization. Our approach exploits internal confidence signals to selectively suppress low-quality state updates. This yields a stable, training-free gating mechanism that mitigates catastrophic forgetting [cite70†38 ] without requiring fine-tuning or additional parameters.
L70: We evaluate TTT3R on standard 3D reconstruction benchmarks, which are typically configured with short-sequence inputs. In this setting, TTT3R performs competitively with state-of-the-art online reconstruction models [cite34†89 , cite46†95 , cite71†106 ] and demonstrates significant improvements with long-sequence inputs. More importantly, these gains in length generalization come at NO additional computational cost over the baseline, thanks to the proposed state update rule.
L71: Overall, we introduce a new TTT-based framework to analyze the behavior of stateful 3D reconstruction models. Based on this, we propose a simple, empirical state update rule to enhance sequence length generalization for CUT3R.
L72: ### 2 Related Work
L73: SfM and SLAM. Structure-from-Motion (SfM) [cite72†57 , cite73†58 , cite74†70 , cite75†2 , cite76†66 , cite77†69 , cite78†39 ] and Simultaneous Localization and Mapping (SLAM) [cite79†52 , cite80†50 , cite81†23 , cite82†29 , cite83†104 , cite84†43 ] have long been the foundation for 3D structure reconstruction and camera pose estimation.
L74: These methods rely on associating 2D correspondences [cite85†4 , cite80†50 , cite86†47 , cite87†25 , cite88†63 ] or minimizing reprojected photometric errors [cite82†29 , cite89†30 ], followed by bundle adjustment (BA) [cite90†1 , cite91†80 , cite92†79 , cite93†77 , cite94†86 , cite40†12 ] for structure and motion refinement.
L75: Although highly effective when assembled into comprehensive systems [cite80†50 , cite76†66 ], these approaches often struggle in conditions of small camera parallax or ill-posed conditions (e.g., dynamic or textureless), leading to performance degradation.
L76: Recent work, such as MegaSaM [cite84†43 ] and VIPE [cite95†35 ], has demonstrated progress in adapting traditional SLAM paradigms to dynamic scenes by integrating semantic segmentation [cite78†39 , cite95†35 ], optical flows [cite96†105 , cite95†35 , cite83†104 , cite84†43 ], and geometric constraints [cite97†48 , cite83†104 , cite78†39 , cite84†43 , cite95†35 ]. Concurrently, methods like VGGT-SLAM [cite98†49 ] and VGGT-Long [cite99†24 ] seek improved robustness by integrating learned front-ends [cite36†91 , cite37†87 , cite100†51 ].
L77: However, these methods require iterative optimization based on off-the-shelf estimation, where synchronization barriers often lead to cumulative errors and high computational overhead. This reliance hinders real-time online inference and learning scalability (e.g., the ’tabula rasa’ blank slate limitation [cite34†89 ]). In this work, we investigate data-driven feed-forward models with generalizable priors to enable dense 3D reconstruction even from dynamic and textureless video sequences.
L78: Offline Reconstruction Foundation Model. The pioneering feedforward 3D reconstruction method DUSt3R [cite36†91 ] introduced an end-to-end formulation that directly predicts two pixel-aligned pointmaps [cite39†11 , cite40†12 , cite101†68 ] from an image pair.
L79: By leveraging a Transformer-based architecture [cite102†28 ] and direct point supervision on large-scale 3D datasets, DUSt3R inherently accounts for image matching [cite103†3 , cite104†16 ] and pose estimation [cite105†27 , cite106†46 ], resulting in a reconstruction foundation model. Although some follow-up methods [cite107†102 , cite104†16 ] extend DUSt3R for robust dynamic scene reconstruction, they inherit the limitation of DUSt3R, requiring costly global alignment when the number of input views exceeds two.
L80: To address this issue, Fast3R [cite108†96 ] and VGGT [cite37†87 ] propose to use a large feedforward transformer with global attention that handles multiview inputs and predicts per-view pointmaps simultaneously, without the need for post-processing, leading to state-of-the-art 3D point and camera pose reconstruction.
L81: However, relying on the full attention [cite41†82 ] causes a quadratic increase in computational and memory cost, and results in an offline process that requires re-running inference over all images whenever a new frame arrives. Instead, we aim for compute-efficient, on-the-fly streaming inference that supports long-sequence, real-time interactive, and compute-efficient applications.
L82: Online Reconstruction Foundation Model. To improve the reconstruction efficiency, several works introduce memory mechanisms to maintain information from past frames, enabling incremental reasoning and add pointmaps to a canonical 3D space. StreamVGGT [cite71†106 ] concurrently caches historical keys and values as memory in a causal transformer framework, allowing incremental processing. However, similar to full attention in VGGT [cite37†87 ], the computation and GPU memory usage in StreamVGGT grow redundantly.
