# S102 Gate0 数据资格 JSON Schema 草案（2026-09-15）

**状态：** `SCHEMA_DRAFT_ONLY`，尚未对新的 held-out 数据执行，也没有读取未来 GT 正文或连接学校服务器。

**目的：** 在运行任何 GRC/VMem 方法前，自动判断一个数据包是否同时具备真实 RGB-D、可追溯时间戳、内参 `K`、外参/pose、单位、文件哈希、足够的候选历史和严格的 future-GT 隔离。纯 JSON Schema 只能检查字段类型和静态约束；时间匹配、哈希回读、路径泄漏和坐标系一致性还需要下面列出的语义检查器。

## 1. Gate0 的通过条件

Gate0 只有在以下条件全部满足时才允许进入 S103（真实 VMem 长时程基线）：

1. 至少 5 条此前未用于开发、阈值选择或方法比较的独立测试 trajectory；
2. 每条测试 trajectory 至少 3 个 future query，并且有不少于 8 条历史候选（支持 `k=8` 敏感性）；
3. 历史和未来的 RGB、depth、timestamp、pose、intrinsics 都有来源和 SHA-256；
4. RGB/depth 是一对一时间匹配，主阈值为 `|Δt| < 0.020 s`，没有重复 depth 使用；
5. depth 位深、单位、无效值编码、有效像素率和分辨率已验证；
6. `K`、pose 坐标系、SE(3) 方向、单位和分辨率能共同解释投影；
7. selector、调参和人工选择流程无法读取 future RGB/depth/pose 的正文或派生答案；
8. held-out 路径、文件哈希、scene/trajectory 身份与 `DEVELOPMENT_SEEN`、`CALIBRATION_ONLY` 无交集；
9. 许可和访问范围已取得可记录的合规证据。仅有网页说明、ZIP 目录或文件头不能通过正式 Gate0。

## 3. 语义检查器（JSON Schema 之外必须自动执行）

以下检查不能靠字段类型完成，必须由独立 Python 检查器读取**允许的元数据**并返回 `PASS`/`FAIL`/`BLOCKED`。本轮只写检查计划，没有读取新的 future GT 正文。

| 检查 ID | 自动检查 | 失败原因 |
|---|---|---|
| `S102-SPLIT-01` | scene/trajectory/sample/path/hash 与已见开发和校准 manifest 做集合交集 | 任何交集都降为 `SEEN_OR_LEAKED` |
| `S102-PAIR-01` | 重算 timestamp 最近邻一对一关系，确认严格 `<20,000,000 ns` | 超差、重复 depth、非单调或平局规则不一致 |
| `S102-DEPTH-01` | 只在取得合法数据正文后核对 PNG 位深、单位、无效编码和有效率 | 目前未执行；缺正文只能 `BLOCKED` |
| `S102-CAM-01` | 检查 K 的 3×3 形状、正焦距、分辨率一致性、pose 方向/单位声明 | 任一未知或无法投影即失败 |
| `S102-HASH-01` | 文件字节数和 SHA-256 与 manifest 回读一致 | 哈希不一致或路径不可读 |
| `S102-CAND-01` | 每条测试 trajectory 历史候选数 ≥8，future query 数 ≥3 | 不支持 `k=8` 或未来查询不足 |
| `S102-ACCESS-01` | 许可回执明确允许研究使用完整帧正文 | 只有网页/ZIP目录/文件头，保持 `AMBIGUOUS_NOT_VERIFIED` |
| `S102-LEAK-01` | 审计 selector 输入目录、配置和调用日志，确认未来答案不可见 | 任何 future body/metric/派生 GT 进入选择即失败 |
| `S102-POSE-01` | 独立投影少量样例，检查坐标系方向、Z 正值、边界和 z-buffer | 投影反向、单位错或边界规则不明 |
| `S102-TIME-01` | 记录历史→future 间隔、重复 query、连续段断点 | 只用文件序号推断时间即失败 |

推荐检查器返回如下固定结构；`future_body_read` 在本轮必须保持 `false`，它不是新数据结果，只是运行前状态字段：

```json
{
  "schema": "S102-gate0-receipt-v1",
  "status": "BLOCKED",
  "future_body_read": false,
  "server_connection": false,
  "checks": {
    "S102-SPLIT-01": "PENDING_NEW_HELDOUT",
    "S102-PAIR-01": "PENDING_NEW_HELDOUT",
```

## 4. 执行顺序与停止规则

1. 在本机先用 `jsonschema` 或等价验证器检查结构；这一步不接触新的 future GT 正文。
2. 获得合法数据后先建立 `CALIBRATION_ONLY` 和 `HELD_OUT_TEST` manifest，再运行配对、相机和深度语义检查。
3. 所有 selector 和调参脚本先通过 `S102-LEAK-01`，然后写入冻结的 `FREEZE.json`。
4. Gate0 `PASS` 后才允许 S103 单场景真实 VMem smoke test；Gate0 未通过时只能做数据诊断，不能称 GRC 实验。
5. 任一字段缺失、future 泄漏、scene 重叠、候选不足、RGB-D 不能绑定或许可不明，都写入 `GATE0_RESULT.json` 并停止后续方法主张；不删除失败目录。

## 5. 与 proposal 和创新路线的关系

这份 schema 只保证“未来几何误差是否可以被可信地测量”。它不能证明 GRC-Memory 新颖或有效。通过后仍需 S103 真实 VMem 长时程基线、S104 固定槽位强基线、S105 风险校准选择、S106 遮挡重访压力、S107 源级反事实和 S108 尾部/定位分析。若 Gate0 失败，最正确的研究结论是数据资格不足，而不是用合成图或已见缓存结果替代未来真值。
