# 下一阶段：配齐一个开发视角，并核真实文件语义

本文件是预备路线，不代表已有图像/深度下载或新模型运行。S89首先只做匹配成员索引，实际结果以最终回执和不同作者核验为准。

若最终存在完整三件套，固定选择当前已核扫描前缀中最小五位ID，仅用于格式开发。不是随机样本，不是全scene最小ID，也不能以后冒称该视角是未见测试样本。完整三件套按同basename的JSON、RGB EXR、depth EXR定义；seg EXR若实际存在则另记，不推断其不存在。

另行绑定三/四个成员的实际offset、size、归档固定commit、索引验收SHA；最多四个精确Range、单文件16MiB、总50MiB、300协作秒、一批、出错停止。超上限不偷偷换样本，也不下载整档。旧已缓存同一成员若SHA/身份可用则直接复用。不将本草案当已冻结执行合同。

第一用途是读取该开发视角的真实通道名、dtype、data/displayWindow、压缩方式及像素分布，并核本机读取器。EXR的lineOrder描述行块存储顺序，不能直接决定相机Y方向。真实RGB、深度、分割与对象JSON字节访问范围都须如实记载，不能用“未显示”代替“未读答案”。不以阈值筛选删除极大值后声称几何正确。

再按作者来源和实际格式核正Z/负Z、像素中心、range与Z换算及miss规则。必要时补一份底层作者源码；不靠目标生成图片效果试符号。单视角内部反投影再投影恒等或相机矩阵逆关系只确认算术自洽，不是独立物理精度。未知归档构建版本保留为限制，不要求无法证明的完美来源来阻止透明探索。

如需预览，HDR到显示图的变换必须明确固定并保留原EXR；图片标注“RTMV模拟场景的数据集原始渲染”，不能称用户实拍或本项目新模型生成。深度伪彩图单独标单位未完全核定、显示范围和无效像素。

一个开发视角只解决格式依赖。之后至少凑齐并验证8个可用视角及固定选择、相机路径和共同支持，才考虑新VMem四历史/四目标基线。若使用独立源深度作为输入，明确这是提供额外正确几何的诊断对照；独立目标信息留作评分。不得把单视角下载、模型自洽、RGB低MSE或工具接通包装成新方法。

格式依据：[OpenEXR官方结构](https://openexr.com/en/latest/OpenEXRFileLayout.html)与[技术说明](https://openexr.com/en/latest/TechnicalIntroduction.html)，本轮实读格式/属性/通道/行序相关段，原工具回执在OPENEXR_OFFICIAL_SOURCE.json；不是NViSII具体归档构建证明。
