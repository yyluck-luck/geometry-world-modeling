## 二、⚠️ 必须由你裁定的协议遗漏

冻结协议 P1 写"**memory 臂**相对 recency 臂"，但臂矩阵有**两个** memory 臂：

| 臂 | 选帧方式 |
|---|---|
| `recency` | 清单固定：目标前最近 4 帧 |
| `early_visit` | 清单固定：早期访问区 4 帧 |
| `memory_nms_on` | **`get_context_info` 原生检索**，NMS 开启（VMem 默认） |
| `memory_nms_off` | **`get_context_info` 原生检索**，NMS 关闭 |

**主对照究竟指哪一个，协议未定义。** 按「不得事后发明」原则，本方不自行选定。

**建议（待你裁定）**：以 `memory_nms_on` 为主对照，因其是 VMem 默认配置；
`memory_nms_off` 与 `early_visit` 作为预先声明的次要臂，全部报告，不事后择优。

## 三、预算清单（已核对，无重复计数）

**NMS 已编码在四臂之内**，不构成额外层，故不存在 256 的重复计数。

```
16 窗口（8 重访 + 8 对照，同一序列的两类）
 × 4 臂（recency / early_visit / memory_nms_on / memory_nms_off）
 × 2 seed
 = 128 次生成
```

另计可见成本：模型加载、surfel 构建（memory 臂每窗口一次）、评分、失败重试。
**不承诺墙钟时长**，按实测吞吐事后报告。

**已声明的终止失败路径**：`get_context_info` 在候选为空时会抛 IndexError
（S111 实测中 2/16 窗口如此）。该情形记为该窗口该臂的**终止失败**并保留，
不替换窗口、不调整判据。
