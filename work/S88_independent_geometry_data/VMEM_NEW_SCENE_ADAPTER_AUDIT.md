# 独立场景接入已有VMem实验：必须保留的坐标边界

本次只是为新数据资格审查核实际已用输入路径；0数组解码、0模型/评分。逐文件SHA及明确阅读行段见VMEM_ADAPTER_SOURCE_MANIFEST.json。此前S69已有不同作者相机/射线复核，本轮不重跑那些检查，也不把本页当新坐标发现或新算法。

1. **原参考坐标和消费者坐标分开。** S69将标准光学c2w先右乘D=diag(1,-1,-1,1)传原消费者；get_cond再翻相机局部第1/2列。这里列按0起始。新数据若本来是OpenGL/Blender约定，先按数据作者定义明确转换，不能把名字含c2w视为同一基。D右乘改局部轴，不是把世界坐标整体翻轴。
2. **先居中再缩放是生成条件。** 实际pipeline.get_translation_scaling_factor按全8相机计算离中位位置距离、0.97分位筛选及均值居中；首相机居中范数非近零时系数camera_scale/r+0.01，近零分支camera_scale。当前camera_scale=2。原utils另一函数有camera_scale/r但无+0.01；它不是S69调用的同一路径，不能拿它替代。方法间必须共用冻结请求相机与相同变换，不用目标图像挑尺度。
3. **消费者单位不是评测单位。** get_cond对居中光学c2w及w2c平移都乘同一系数，产生射线/力矩条件。物理米或模拟器单位的深度/位置评价仍需保留原始K、c2w/w2c、scale及其反变换。不能拿归一化平移直接与米制深度配对，也不能把缩放后距离当米精度。
4. **已有生成预算是4历史+4目标。** S69当前序列是4个允许历史latent/embedding和4个目标相机，K像素单位576网格，mask前4真后4假。S70实调do_sample用H=W=576、T=8、4通道latent和cfg=2；新数据没有现成这4历史cache，必须新编码、绑定身份并另立执行合同，不能只改target路径冒充新场景已运行。
5. **相机共同输入与答案隔离不矛盾。** 若任务本来请求已知相机，新数据K/请求位姿可给所有方法；目标RGB/深度/实例对应仍是评分答案。GT深度若被用于生成warp，只能先标oracle诊断或给对应同信息基线，不能把它的额外监督当方法收益。两种信息协议应另分臂，不把GT-assisted策略对只看RGB的旧臂称公平机制对照。
6. **未见资格不靠换文件夹。** 新场景先审其与规则选择/当前数据的关联；公开模型训练是否含同场景若无法核实应保留UNKNOWN。冻结之后未据目标答案选规则，可以支持未参与本项目选规则的探索；不必因此谎称模型预训练绝对未见，也不把未知当所有本地研究无法进行的理由。

已有S69输入是TUM转换，不可直接当其它数据的转换证明。下一步只在具体官方小样例的坐标/深度语义得到确认后实现最小适配；目标图像/评分数据继续隔离。普通修正坐标是基线正确性工作，NO_METHOD_SELECTED / novelty_authorization=NONE / new_method_validated=false。
