## 2. 按问题分级，不要求一次取得完美真值

| 可取得的参考 | 可以开展的最小问题 | 不能据此声称 |
|---|---|---|
| 同一静态场景或同一模拟状态的 RGB、来源明确的 K/RT | 在固定目标参考上的完整 RGB 误差及非盲外观记录；对事前固定匹配观察器作条件性的极线一致性诊断 | 唯一的源点目标位置、米制三维误差、目标遮挡真值、生成物体身份正确 |
| 上述资料加外部源深度，且深度类型与相机注册已确认 | 为深度有效源点计算期望目标坐标；对明确建立对应关系的生成位置报告条件误差 | 仅凭落在画面内就判可见；把对应失败、深度缺失算作位置正确 |
| 外部稀疏三维点/目标二维标注及可识别身份；可选目标深度或可见性标签 | 对预先定义的有限物体/点测位置、缺失、重复；有可见性参考时再测遮挡相关问题 | 自动覆盖全图、所有物体，或证明长期状态记忆/跨场景泛化 |

一般平移下，只有 K/RT 时，源像素确定一条三维射线；不同深度沿射线投到不同目标位置。正确匹配应满足极线约束，但低极线残差不是唯一对应证明。**纯旋转或已知平面是需要明确声明的特例**，可由相应单应关系预测位置；不能把这种特例推广到未知非平面场景。纯旋转下常规平移型极线检验也可能退化。

没有深度时仍可使用可靠稀疏二维对应或外部三维地标；稠密深度不是唯一合格入口。反过来，即使模拟器给出完美参考深度与实例 ID，生成图没有继承这些 ID：两个杯子重影中哪个对应原杯子仍是测量问题。观察器必须事前规定候选、位置、重复、漏检、歧义和无法评分状态；不得看目标真值后挑最近的候选，或把未匹配点静默删除。若暂时没有可靠生成身份定位，只报告参考几何和观察器条件结果，保留绝对物体位置结论为 UNKNOWN。

## 3. 获取小样例前就填写的最小数据身份表

正式合同应逐文件填写以下字段；没有证据的字段写 `UNKNOWN`，并限制相应结论，不猜值。

| 字段组 | 必须记录的内容与来源 |
|---|---|
| 身份与来源 | 数据集/实际版本、官方入口、固定代码 commit 或已取原文字节 SHA；小片段的归档成员、文件路径、字节和 SHA；场景/采集或渲染批次/视角/帧 ID；许可声明来源与未解决冲突。代码许可不自动代表数据或原资产许可。 |
| 场景与时间 | 是静态场景多视角，还是同一动态状态的同步视角；依据为物理采集说明/时间戳或模拟器同一状态 ID。相同帧号、相似画面、相同对象名称不证明同步。实测还记录曝光/时钟/同步误差已知范围；未知不伪称精确同时。 |
| 相机与图像 | 原尺寸、RGB 通道/范围/量化；K 的投影模型、像素坐标原点/中心约定、畸变与是否校正；RT 是 world-to-camera 还是 camera-to-world、行/列向量、轴向/手性、平移单位。每个结论回到作者导出代码或物理标定来源，而非文件键名推断。 |
| 预处理 | 所有缩放/裁剪/补边及像素映射；对应 K 更新；最终数组实际精度及读回数值。线性像素变换满足相应条件时才用 K′=AK；非线性去畸变另存映射。不得用名义整数 K 替换实际保存的浮点 K。 |
| 深度，仅在使用时必填 | 原 dtype、单位比例/偏移、是光轴 Z/欧氏距离/逆深度/视差/渲染缓冲值、背景与缺失码、有效区间来源、与哪张 RGB 注册。视差没有基线/焦距不能换米；渲染缓冲值不能直接当 Z。 |
| 对象/点身份，仅在该问题使用时必填 | 稳定实例与点 ID、每个时刻的外部位置、投影/可见性生成依据；参考身份与生成图观察器输出的关联规则分别记录。模拟器参考称模拟器参考，传感器参考称实测参考；模型预测不得冒作二者。 |

例如理想针孔下，归一化射线为 `(x,y,1)`：光轴深度直接给 `Xc=Z(x,y,1)`；若文件保存欧氏射程 r，则 `Z=r/sqrt(x²+y²+1)`。只有文件语义和投影模型已确认才能选其中一个。深度必须与位姿处在同一单位；尺度未知时最多报告声明的相对/模拟器单位，不报米。

源深度无效、目标相机后方、非有限、出画面、已知遮挡、可见性未知、生成身份未找到/多个候选必须分别计数。评分报告总请求数 N、参考有效数 V、可定位数 M、实际可评分数 S；保留所有排除原因与分母。条件误差与覆盖/缺失并列，空集报 NA/UNKNOWN，不能填 0 或默认为错误。若要把漏检纳入任务损失，另在执行前规定，不能结果出来后处罚或豁免。

## 4. 输入与目标答案的分离合同

1. **所有普通方法的共同允许输入**：冻结的源 RGB、其合法时间/视角元数据、源 K/P，以及任务本来请求的目标 K/P。若采用当前 VMem 接口，另固定四输入＋四目标的完整八槽顺序；样例不足八视角不假造帧，而是另审更小接口。同步新视角输入须叫多视角条件，不能改称过去历史，更不能由此证明未来预测。
2. **默认仅评分侧可读**：目标 RGB、目标深度、目标实例/轨迹/可见性答案；RGB-only 任务中的外部源 GT 深度也仅供评分侧。生成阶段不得以目标答案选源帧、阈值、姿态尺度、强度或最佳输出。
3. 若把外部源 GT 深度用于 warp，标记单独的 **oracle 诊断**（额外真值输入），并给比较方法对应相同信息，或明确它只是信息上界对照。不能与 RGB-only 基线混称同信息机制比较。目标深度作引导涉及更多答案输入，也必须另设合同，默认禁止。
4. 先冻结样例 ID、输入清单、目标清单、变换、全部请求、观察器及失败规则，再生成封存；之后才打开隔离答案评分。已有下载/阅读不追溯改称“从未见过”：记录哪位成员何时看过什么，以及它是否影响选样/规则。必要的标注质量核验与效果选择分开，按预定资格规则操作并保留所有被排除 ID。

**已有 VMem 的特定适配约束：** 外部原单位光学 c2w 与 consumer 版本分别保存。已用 S69 路径先右乘 `D=diag(1,-1,-1,1)`，原 `get_cond` 再翻局部第 1/2 列；这不是所有新数据天然采用的约定。实际 `pipeline.get_translation_scaling_factor` 使用全八个请求相机居中，非近零分支为 `camera_scale/r+0.01`，当前 `camera_scale=2`；不要换成另一个缺少 `+0.01` 的 helper。精确条件、0.97 分位筛选及近零判据以绑定源码为准。共用请求相机是任务输入，不等于偷看目标 RGB；外部评分必须回到原单位位姿，不能把 consumer 缩放平移当米。详见本轮 `VMEM_NEW_SCENE_ADAPTER_AUDIT.md`；本作者已读原保存源码段 1090–1193 与 S69 段 194–234。

## 5. “未见测试”的最低诚实声明

- 按实际物理场景/模拟世界配置及重复轨迹家族划分，不能只随机分相邻帧或改文件夹。记录共享资产、背景、运动、相机轨迹和渲染种子；不同种子不自动代表完全独立场景。
- S73–S87 已见 TUM 场景属于开发证据。下一场景的选择只依事前资格元数据和固定选择规则，不按生成效果、目标误差或肉眼好坏取样。冻结所有合格请求及顺序；失败和缺测也进入报告。
- 至少有一个未用于本项目调规则的独立场景，才可报告“项目内留出场景的一次探索”；一个场景仍不支持跨场景稳健收益。多个视角/像素/噪声不是多个独立场景。要做一般化论断，需另定多场景测试与场景层面的汇总，不在本数据门临时许诺样本量或成功阈值。
- 预训练模型是否见过该场景单独核训练来源；不能确认则写 `model_training_overlap=UNKNOWN`，不称模型绝对未见。这个未知限制未见资格的口径，不阻止透明的小规模探索。
- 不在测试集看完结果后选 λ、观察器或最好方法再把最小值报验证成绩。若因结果修改规则，该集合转为开发集，下一验证另留。S87 六策略事后包络的否证口径不能直接变成新测试的调参程序。

## 6. 最小阶段决策与当前缺口

**数据资格**回答“拿到了什么、能问什么”。**程序坐标检查**回答“是否按冻结坐标和单位实现”，如逆变换、同相机投影、手算光线及保存回读；它不能证明标定真实或生成物体正确。**观察器资格**回答“生成位置是否能可靠识别”，可能需要在新数据上少量有依据的校准；不能用反复更换观察器取得有利分数。**基线效果**需要完整真实输出、外部答案与公平输入的实际对照。**创新**还需要最近方法差别、可推翻机制及独立场景证据。上述五件事不得互相代替。

当前没有候选被本稿正式接纳。PointOdyssey 官方 README 确实描述多模态、相机、轨迹和多视角生成代码，也明确版本曾修深度问题；它不能单独证明某个可下载包里含所需的同刻视角组。作者 issue #7 的 OWNER 回复只说明多数原资产受许可限制，不能由此认定渲染数据不存在或所有资产不可取。具体同步索引、实际版本字段和小片段可得性仍交 root 的来源核验；本稿不套用旧版本深度公式。官方来源原文已在本地留存，本批没有重新请求。
