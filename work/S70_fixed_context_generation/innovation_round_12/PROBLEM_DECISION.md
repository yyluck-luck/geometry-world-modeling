# Round 12 — Is the invisible bounce actually predictable from the allowed past?

**Decision: no distinct innovation is justified yet.** Before another neural comparison, test whether an ordinary state estimator plus the original deterministic reflection rule already predicts the one candidate event. Unknown bounce time can follow from uncertain position, velocity, or boundary location without any history being discarded.

**Closest original alternatives.** [Kalman (1960), Theorem 3 and Applications Example 2](https://people.math.harvard.edu/archive/116_fall_03/handouts/Kalman1960.pdf), explicitly treats constant-velocity particles with noisy position observations and recursive state/covariance estimation. Its assumptions do not establish optimality for perspective pixels, uncertain identity, or a wall-triggered switch. [Nardone–Aidala, technical memorandum 80-2059 (1980), Problem Formulation Eqs. 5–10 and Conclusions](https://www.researchgate.net/publication/235190081_Necessary_and_Sufficient_Observability_Conditions_for_Bearings-Only_Target_Motion_Analysis), analyzes a constant-velocity target through bearings and known observer motion: motion alone does not guarantee a unique solution. The author-uploaded report was actually read; the related 1981 journal DOI did not open and is not substituted for a full-text read. Neither work supplies a FloWM-specific success result.

**What “enough past” means (independent elementary derivation).** If a single object's metric coordinate is measured at two distinct times, with no intervening reflection and correct identity, then x(t)=x0+t·v. The observation matrix [[1,t1],[1,t2]] has determinant t2−t1, so two noiseless positions identify x0 and v. With bounded coordinate errors ε, the two-point velocity error can be as large as 2ε/|t2−t1|. Thus two noisy sightings are not exact state knowledge. A boundary parameter is absent from these free-motion equations: it needs separate geometric evidence or an explicitly allowed prior. Long gaps can also hide multiple reflections, invalidating the free-motion inference.

Our actual inputs are RGB plus observer actions, not those metric coordinates. Bearings/perspective measurements need calibrated projection, a camera trajectory, and valid feature correspondence; image displacement is not world velocity. A stationary or constant-velocity observer admits the familiar generic bearings-only scale ambiguity: scaling relative position and velocity preserves all bearings. FloWM's known unit-speed/grid/room priors can remove some such alternatives, so that generic ambiguity is **not** a proof of ambiguity for its particular episodes. Known action IDs do not directly reveal an object's 3D position or the wall's location in the camera frame. Occluded same-colored blocks and uncertain 2D localization remain separate issues.

**One cheapest diagnostic, before any new model arm.** Use batch11's fixed first original validation episode and its 70-frame allowed prefix, not a prediction-selected failure. For one unambiguously associated visible block, obtain a few past 2D feature observations with a declared error bound; use only the same allowed camera/action/calibration information and explicitly declared original environment priors. Establish the room frame from allowed evidence. If that needs GT depth, object state, or an unprovided initial pose, stop and record the missing input instead of silently granting an oracle.

Keep all discrete position/direction hypotheses compatible with those past observations and propagate each using the **exact source rule**: test the next position against the wall using object radius, reverse direction if blocked, then attempt the reverse step. Do not replace it with a continuous-time elastic formula with different collision timing. This is ordinary finite-state tracking/system identification. Conditional on a known 15×15 lattice in the recovered room frame, four directions give only 900 hypotheses per object; a 70-step propagation is 63,000 state steps, not a GPU task. This is an arithmetic work count, not a measured runtime or a validated implementation. The room-frame and observation-model prerequisites have not yet been demonstrated.

Freeze the resulting range of predicted positions and bounce times before reading the future. An oracle simulator initialized from the true hidden state would settle only the mechanics; a simulator initialized from **past-inferred** states tests the actual information question. A Kalman constant-velocity segment estimate can be an ordinary noisy-input baseline, but a single Gaussian need not represent multiple identity/bounce-time hypotheses. Full RGB generation and pixel-perfect rendering remain different tasks.

**Falsification and stop rule.** If the compatible past-inferred states still imply substantially different future positions/bounce times, this case is not a clean predictable-bounce witness. That establishes ambiguity of the declared observation summary/model, not absence of information in every RGB feature. If ordinary recent evidence yields the same tight prediction as the full prefix, there is no demonstrated need for a new memory-selection policy. Only if the full allowed past supports a tight correct trajectory, a fixed-K recency/uniform summary does not, and a fair consumer comparison exhibits the predicted failure is a history-loss question qualified. Full history remains an information ceiling; all fixed-K policies must retain timestamps and the complete permitted action stream, without treating skipped frames as adjacent. No such result exists here. A subsequent FloWM miss could still be state advancement or readout failure rather than compression causality.
