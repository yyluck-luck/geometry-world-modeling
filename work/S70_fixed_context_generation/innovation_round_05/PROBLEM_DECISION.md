# Batch 05: what HyDRA and FloWM actually retain

Decision: **no qualified new pair-selection mechanism is established.** Both systems support retaining temporal predictive information beyond spatial coverage. Neither inspected evaluation establishes that a fixed budget of raw observations requires a new complementary-pair selector after matched recency, uniform-time and information-design controls. This is a narrower conclusion than saying every possible such selector is already dominated.

Actual review: 2026-09-09 03:14:04 UTC to 2026-09-09T03:25:53.061131+00:00. Two previously read systems were deepened; one classical primary mathematical control was added. No project RGB, depth, latent, model weight or scientific result was read. No model, downloaded source, renderer or selection experiment was executed. ## 1. Access budget is different from attention budget or recurrent-state size

**HyDRA — Out of Sight but Not Out of Mind: Hybrid Memory for Dynamic Video World Models.** The bound paper is [arXiv v1](https://arxiv.org/html/2603.25716v1), 26 March 2026; formal acceptance was not verified. The official code was read at [commit f2c6660](https://github.com/H-EmbodVis/HyDRA/tree/f2c666061098f24d7327968a57e253cf0a339bfa).

The default released entry reads 77 conditioning RGB frames, VAE-encodes the full source clip, and retains its 20 latent slices throughout denoising. It jointly processes those slices with 20 noisy target slices. In every transformer block, a 3D convolution compresses the joint 40×30×52 token field into 20×15×26 memory slices. Each query slice attends to ten retrieved compressed slices plus five local full-resolution slices. That is 10×390 + 5×1560 = 11,700 keys per query slice in this branch; it is not a ten-frame raw-input budget. The retrieved pool contains compressed source and target features, and the selected union may change across layers and diffusion steps. The full source clip has already influenced the representation before selection. There is no streaming raw-frame eviction rule here. [Entry lines 195–243, 273–297](https://github.com/H-EmbodVis/HyDRA/blob/f2c666061098f24d7327968a57e253cf0a339bfa/infer_hydra.py#L195); [pipeline lines 200–365](https://github.com/H-EmbodVis/HyDRA/blob/f2c666061098f24d7327968a57e253cf0a339bfa/diffsynth/pipelines/HyDRA.py#L200); [tokenizer and selection lines 213–360](https://github.com/H-EmbodVis/HyDRA/blob/f2c666061098f24d7327968a57e253cf0a339bfa/diffsynth/models/wan_video_dit.py#L213).

The nominal joint feature size is 40×30×52×D, the compressed pool 20×15×26×D. The entry uses BF16, but normalization/positional operations can use other precision. D is obtained from weights which this review did not read. These formulas are source-derived feature counts, not measured peak memory. Hard-coded dimensions bind the inspected path to its clip layout; arbitrary-length streaming is not demonstrated by this code inspection.

The released affinity computes a dot product between spatially averaged query and compressed-key features. This differs in general from paper Eq. 4's sum of corresponding spatial dot products; record the version boundary, rather than silently treating the formulas as identical. This is not an execution failure finding. The tokenizer already mixes neighboring time slices, and later query/key features are contextualized: calling it independent raw-frame salience would also be inaccurate. [Actual affinity lines 448–497](https://github.com/H-EmbodVis/HyDRA/blob/f2c666061098f24d7327968a57e253cf0a339bfa/diffsynth/models/wan_video_dit.py#L448).

**FloWM — Flow Equivariant World Models: Structured Memory for Dynamic Environments.** [Author paper v2](https://arxiv.org/html/2601.01075v2) was read; ICML 2026 title listing and the author acceptance statement were checked in batch 04. The [official listing](https://icml.cc/Downloads/2026) supports that status; the exact poster page was restricted and no PMLR entry was recovered. Code is bound to [commit c909c54](https://github.com/hlillemark/flowm/tree/c909c54a3d58ae240de03f5ebbec222d3e6b1264).

The inspected dynamic 3D inference configuration consumes 70 ordered history frames and known self-motion actions, and also receives the future action sequence. It sequentially updates a map; it does not pick four or ten original images. The configured recurrent map has five velocity channels, 33×33 spatial cells, and 256 features per cell. With the configured FP32 path this is nominally 1,393,920 scalars, or 5,575,680 bytes per item. This excludes parameters, activations, input sequence, output sequence and optional stored latent-map diagnostics. Fixed recurrent state therefore does not establish fixed total runtime memory. [Inference configuration](https://github.com/hlillemark/flowm/blob/c909c54a3d58ae240de03f5ebbec222d3e6b1264/configurations/shortcode/exp/blockworld/flowm/infer/base_inference.yaml); [model dimensions](https://github.com/hlillemark/flowm/blob/c909c54a3d58ae240de03f5ebbec222d3e6b1264/configurations/shortcode/model_config/flow_vit/flow_vit_10m.yaml).

At each step, internal flow shifts velocity channels, known actions shift/rotate the map, and current-FoV tokens undergo a learned gated update. Query-time readout decodes the action-aligned current FoV, pooling velocity channels in this configuration. Predicted images then update the map during autoregressive inference; the evaluation caller does not pass target RGB into the predictor. There is no timestamp-based frame eviction: overwriting is learned, map extent is finite, and the inspected shift operations use `torch.roll`/`rot90`. Future horizon comes from discrete action steps, not an arbitrary elapsed-time query. The rigid action grammar and learned encoder approximation limit transfer to unconstrained camera trajectories and contacts. [Map updates lines 145–340](https://github.com/hlillemark/flowm/blob/c909c54a3d58ae240de03f5ebbec222d3e6b1264/algorithms/mem_wm/backbones/flowm/flowm_models_3d.py#L145); [consumer lines 526–675](https://github.com/hlillemark/flowm/blob/c909c54a3d58ae240de03f5ebbec222d3e6b1264/algorithms/mem_wm/backbones/flowm/flowm_models_3d.py#L526).

## 2. What the ablations establish, and what remains untested

HyDRA §5.3 and Appendix 0.B compare temporal kernel size, retrieval count and dynamic affinity versus FoV overlap. The appendix describes overlap-based retrieval selecting empty views after a subject moves, whereas affinity can find its appearance. That is evidence against spatial overlap alone in those examples. Finding one view containing the subject is a competing explanation; it does not establish that a complementary observation pair was necessary. Temporal convolution and larger retrieval counts can help without proving pair-selection synergy. Dynamic selection across many blocks also increases cumulative access. The read ablations do not isolate a matched raw-k recency or uniform-time comparator. [Methods, Tables 4–5 and Appendix 0.B](https://arxiv.org/html/2603.25716v1).

FloWM §4 and Appendix H/I compare velocity/self-motion structure, alternative recurrent/diffusion models, and map/FoV capacity. They support the value of its structured representation under the tested action/dynamics assumptions, rather than a raw-frame selection policy. The paper reports substantial training compute and describes dense gated-map updating as not fully optimized. Its successful memory is learned from all available history. No inspected recency/uniform raw-k ablation shows a residual complementary-pair selection failure. Absence here is restricted to the read sections and controls, not a claim that the complete literature has no such result. [FloWM §§3–4, 6; Appendix H4–H9, I1–I3, Tables 13–15](https://arxiv.org/html/2601.01075v2).

## 3. Complementarity already appears in the ordinary mathematical control

Joshi and Boyd, [Sensor Selection via Convex Optimization](https://web.stanford.edu/~boyd/papers/sensor_selection.html), IEEE Transactions on Signal Processing 57(2), 2009, is the added primary control. In its linear measurement model y_i=a_iᵀx+v_i with independent equal-variance Gaussian noise, estimation covariance is proportional to (Σ a_i a_iᵀ)⁻¹. Its fixed-cardinality design maximizes log det(Σ a_i a_iᵀ); it jointly rewards complementary measurement directions. The convex relaxation/rounding is an approximation, not a universal optimality guarantee. [Paper p. 452, Eqs. 1–8 and §III](https://web.stanford.edu/~boyd/papers/pdf/sensor_selection.pdf).

A finite algebraic example already defeats independent norm salience: a₁=a₂=(1,0), a₃=(0,1), budget two. All individual norms are one; {1,2} is singular, whereas {1,3} observes both coordinates. This is classic observability/design, not a new video mechanism. Under a constant-velocity observation model a(t)=(1,t), a pair of distinct times similarly observes position and velocity. Recent/uniform choices may already provide that pair. Conversely, maximizing global log determinant need not minimize a particular query's prediction error; using c_qᵀΛ_S⁻¹c_q for a specified linear query is ordinary query-specific experimental design, not new merely because it selects different frames. Nonlinear contact/mode uncertainty can invalidate a linear information model; that mismatch alone is not evidence for a novel selector.

## 4. One remaining conditional question and stop decision

**Question:** in an independently observed dynamic revisit with a fixed raw-history budget, does spatial selection discard a predictive state change that equally budgeted recent and uniform-time histories, and an appropriate ordinary information-design baseline, also fail to retain?

The cheapest useful prerequisite is one existing real sequence with pre-query object tracks or independently checkable state-change annotations, timestamps, camera self-motion, and a later visible outcome. Freeze the query and budget before looking at the future outcome; keep the selector blind to future RGB/labels. Compare what a common, predeclared elementary motion predictor can infer from spatial/recent/uniform/info-selected histories versus the available full history. This is a local annotation/probe diagnostic, not video generation or Bayes-sufficiency proof; no such run was made here. The dataset feasibility work belongs to the other agent.

If recency or uniform time retains the signal, implement that ordinary baseline before proposing a complex policy. If correctly specified information design explains the difference, this is a known-design integration opportunity. If full history offers no independently checkable predictive advantage, do not attribute the failure to compression. If only a weak probe fails, do not infer that all information is absent or the decoder is solely responsible. A new mechanism would require a reproducible residual beyond these controls plus a concrete reason its accessible inputs and budget can resolve that residual. These two papers do not presently supply that witness. Stop further paper accumulation on generic “complementary pairs”; await the bounded real-data feasibility finding or move to a different demonstrated failure. **No new arm, algorithm, method selection or benefit claim is authorized.**
