# FloWM residual-problem decision, round 11

**Decision: ordinary baseline qualification/reproduction is currently justified; a new memory method is not.** One conditional diagnostic survives: after enough past observations to identify a block's motion and room boundary, does the original model correctly advance an unseen wall reflection until that block returns? No qualifying episode or model failure has been observed in this review. This is a known dynamics/partial-observability test, not an innovation claim.

## What the original task actually contains

The paper-frozen environment is [`flowm_release`, commit bc7972050155b67e242c07bfdccfe1eeddbf9882](https://github.com/hlillemark/Miniworld/tree/bc7972050155b67e242c07bfdccfe1eeddbf9882). Its original dynamic train/validation commands use the same physical and camera-policy settings: grid mode, cardinal velocity, range −1…1, room size 16, 90° camera turns, unit forward steps, six to ten blocks, and `biased_walk_v2` with forward probability 0.92. They request 10,000 versus 1,000 episodes; block-directory sizes also differ. These are author command records, not receipts proving the exact realized datasets are disjoint. The single-item generator uses OS-random seeds unless a base seed is provided. The parallel wrapper remained inaccessible after two SSL failures; actual dataset seed/shard identities were not read.

In [`moving_blockworld.py`](https://github.com/hlillemark/Miniworld/blob/bc7972050155b67e242c07bfdccfe1eeddbf9882/miniworld/envs/moving_blockworld.py#L299), the main flags give initial velocity exactly one of (±1,0) or (0,±1). Velocity persists between events. A wall intersection reverses the relevant component and attempts the reverse step; this is a genuine discrete transition. Main commands disable block–block and agent–block collision response. The engine also supports other collision/torus configurations, but enabling them would change this task. Thus “no contact changes whatsoever” is false, while pushing, arbitrary acceleration, and altered interaction rules are not established in-distribution tests.

Rendering enables depth testing; visual occlusion can still occur despite disabled physical collision response. `generate_videos.py:1554–1620` explicitly re-renders **after** each complete `env.step`, then retains frame t with action/delta t→t+1. The earlier image returned inside the base step is not the saved RGB. `BiasedWalkV2Policy` consults room/agent state, pauses and turns, and uses `do_nothing`; its stale docstring mentioning pickup does not describe the executed returns. Future supplied actions describe observer motion, not human manipulation.

The [FloWM paper](https://arxiv.org/html/2601.01075v2) E.1/Table 4 matches these 3D dynamics; F.1's periodic boundary is the separate 2D MNIST environment. G.5/K.4 describe 50 observed/90 predicted frames in FloWM training versus 70/70 for competing models, with common 70-frame evaluation context; the authors report little difference between FloWM's 50/70 context evaluations. C.3 describes a transient coordinate-probe error followed by recovery. That is not a demonstrated memory-compression failure. Section 6 limits the scope to controlled settings. Formal ICML 2026 listing was already checked in round 10; this round reread the available author manuscript, not a new proceedings PDF.

## One conditional falsification, with its strongest counter-explanation

The original FloWM forecast loop already shifts velocity channels, aligns the map using target actions, and mixes velocity channels over the map before decoding (`flowm_models_3d.py:603–632`). It is therefore unjustified to claim the model cannot change a hidden object's velocity. A wrong returning object could instead reflect ambiguous same-colored tracks, insufficient past boundary information, accumulated state error, or readout error. One probe's failure does not separate these explanations.

After the independent CPU implementation qualifies, the cheapest next step is **one original validation episode, one original checkpoint, the fixed 70-observed/70-predicted window**. First choose the episode by a fixed existing order, without inspecting predictions. Inspect only its allowed past to determine whether at least two separated, unambiguous sightings plus the known camera actions and visible room boundary actually constrain one object's position, velocity and reflection time. Six to ten blocks with a six-color palette do not guarantee unique identity. Save the eligibility conclusion before reading future outcomes; if it fails, report that the first episode provides no witness rather than mine generated errors.

For an eligible case, keep all predicted frames and the ordinary published metrics. The focused question is whether the returning object follows the past-supported reflected trajectory. Any simulator state or future depth used later to annotate the event is evaluator-only information, never a model/baseline input. A cheap ordinary comparison is an analytic constant-velocity-with-wall-reflection predictor inferred from the **same allowed past**, not oracle state. It can first compare recent versus all-history evidence without another neural run. This is a diagnostic control, not an equal-compute RGB generator.

For a future fixed-K selection claim, recency/uniform must use the same K observations, timestamps and known action stream as the proposed selector. Full history is an information ceiling, not a fair same-budget competitor. Simply deleting frames from FloWM changes the per-step dynamics and its training-context regime; running K surviving frames as adjacent steps would invalidate the comparison. A learned selection comparison would require a separately justified matched training/input contract, absent here.

**Stop conditions:** no past-identifiable event; only probe/readout error; ordinary recent evidence already sufficient; or the original model handles the event. Even a clean failure would establish a missed predictable transition, not yet compression causality, a new algorithm, real-photograph performance, or long-horizon benefit. No model, environment, data, pixels, checkpoint, or S70 scientific output was opened or executed in this round.
