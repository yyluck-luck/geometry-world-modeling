■ 3.1 基线建设：三个已有几何方法，由弱到强
  在同一段 TUM fr2_desk 前300帧真实照片（约10.44秒）上实测：
    CUT3R   ATE RMSE = 8.254 厘米
    TTT3R   ATE RMSE = 2.848 厘米

  含义：漂移问题已被已有方法逐级解决，普通门控/滤波的创新压力极高。
  注意：FILT3R 数字带"共同精度适配"条件（原生代码 FP32 vs FP16 差异，修正后

■ 3.2 真实生成对照（最重要的负结果）
  三个条件各跑一次50步采样，共同输出四个目标（目标20-23）：
    A0（历史[19,18,13,12]）平均MSE = 0.131167
    A1（完整重复A0）        平均MSE = 0.131167  （与A0逐字节相同）
    B （历史[19,18,14,13]） 平均MSE = 0.125289
    B − A0 = −0.005878
  预先规定的预测"几何支持更高 → 误差更低"被否定（受益事件=false）。
  因为 A0/A1 精确重放，这个差异不是随机噪声。
  但：四目标全部保留；目标20是A更好，21-23是B更好；
      低MSE的图取景与物体位置反而与参考明显不同，且可见重影。
  成本：4439秒（约74分钟），本机CPU。

■ 3.3 末端强度反证（复用已存末态，0新完整链）
  强度 .5/.75/1 两族，全图四帧MSE：
    Gpaste    .5=0.065033  .75=0.053361  1=0.056060
    Gterminal .5=0.067558  .75=0.051168  1=0.052532
  Gterminal(.75)=0.051168 低于此前多步引导 0.052422。
  结论：拿到本例这个MSE不需要多步引导。
  边界：是看过旧结果后选的强度，不是独立确认；目标22反而更差；四目标仍有重影。

【八、⚠️ 发现的风险问题（需要处理）】
--------------------------------------------------------------------------------
■ 8.1 Git 仓库位置错误（重要）
  现象：项目目录内没有 .git；
        但在项目目录执行 git 命令时，生效的仓库根是 /Users/rocket，
        即你的整个用户主目录被当成了一个 Git 仓库（/Users/rocket/.git），
        而且已有约776个来自主目录之外的条目被 add 到暂存区。
  风险：1) 误提交主目录下的无关文件；
        2) 无法只对项目做版本控制；
        3) 这个仓库有0个提交（"does not have any commits yet"），
           但暂存区很乱，未来容易出错。
  建议：不要在该仓库直接 commit。要么在主目录级仓库里只 add 项目路径，
        要么在项目内单独 git init（推荐后者，配合正确的 .gitignore）。

■ 8.2 大文件不适合 Git
  项目69GB（data 33G / results 28G / work 6.2G）。
  work/ 内单个最大文件为155MB的 .npz，另有64MB级 .bin、98MB模型权重、
  以及一个嵌套的 .git（94MB）。
  建议：Git 只跟踪文本（src/tests/scripts/docs/configs/reports 及顶层md），
        排除 data/ results/ work/ 与 *.npz/*.bin/*.pth/*.pdf。
        大产物用哈希清单（项目已有SHA256回执习惯）或 rsync 备份。

■ 8.3 本机代理干扰远程连接
  本机 Clash(fake-IP) 把 superpod.ust.hk 解析成 198.18.0.165，
  导致 SSH 时通时断。当前 dsh 隧道已断。
  建议：使用 SSH 隧道/远程任务前确认代理未劫持该域名，或为该域名配置直连规则。
