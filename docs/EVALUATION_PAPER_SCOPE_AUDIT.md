# 机制评测研究的论文范围审查

应用Supervisor-Skills的benchmark-paper-template五支柱、构建过程和检查清单。tech-paper-template的前置类型判断将此候选路由到评价论文：当前拟议贡献是可识别的组件诊断，不是新的生成器或已证实更好的更新算法。本文是范围与缺项审查，尚不具备投稿完成状态。

## 五支柱完整性

| 支柱 | 当前证据 | 判断与下一项可执行工作 |
|---|---|---|
| 研究缺口 | VMem/AnchorWeave/Spatia/LSM-World的机制与模块差异已核；WorldScore/MEt3R/GeCo/SysCON3D/WorldExam各有不同评价目标 | 部分。定位“本项目需要区分的位置—关联—读出机制”明确；不能从未检出同设计推出前人遗漏 |
| 构建流程 | 真实TUM输入、固定裁剪/筛选、已冻结CUT3R预测，S7拟固定观测身份重放四臂 | 部分。S7仍待运行；单一环境不满足广泛覆盖，不能称完整benchmark |
| 评价框架 | 决策ID、支持并集、共同像素几何差、自身覆盖、事件轨迹；测量在选择封存后使用 | 有明确协议。需验证反事实重放不改关联、读出消融不夹带最后帧，不能用一个分数替代全部维度 |

| 配套改进方法 | 均值只是简单对照 | 不适用当前阶段。无需为了填模板添加新gate；若以后有机制依据，再另立方法协议 |

## 构建过程与质量条件

| 阶段 | 输入→操作→输出 | 检查与失败处理 |
|---|---|---|
| 来源 | 已授权公开TUM序列→固定三个时间块→72张RGB | 原文件哈希、配对与轨迹插值有效性；缺失不补造 |
| 预测 | 固定CUT3R与运行适配→S6历史可写/查询只读→504原数组 | 已核有限性、输入一致性和状态记录；保留适配及CUDA未验证范围 |
| 干预 | 相同接受观测→录制A0/A1事件→P0/P1重放 | 对角必须逐值复现S6；跨A变化含点数/分区等多因素，不伪装纯来源 |
| 决策 | 四地图→同K四种读出→参考ID及中间轨迹 | 原NMS顺序复现、ID唯一且只属于历史；选择及源文件封存 |
| 评价 | 封存结果+已独立核验测量→几何/支持→逐查询记录 | 复用评分源明确标注；与独立S6重建数组逐值比对、哈希固定 |
| 扩展 | 将来新增独立场景→预先写独立协议→外部检验 | 尚未进行；当前B0/B1/B2时间分块不是跨场景泛化 |

全部操作为程序执行，运行时点记录来自实际元数据。没有专家标注或人工评分，因此不编造标注者一致率、专家抽查比例或导师审核。模型预训练是否包含TUM未知；时间分块不能解决预训练污染。困难度按可见性/关联/选择边界分析，而不人为追求模板示例中的低正确率。

| 段落 | 当前可写的逻辑 |

§2任务与设计目标：明确三种机制、可干预单位与证据边界，用对照表承担论证。§3构建过程：真实输入到观测、事件、四地图、四读出的可复核步骤，使用已经实际导出的Draw.io图。§4配套方法当前省略，避免给均值起新名字。§5按三个RQ分别报告逐查询/分块/密度结果与共同覆盖，不按“最佳数字”组织。§6讨论何种解释成立、何种被反驳、未验证什么。§7将现有工作按作用环节比较，直接引用已核实主张；结论只回答实际完成的RQ。
