# S7：固定观测身份的关联重放实验协议

本协议在读取 S6 结果后制定，是事后提出、下一轮运行前冻结的机制实验；不是新的独立测试集，也不是 S6 的预注册假设。冻结时点与 SHA256 由研究账本和运行元数据记录。本轮不运行或调用 Claude 模型。

## 问题与三种可同时成立的解释

同一批历史照片，S6 的位置平均同时改变最终坐标、后续匹配、地图点数、来源集合，不能据两臂结果归因。

- H1 最终位置解释：在固定关联轨迹下，只更换最终位置规则就能改变可见投票、参考 ID 或支持。
- H2 关联轨迹解释：固定位置规则时，换关联轨迹仍改变选图。这里的轨迹效应包括点的分区、点数、出生属性和来源集合，不是纯来源标签效应。
- H3 选择规则解释：同一地图和候选排序下，抑制相似相机位置的 NMS 或候选限制会改变最终 ID 与支持；较高几何代理不自动转成较高选图代理。

三者可以共存，不预先宣布哪一个主导。所有不换图、下降和开发集结果都保存。有限样本中未出现某种变化，仅限制本设置的解释，不证明该机制普遍不存在。

## 输入、预算和冻结约束

沿用 S6 三块各24张真实 RGB 和已有 CUT3R 原数组；B0开发、B1/B2测试，每块前20历史、后4只读查询。共12张不同查询，主测试8张，单一环境；不新增模型推理。沿用 S6 纯预测归一化、裁剪内参、过滤、法线、半径与匹配规则。主 stride8、敏感性 stride12；仅使用检索宽度160（S6两档在全部条件下相同，明确不当作独立重复）。K=4、距离平移权重0.1、NMS初始阈值仍由前5预测姿态计算。

只写新的 `results/S7_event_replay/`。任何失败保留，修复后新目录重跑；不得覆盖S6。所有选择封存后才允许打开已有测量评分数组或depth/GT。S6与独立审查的支持/目标数组可以在评分阶段复用，必须先逐值对照二者并核源哈希，明确这是复用已独立验证的测量，不是再读PNG重建。

## 观测身份、事件与四臂

每个接受的历史观测身份为 `(frame,u,v)`，u/v为原224裁剪图整数像素；身份在两个关联轨迹中完全一致。不可用最终点编号冒充物理身份。可用相同surfel构造器、临时像素编码颜色来取回像素坐标，但必须验证真实RGB与编码RGB生成的几何逐值相同，编码图绝不能进入正式地图颜色或外部评分。

按原 `Memory.add` 分别记录首写路径 A0 与在线平均路径 A1 的每个观测匹配目标；未匹配观测按原输入次序分配出生点。每帧保持原冻结旧点树语义，新出生点不能被同帧后续观测匹配。

每条路径仅重放已记录的归属，不重新搜索邻居：

| 地图 | 关联路径 | 最终位置规则 |
|---|---|---|
| A0P0 | 首写在线路径 | 首次观测位置 |
| A0P1 | 首写在线路径 | 每个贡献帧一个质心，按原递推等帧平均 |
| A1P0 | 在线平均路径 | 首次观测位置 |
| A1P1 | 在线平均路径 | 每个贡献帧一个质心，按原递推等帧平均 |

同一路径内点数、出生法线/半径/颜色、贡献帧次数和来源集合必须严格相同，只有位置可变。逐帧平均不能改成对所有像素平均。跨路径无法一一配对地图点，不直接减去点编号，也不声称纯来源干预。

**运行前置核验：** A0P0与S6首写、A1P1与S6均值的全部数组、来源表和地图摘要必须严格相同；重新录制的原 `Memory` 与相应重放也必须相同。两个路径接受的观测ID/原几何顺序必须相同。任何不一致立即停止，不评分。

地图摘要特指S6的 `memory_digest`：包含位置、法线、半径、颜色、贡献帧计数和来源表，不含不可重复的运行耗时或建图计时记录。匹配记录的逻辑字段另行保存。

新录制build_trace排除elapsed_seconds后与S6逐字段比较；S6没有保存逐观测事件，因此只能称本轮新记录的事件，不能称逐值重现旧事件。运行版本保存Python、NumPy、SciPy、Torch、Pillow及Torch默认dtype；排序显式float32并保留本机库默认并列语义。实际展开候选的并列数从新decision_trace计算，旧official_trace中的辅助candidate_pose_ties不用于机制结论。

## 每地图的四种读出

1. `official`：原VMem完整选择器，包含渲染、投票、分配候选和NMS。每地图每查询保存原始可见点索引、深度、cos值、票权和候选计数。
2. `candidate_no_nms`：与原选择器完全相同的展开候选、多重计数、float32距离排序和并列次序，取排序后前4个唯一历史ID。只移除NMS，不强制插入最后一帧。
3. `all20_nms`：候选为历史0..19各一次，沿用相同距离精度、排序和原NMS过程、阈值及放宽规则。
4. `all20_no_nms`：同上全20候选，取前4唯一ID，作为匹配预算的近姿态对照。

不能直接把官方 `use_non_maximum_suppression` 设False当纯消融，因为该分支会强制加入最后一张历史，并改阈值。新辅助选择器属于项目诊断实现；带NMS的候选路径必须对每张地图每次查询逐项复现官方最终顺序，验证失败立即停止。保留展开候选顺序，不为方便排序先去重。若任一路径不能返回4个不同的0..19ID，停止并报告设置局限，不偷偷补图。保存排序、每轮拒绝原因、阈值放宽和回填记录。

距离查询先经过官方单姿态 `average_camera_pose` 的四元数规范化，不能用未规范化输入悄悄替代。原投票器按可见像素累加，并包含每个来源首项双加的现有语义，本轮全部保留。

## 评分、主要比较与报告

全部6案例×4地图×4查询的选择文件与原渲染数据先SHA封存，再读S6评分数组。每组4种读出，共384个选图条件，但仅12个不同查询。

主要评分仍是同一有效目标mask上的所选4张历史实测支持并集，50mm阈值与S6相同。报告每查询ID/支持和主8查询均值，不用像素、两种密度或多个方法扩大样本量，不做总体显著性检验。

- 位置干预：分别在A0与A1内比较P1−P0。
- 关联轨迹干预：分别在P0与P1内比较A1−A0，明确多种属性联动。
- 交互描述：支持的 `(A1P1−A1P0)−(A0P1−A0P0)`，不把描述分解当自然界因果效应或唯一归因。集合ID变化另报，不能用支持相同推断选图相同。
- 选择规则干预：同地图对比official与candidate_no_nms；在同NMS规则下对比候选限制与all20。all20读出不依赖地图，应跨四地图严格一致。
- 伴随几何：用原S6尺度/GT投影约定重算四地图在每查询的112栅格zbuffer；四臂共同有效像素及各自覆盖均报告。也保留对角两臂共同mask以验证复现S6。共同像素为空则记为空，不删除查询或换阈值。

不构造GT选帧的新方法，不做事后挑查询、权重调参或新增干扰幅度。不将支持提高称为视频改善。主结论只回答该批数据与固定组件下，哪些链路足以改变选择，哪些链路未显示变化。

## 独立核验与下一步条件

先用人工小例检验位置平均对一个贡献帧只计一次质心（不是修改VMem可见像素投票）、同帧新点不能自匹配、固定路径重放无邻居搜索、无NMS不强制末帧。人工例仅用于程序正确性，不计真实研究样本。实际完成后请独立实现从观测ID/事件复算地图与来源，并从已核实测量数组复算全部支持和差值；审查工具不得导入本轮重放/辅助选择实现来证明其自身正确。

若对角重现失败，先修实现；若机制作用仅见单个查询或单一场景，完整展示局限，后续另立独立场景协议。机制清楚也只构成候选诊断贡献，尚需最近工作排重与跨场景验证；不会宣称一种普遍更好的视频生成方法。
