# S5冻结协议：三段连续RGB的学习几何诊断

S4两图适配运行与评分已经完成，其输出可用于判断本机可行性。S5是在看到S4结果后决定的新阶段，本协议及输入清单在任何S5推理之前保存并写入时间账。S0–S4不改。

## 问题与固定输入

问题：在更长的连续画面中，只用开头一张的实测深度校准比例，后续预测深度和相机移动保持到什么程度？这仍是模型特征诊断，不是假定提出了新方法。

完全复用S3 selection_manifest.json已有3个非重叠等时长段，各24张按时间排序RGB，共72张；不是3个环境。B0沿用开发标签，B1/B2沿用测试标签。清单逐图保存RGB、关联depth的相对路径、时间与SHA256，不按S4好坏挑选图片。

官方CUT3R固定提交8bc15dc92a6d7fd92920b4ec81540d3dec7d3ecf，224 linear中间权重SHA256 7a7d83e47f822e040980c8f5aff4c15aa94366d469d3ceae51fa30cc2f62327d。使用S4已独立审查的有符号RoPE和阻塞输入搬运，CPU FP32、8线程、seed0。各块新进程一次inference(24 views)，因此每块从该块首帧初始化。所有view的reset=False；不使用会在预测后撤销该帧更新的reset=True，也不使用仅服务ray查询的inference_step。

## 状态和评分分工

模型只收到RGB、模式掩码和初始化占位张量，不接收实测深度/参考位姿。官方decoder在块内按时间递归，后帧能够看到前面的RGB历史。前20张为历史段，后4张是评分重点；后4张依次进入RGB估计过程，后面的评分图可能已看到前面评分图的RGB，但从未看到其depth。这是因果RGB序列估计，不是将查询排除在模型之外的视频外推任务。若后续研究历史记忆检索，需要另设只含前20张的记忆，不能把这里状态当作无查询泄漏的检索地图。

每块单独使用第0帧self_view正Z和TUM有效depth的median(measured_Z/predicted_Z)得到一个尺度。首图本身只作校准描述；该比例冻结用于本块其余23帧，不做逐帧或轨迹拟合。共用了3张校准深度，不是全程纯RGB米制估计。

主结果：B1和B2的frame20–23，共8个实际图像，逐帧等权平均MAE、中位绝对差、p90、带符号平均差、30mm内比例、AbsRel；每项仍完整列出各帧、各块。B0后4帧单列。其余69个非首图结果作为完整描述（包括主8图，不新增独立样本）。不给空间相关像素、同场景帧当独立重复，不作显著性检验和置信区间。

深度接口完全沿用S4：640×480到299×224再crop[37,0,261,224]；RGB LANCZOS，原始depth及有效mask NEAREST。原始depth 5×5全有效且与中心差≤50mm为有效，外边2像素无效；0或非有限depth剔除。不按预测置信度筛选、不剔除剩余大残差。报告预定target有效像素和positive finite预测覆盖。

位姿：参考GT插值到各RGB时间、最大间隔0.1秒、不外推。每帧比较inv(P0)Pt与inv(G0)Gt，平移乘首图depth尺度，报告旋转角差、平移向量差和参考移动幅度。矩阵正交与有限性先验证。head是LinearPts3dPose，点图和位姿独立预测；共享尺度是诊断假设，other点图与pose×self差只描述。没有ICP/Umeyama/全轨迹对齐。

## 运行、保留与复算

固定输入见data/cut3r/S5_inputs.json；三块独立保存raw预测、元数据、源码快照、全部输入张量搬运检查及耗时/RSS。任一块失败保留并记账，仅修兼容/资源问题；任何改变都另记修正，不删帧凑成功。16GiB进程RSS为启动前软资源预算估计，实测超出时停止并保留；不得为了速度改精度或偷偷截短。

记录每块尺度、逐帧深度/位姿指标、总表、所有72张缩略图/深度诊断以及随时间曲线。计时为单次无预热描述，不作硬件benchmark。完整结果由另一实现直接重算NPZ。该阶段不生成新视频，不评VMem完整清理或检索，不宣称通用精度/新颖性。
