# S4 两图结果独立数值与解释审查

结论：**在本次有界核验范围内通过，未发现需阻止报告使用的数值、裁剪、掩码或设备尺度错误。** 独立程序的 185 项检查全部通过，另两张 RGB 的官方预处理再对照均逐值相同。这是对保存证据的复核，不是新增场景、模型复现实验或课程完成证明。

核验实际执行时间：2026-09-05 23:16:53–23:16:55（Asia/Shanghai；数值核验）；官方 RGB 对照于 23:17:15 完成。精确 UTC 时间及源码哈希见下列证据。

## 1. 独立性与输入

本审查读取冻结的 [S4 协议](S4_TWO_FRAME_PROTOCOL.md)、[运行前点图语义修正](S4_PRE_RUN_AMENDMENT.md)、[运行兼容修正](S4_RUNTIME_AMENDMENT.md)，以成功的 `CUT3R_cpu_2frames_signedrope_sync` 与 `CUT3R_mps_2frames_signedrope_sync` 的原始 `predictions.npz` 为预测输入，以原始 TUM PNG 和 `groundtruth.txt` 为测量输入。

独立实现使用 NumPy/Pillow，从整数深度重建掩码与裁剪，用手写四元数插值重建 RGB 时刻的位姿，并从数组重算尺度、残差、相对位姿及设备差异。**没有导入或调用 `learned_pair_metrics.py`、`evaluate_cut3r_pair.py` 或项目的 TUM 位姿/关联函数。** 官方 `load_images` 仅在额外的图像预处理检查中调用，没有加载模型或运行评测函数。

核查了固定输入图片及其哈希、两设备预测文件哈希、完整检查点的 2,994,205,002 字节与 SHA-256、运行元数据中的固定提交、FP32、完整权重键匹配和真实 head 类。评测源码归档内与结果清单对应的哈希也通过。两设备是带 signed-RoPE 与阻塞输入搬运的适配运行，不能表述为官方代码原样执行；本审查未在 CUDA 硬件上验证兼容器。

## 2. 裁剪、掩码和尺度

两张 640×480 RGB 均按固定官方 224 分支缩至 **299×224**，裁剪框为 **[37, 0, 261, 224]**。独立重建的 RGB 裁剪再经归一化，与重新调用固定官方 loader 的两组输出最大差均为 **0**。NPZ 中的 `frameN_rgb` 是预测 RGB head 输出，并非保存的输入图，因此未错误地要求它与输入相等。

有效测量掩码由原图 5×5 邻域重建：所有深度必须正值，邻点与中心的绝对差不得超过 250 个原始整数单位，即 50 mm；外圈两像素无效。独立实现直接使用整数比较，避免 50 mm 阈值附近的浮点歧义。深度和掩码采用最近邻缩放及同一裁剪。**两张重建掩码与保存掩码均逐像素相同。**

| 检查项 | 第一图，校准 | 第二图，留出 |
|---|---:|---:|
| 原图通过邻域规则的像素数 | 197,266 | 207,222 |
| 裁剪后有效测量像素数 | 35,699 | 37,325 |
| 占整个 224×224 裁剪的比例 | 71.148% | 74.388% |
| RGB 晚于关联深度的时间 | 14.897 ms | 11.388 ms |
| RGB 时刻位姿插值跨度 | 10.000 ms | 10.100 ms |

原始整数深度除以 5000 后与保存浮点深度的最大差分别为约 `1.18e-7 m`、`5.93e-8 m`，来自一次 float32 深度存储舍入；按该存储精度重建后与保存深度**逐值相同**。这不是单位或插值错误。

仅用 **CPU 第一图**的 35,699 个有效像素重新计算 `median(z_measured / z_predicted)`，精确重现尺度 **1.1583864704346218**。独立将此同一尺度乘到 CPU/MPS 两图的原始 self-view Z，得到的四张数组都与保存的 scaled depth 逐值相同。没有对 MPS 独立拟合尺度，也没有用第二图或 GT 位姿重新对齐。

以下为同一张留出图、同一测量掩码、同一 CPU 首图尺度下的结果。CPU/MPS 在有效测量掩码内的有限正向预测覆盖均为 100%；它表示覆盖这 37,325 个有效测量像素，**不是整个裁剪画面的 100% 有效测量覆盖**。

| MAE | 32.323640 mm | 32.320834 mm |
| 绝对差中位数 | 24.368071 mm | 24.362811 mm |
| 绝对差 p90 | 67.788246 mm | 67.789613 mm |

保存汇总的以上指标全部复现。第一图的校准后与未缩放描述分数、第二图的未缩放单位假设分数也全部复现；未丢弃大残差，未按置信度选择像素。第一图 CPU 校准后 MAE 仍为 **81.474130 mm**，不能从尺度拟合推断全部几何误差已消除。未缩放输出对测量的差异只能称单位假设下对照，不能据此宣称原模型米制误差已被证实。

## 4. 位姿与 head 语义

独立读取原始 mocap 轨迹，使用 **RGB 时间**而非深度时间进行线性平移及四元数球面插值，不外推；重建的两张 c2w 与保存值一致。再计算 `inv(P0) @ P1` 和 `inv(G0) @ G1`，仅把预测相对平移乘 CPU 首图尺度。

| 相对位姿指标 | CPU | MPS |
|---|---:|---:|
| 旋转角误差 | 0.929059° | 0.929211° |
| 平移向量差 | 19.835704 mm | 19.829506 mm |
| GT 相对位移 | 371.938476 mm | 同一 GT |
| GT 相对转角 | 10.325203° | 同一 GT |

独立四元数解码与保存的 `camera_c2w` 在 float32 误差范围内一致；旋转正交性、行列式、有限值和 self-view 正向 Z 检查通过。

固定 factory 和实际运行元数据均选择 **`LinearPts3dPose`**，不是 `LinearPts3dPoseDirect`。前者分别预测 self 点图、位姿和 cross-projection 的 other 点图。因此，`pose × self` 与 `other` 的差异只能作为描述性自洽诊断：CPU 第一/第二图的最大逐坐标差分别为 **0.139652703 / 0.018527423 个模型单位**，不能因为不相等判定实现失败。平移误差还依赖**点图尺度可用于位姿平移**这一假设，当前数据没有独立证明该假设可推广。

## 5. CPU/MPS 数值一致性

直接对两份 NPZ 的全部 **14 个同名数组**逐元素检查有限值、形状和预定的 CPU 参考容差 `abs(MPS−CPU) ≤ 1e-3 + 1e-3×abs(CPU)`，全部通过。最大原数组绝对差为 **0.0006508827209472656**，出现在第二图 `conf_self`；这是置信度数值的差，不能当作毫米几何误差。每个数组的最大/平均差和形状保存在审查 JSON 中。

这支持“本机这对输入在两设备上数值接近”，不支持“所有输入与所有设备完全相同”。单次未预热 CPU/MPS 前向时长也不能作为吞吐或设备优劣 benchmark。

## 6. 可采用的解释与必须保留的边界

可报告：独立 CUT3R 224 中间检查点经明确的本机兼容适配成功处理固定两张真实 RGB；在 CPU 首图深度校准一个尺度后，第二图得到上述测量残差；两设备原输出在冻结容差下接近。

必须保留：**一张校准图、一张留出图、一个环境、一次相对位姿转换**。37,325 个像素具有空间相关性，不能当作 37,325 个独立样本或多场景验证。Kinect 测量、轨迹、标定和非零 RGB/深度时间差均有误差；测量一致性不是无噪表面真值精度。第二图的 RGB 照常进入推理，“留出”指其深度不参与拟合。S4 的密集自视深度与 S3 的稀疏投影、掩码和统计对象不同，**不能把 S4 较小的 MAE 写成相对 S3 的方法提升**。本轮没有验证长序列、原 VMem 完整清理、检索收益或生成视频质量。

本次没有发现需修正的主数值。上述是结论边界，不能因核验通过而省略。此审查不替代模型源码全量审计、人类课程审核或后续外部环境复现。
