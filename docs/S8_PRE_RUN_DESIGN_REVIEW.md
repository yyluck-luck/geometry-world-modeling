## 采样代码与确定性规则

`gt_time_intervals()`只将每行第一个token转为时间戳；其余七列只检查行结构，未转成位置/四元数。它对GT时间排序并拒绝非有限或重复值，按严格`gap > 0.100`切成闭区间。`interval_at()`能排除区间外和断点内部，支持精确端点。

运行入口使用原`read_timestamp_file`读取RGB/depth列表，原`associate_rgb_depth(..., max_difference=.020)`先做完整全局贪心一对一关联。该算法不是保证最大匹配数的全局最优指派，但这是明确复用的既定规则。`plan_windows()`随后要求每个配对的RGB/depth时间落在同一个GT区间。它接收原函数已经按RGB时间排序的输出，按GT区间变化或相邻合格RGB差大于100ms分段。

选窗实现在每段逐个RGB时刻尝试名义起点，目标为`start + 8.840*i/23`。二分搜索整个连续段，比较左右候选的绝对时间差，再以较早RGB破并列；误差超过50ms或出现重复即拒绝。接受窗口后只考虑起点严格晚于名义终点加100ms的候选。剩余时长不足时退出本段等价于拒绝本段所有更晚起点，不会跳过后续可行窗口。最终选择接受窗口列表的首个、下中位索引和最后一个，数量不足3则失败，不换序列。

末图最多越过名义终点50ms，而下一窗口实际首图就是其名义起点，且起点严格晚于前一名义终点100ms。因此当前规则保证实际RGB输入不重叠。完整一对一配对及最终清单验证又防止重复depth输入。清单验证只读文件字节核SHA，未解码图片；还核对路径、inode、SHA、时间戳唯一性，三块标签固定为test，帧0…23按RGB时间严格递增。

清单保存全部已接受候选窗口、选择索引、目标/实际时间、snap误差、GT区间、名义/实际时长和RGB间隔。`rgb_minus_depth_seconds`逐帧偏移已加入。两级冻结顺序合理：先冻结设计，再用纯时间规则生成清单，执行源码与清单固定后才做RGB QA及模型运行；不能把清单产生后的判断倒写成数据前假设。

## Cadence与双时间约束的实际含义

本轮只读旧S5输入清单核得旧三块RGB跨度分别为8.836127、8.835887、8.835962秒；平均帧间隔约0.384179、0.384169、0.384172秒。新名义间隔`8.840/23 = 0.384347826`秒，采用近似匹配的时间跨度有依据。

这不是实际间隔分布逐项相同。50ms snap允许实际相邻间隔偏离名义值；新清单应保留实际分布，按协议报告而不据此重新选窗。同样时长也不保证相同角速度、平移、纹理、遮挡或历史参考重叠。新场地、实体Kinect及运动共同变化，跨场景数值差不能单独归因于地点。

双时间处于同一GT连续区间可防止把关联depth放到无参考轨迹的大缺口另一侧；它不能消除RGB与depth的拍摄偏移。depth是注册到RGB坐标的观测，仍按RGB时刻GT评价、不做异步补偿，这与旧评估约定保持一致，但依然是带测量误差的代理。时间戳与文件字节已被读取，因此正确说法是“不解析/使用GT位姿数值或解码深度参与选图”，不能说选图前从未接触GT文件。

## 可反驳性与避免伪重复

H1/H2按每个固定干预分别统计集合改变、仅顺序改变、支持升降及零变化。主12查询全部没有集合和顺序变化时，预定表述为该场景设置未重复相应选择变化；不能改找另一读出替代原对比。这个零结果限制局部观察，不证明机制普遍不存在。

S7的具体符号模式单独检验主stride8的12查询平均P效应是否仍为A0负、A1正，并另列各块符号。任意非零、单个查询变化或反号，都不能自动算成该符号模式重复。

稀疏抵消只检查预定`A0P0→A1P0→A1P1`路径：起止有序ID相同、中间有序ID不同，同时起止支持相同而中间支持不同。所有不满足项及满足数一起报告；不事后选择另一分解路径。起止支持相同必然使这条路径两段差值相加为零，真正需要核实的是中间干预确实改变ID和支持，而不是将代数相消当作两个独立物理机制已被证明。

H3正确分开原候选的NMS开/关与全20候选的NMS开/关。全20读出与地图无关，四图重复出现不能增加样本量。三块全部作为本次开发之外的测试；只有一个新场景、12个不同查询，时间窗口不重叠也不等于相互独立。384读出是条件数，旧fr1的8个测试查询另报，不拼成跨场景独立样本做显著性结论。
