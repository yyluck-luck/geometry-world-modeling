# S16真实保存数据诊断：来源更新会怎样互相影响

**实际计算及不同实现复核均PASS，但没有得到可宣称的新算法或新深度竞争机制。** 在all_new规则下，四个来源各自更新都提高聚合δ1；当其余来源已经更新后，再更新每个来源却都降低聚合δ1。这个上下文效应确实存在于当前保存数据中，但交互贡献只落在来源覆盖变化或来源像素路由变化位置。固定候选身份位置的贡献为零；事后检查进一步发现该区域真正受改动且有多来源支持的位置很少，不能把大量未改/全空位置当成广泛反证。

给新手的一句话：单独换一块旧几何，看起来有帮助；同时换很多块，投到新视角后的空洞、像素落点和哪个来源在投影中胜出都会变。我们把这种组合效应真实算出来了，但它目前符合普通投影和z-buffer的已知行为，还不能叫创新成果。

## 全部规则的主结果

所有差值单位均为**δ1百分点（pp）**。δ1在目标全部有限正GT上计算，缺失算失败，阈值严格小于1.25；每目标的分母为36,827、40,836、44,328、45,409，合计167,400次目标像素访问。主结果是四帧等权平均，不是把167,400个像素当独立实验，也不是用合并像素比例替换四帧均值。

`joint gain=F(全改)-F(全旧)`；`sum single`为四次单来源增益之和；`I=joint gain-sum single`。后三列是同一个I按三类位置精确分摊，仍使用全目标GT分母。

## 三类贡献和固定区域的事后支持审查

冻结分类只看该policy自己的四来源old/new图层，不看GT数值：有效性改变归coverage；有效性全部不变但某来源层的获胜source-pixel身份变化归routing；有效性和每来源赢家身份都不变归fixed。三类是互斥的空间记账，**不是三个独立物理根因**。coverage/routing类别也可同时涉及深度顺序变化。

所有policy的fixed贡献都为0。为防止误解，这里另做明确标为**事后**的支持审查，既不修改冻结协议，也不改原S16输出。只读取root授权的S16图层/maps及已评分GT NPZ；以模型单位层深度的精确不等定义“实际z改变”，没有用结果调阈值。下面的数是四目标像素访问总数，不是独立场景数。

root随后补了更严格的事后必要条件：高阶交互至少需要同一目标像素上**两个来源的层z实际改变**；只有两个来源有效不够，否则该像素至多依赖一个开关，j必为0。对应表中“≥2来源实际改z”一列，pool只有48个、split只有17个，而不是前一列的1,521和1,456个。root的独立补查实际UTC为2026-09-06T10:48:23.962727+00:00—2026-09-06T10:48:24.025622+00:00，全部六policy在该更窄支持上j非零数仍为0；逐目标计数见 `work/S16_root_support_audit/two_changed_source_support.json`。这进一步限制了反证强度：本段几乎没有覆盖pool/split的固定身份高阶交互机会，不能把零结果写成广泛否定。

即使满足至少两个来源改动，也只满足必要条件；最小深度赢家和δ1命中状态仍可能不变。该筛查用来说明证据支持程度，不替换原协议的固定分母或重新挑选主结论。

这份审查既阻止把全空区域当反证，也没有救回新颖性：在实际受改动的固定域里仍未观察到该指标的非加性交互。正确结论是“本段和此指标未支持固定候选身份上的交互主张”，不是“证明物理场景中没有来源竞争”。逐目标、全部子域、j正/负和整数和详见 `work/S16_reporting/actual_support_and_figure/fixed_support_audit.json` 及CSV。

## 按预定标准收束

软件门全部通过，all_new等规则确有聚合边际翻转；因此此次诊断确实测到了组合上下文差异。但原协议要求的fixed域证据未出现，而且更严格支持很窄，主体贡献位于已知的覆盖与像素路由变化区域，**停止把本次结果定位为新的深度竞争或新的几何记忆更新机制**。这是当前证据不足以支持该主张，不是证明此类机制在其他条件下一定不存在；也不能把一次成功算数当作创新成立。
