# 第三组真实运行失败：原因、验证和下一步

第三组确实在本机运行了模型，完成第一批四张目标画面后退出；第二批尚未开始采样。现在已经查到一个具体原因，并用保存数据重现：场景几何的数值尺度与程序固定的可见距离不相容，导致历史检索为空。**这属于基线故障定位，尚不是新方法，也不是完整视频已修好。**

## 用一个例子理解

同一个房间，长度可以用米或毫米表示。若房间点、相机位置和小表面的半径都按同一个比例换算，点在照片上的投影位置应当相同。但程序把“0.1到1000”固定当作可见距离，没有先明确场景重建使用的长度单位。

本次保存的515个点全部在约0.000002到0.000007之间，程序将它们全部当成“太近”。随后历史画面列表为空，原代码仍试图取第一项，发生越界。这里的数字是模型重建坐标值，不能解读为真实房间的米制尺寸。

把位置、相机平移和半径一起换算，使正深度中位数等于1；旋转、焦距、法线、来源、渲染代码和原距离门槛保持原样。倍率由这条固定规则得到，没有搜索倍率或挑最佳结果。

原单位的depth、index、cos三个输出数组与失败档案逐项完全一致；归一化条件能产生非空候选。这里统计的是数值几何栅格，**不是生成照片的质量指标**。不同作者已独立复核两张结果包、515点投影及来源权重；权重最大差约1.82×10⁻¹⁴。没有调用第二批生成、没有进行最终NMS上下文选择或评分，也没有更改生产管线。

这证明这个保存输入的检索边界依赖绝对长度数值。近裁面分析已给出原空集的一条充分原因；两条件同时保留了深度权重里的固定常数，因此不能把所有权重变化都唯一归于近裁面，更不能声称已解决全部尺度问题。

## 极小尺度从哪里来

五份几何输出深度在构造surfel之前就已经很小，全局范围约1.58662×10⁻⁶–7.58070×10⁻⁶。这排除了“只在后面的surfel筛选才变小”的解释。五个相机中心相同，首次几何调用也没有固定深度；源码里的相机相似对齐可能选到极小尺度。

但现有档案没有保存原始CUT3R预测、MST初始化尺度及逐步深度，尚不能唯一归因。旧S27已经发现深度getter梯度断链，所以目标函数下降不能用来宣称“400步优化压塌了深度”。S29/S34的既有尺度分析与修复也不重复计作本轮创新。

原仓库[issue 13](https://github.com/runjiali-rl/vmem/issues/13)已有同一越界报告；[评论](https://github.com/runjiali-rl/vmem/issues/13#issuecomment-3584880884)描述过几何过远而被far门槛排除。本例在相反的near端，不能照搬评论的far参数修改。已保存公共API原文与访问回执，未联系作者。

## 下一步及创新边界

先明确强基线的尺度处理：点云、相机平移、深度、半径和历史缓存更新要保持一致，空检索必须显式报告。恢复方案须另标基线修复变体，不能把本次部分输出改写成原协议成功；已消耗V9目录不重跑、不覆盖。小值阈值、普通中位数归一化和最近帧回退都不是可独立宣称的新算法贡献。

若要进一步定位原始预测与初始化的区别，需要一项明确记录中间量的有限重放；这项尚未启动。可以复用已生成图像的几何输入，但仍须如实记录几何模型调用，不能冒充纯保存数值分析。当前没有运行V10或任何恢复后的完整C2。

创新探索继续参考Supervisor手册与正式顶会论文。S59已阅读Self Forcing、FramePack指定正式章节，并实际使用Gemini作反方分析；一个精确数学反例排除了“等能量噪声对照即可证明曝光偏差”的跳步。真正的新方法仍须从强基线留下的、具有独立参照的长期生成失败中提出和验证。当前 **NO_METHOD_SELECTED；new_method_validated=false；尚未达到PhD/CCF A目标。**
