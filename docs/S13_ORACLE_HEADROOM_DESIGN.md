# S13设计：四张参考图的事后上限诊断

## 要回答的窄问题

S12已经发现：同样先留14张候选、再经相同NMS选四张时，来源14相对姿态14的测量支持在S7测试为−2.338961个百分点、在S8测试为+4.382920个百分点。下一步不立刻发明新规则，而是先问：在**知道测量支持答案以后**，现有四张选择还剩多少理论可提升空间？

这是一项oracle（知道答案后的最优）诊断。它不能部署，也不测视频质量或新颖性；任何结果均不得写成可运行检索器、泛化证据，或普通coverage greedy的新证据。

## 预定样本、主设置和三个候选池

- 使用S12已经固定且已见的24个查询：S7开发4、S7测试8、S8测试12，场景和开发/测试划分始终分开。
- 主设置固定为A0P0、stride8。不会因结果漂亮改用其他地图或stride；也不将24个相关时序查询写成24个独立场景。
- 对每个查询枚举恰好4张不同历史图的组合，分母沿用已有valid测量点，支持定义沿用50mm一致的support并集。
- 池G：该主设置中保存的来源14候选；池P：S12保存的姿态最近14候选；池20：全部20张历史图。组合数分别为C(14,4)=1001、C(14,4)=1001、C(20,4)=4845；全程预定164328个静态组合评分。

池G/P分别说明各自当前四图选择距离“同候选池理论最佳四图”的余量；池20仅是更宽候选空间的事后上界，不能与14候选结果说成相同预算。三池都只是分析对象，不新增筛选算法。

## 计算、封存与判定

1. 先只读并SHA绑定S12 records、summary、run metadata、24份stride8 scoring NPZ，以及S12独立审计和本设计/前审文件。确认S12状态completed、24个ID域完整、每个G/P候选池均14个不同ID、两个现有四图均在对应池内；核24份stride12的support/valid身份与stride8相同，但不对stride12另做oracle。
2. 新入口在未读取support/valid前先从records提取并封存24个G/P候选池、两个既有四图和完整组合清单的哈希；组合按ID升序生成。这个封存只保证候选域不因评分结果变化，**不**把oracle伪装成未知GT选择。
3. 然后读取每query一份保存的support/valid。对每个预定组合F计算 `sum(any(support[F], axis=0) & valid) / sum(valid)`；不重算投影、深度、GT轨迹、renderer、NMS、CUT3R或VMem。
4. 每池保留最大分数、最大整数分子、达到最大值的组合数和字典序最小的代表组合。字典序只用于可复现记录，不能被称为有语义的可部署tie-break。
5. 同时对S12已保存的来源14和姿态14已选四图用同一数组重算并要求与S12主设置精确一致；否则停止。输出逐查询与三分层均值：当前选择、对应14池oracle、绝对余量（oracle减当前，百分点），以及20池oracle相对两个当前选择的余量。只作描述，不做p值、置信区间或跨场景总平均。

## 必须通过的退出条件

- 输入/候选/组合域、数组shape/dtype、valid非空、四图ID合法性及S12主设置现有分数全部精确核对；任一失败即保留失败目录，不删样本、不改候选池或容差。
- 使用全24查询和全部三分层；不按oracle余量挑案例。相同最优分数的多组合数量必须完整报告。
- 运行只写新`results/S13_oracle_headroom`目录；一次执行预算为CPU 600秒、16GiB软观察预算，非性能测量。
- 最终需要独立只读审计：重开保存的support/valid，独立枚举组合并核现有分数、最优分数、代表组合、并列数和分层汇总；不重新运行模型或投影。

## 允许与禁止的解释

若当前规则离oracle很近，只能说明在本指标/已见查询/该候选域中可挖的静态并集支持余量小；这不证明当前选择对视频最优。若余量大，也只说明有值得解释的失败模式，不能直接把GT覆盖最大化规则部署，不能称其新颖或优于COVRAG、I3DM等已有方法。

在任何候选机制设计前，必须将oracle逐查询的失败结构与S12两场景方向相反的现象联系起来，提出与现有coverage方法可区分、可被推翻的机制，再做新颖性审查和新的冻结实验。
