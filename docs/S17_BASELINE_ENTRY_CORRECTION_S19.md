# S19对原视频最小入口的限定更正

这是一份源码审查勘误，未运行生成器；不改旧S17/S18冻结文件。证据见 [S19_FEEDBACK_PATH_AUDIT](S19_FEEDBACK_PATH_AUDIT.md)。

S17可行性曾按第一批7个实际目标、下一批4个估算最多1+7+4=12个保留帧。这个数量适用于不padding的长trajectory入口；不能同时默认其NMS初始化与作者4目标导航入口相同。

作者app/Navigator默认请求4目标。首轮确实仍计算7个目标槽（加1个context），其中3个padding不保存；实际历史从1变5。下一次原默认NMS于是满足len==5。若选择同样的4目标请求做第二批，累计可保留1+4+4=9帧，但模型计算依旧按原T8与50步，不能把它叫4帧计算成本或已经成功的9帧视频。

下一份真实生成协议应明确采用已核的作者4目标导航保存语义，并固定padding/保留帧ID；不能先按长路径首批真实7帧令history变8、再默认第5帧初始化已经发生。如果另测长trajectory与NMS组合，应单独保存条件性故障/修复合同。当前只观察到源码风险，未出现实测AttributeError；尚无理由修改原代码来“修复所有路径”。

生成前仍需要原主权重合法访问、指定VAE和CLIP、本机完整算子/资源检查。S18成功只补地图候选组件，不能替代这些缺项，也不能推算视频耗时。S19的祖先依赖问题还需要每次真实生成的context/cache/RNG/padding/output事件记录；当前未采集。不得用占位latent或CUT3R旧数组代替真实生成闭环。
