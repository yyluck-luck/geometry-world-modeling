## 最小输入合同

只用30份JSON即可准备基础特征：

- S7/S8各3块的 `results/S7_event_replay/block{0,1,2}_stride8/prediction_only_selection.json` 与 `results/S8_event_replay_v2/block{0,1,2}_stride8/prediction_only_selection.json`。
- `results/S12_matched_budget/selections/` 中24份 `S7或S8_block{0,1,2}_query{20,21,22,23}.json`。

以上名称中的花括号只是文件域说明，不是新文件名。实际白名单必须由清单中的确切路径和SHA构造，不能全目录glob把后来加入的评分文件混进来。禁止提取器读取S12 records/summary、S13 oracle、scoring NPZ、GT深度/轨迹、原图或场景标签作为数值特征。

## 生成前可用性的实质限制

模型metadata显示：前20历史更新状态，后4query只读状态，但所有query仍输入真实RGB。只读记忆状态不等于没看查询图。这份合同最多支持“给定当前预测查询相机”的组件诊断；完整生成开始前若只有目标轨迹，必须另做从轨迹/历史取得相机的接口验证。不能凭不读GT就称已经可在完整VMem生成前部署。

两方案共享20历史与预测查询相机；主设置A0P0/stride8不变。`stage/block/query/split`仅作来源和分组元数据，任何学习器不准用它们记忆场景答案。将来新校准/测试按物理场景隔离，当前24查询不能恢复为未见数据。
