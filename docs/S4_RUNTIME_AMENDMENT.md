# S4实际运行的兼容修正

这是运行遇到错误后的兼容修正，不是初始冻结协议的一部分。原失败记录和原协议保留。两张输入、第一帧尺度校准、第二帧留出评分、所有指标及设备数值容差不变。此次使用官方源码加外部运行适配，不能称原样运行。

1. 首次CPU加载全部参数成功，前向因pose token位置为(-1,-1)、纯PyTorch RoPE查表不支持负索引而失败。外部signed-RoPE适配按固定官方CUDA源码中的有符号角度计算；对非负位置逐值等于原fallback，CPU/MPS合成检查通过。没有CUDA硬件验证。适配器SHA256为6939dcead1b87e920eafce9aae47c1cc9a46b7a651ef816b3f521c779582152e；独立审查见CUT3R_ROPE_ADAPTER_AUDIT.md。
2. 加入RoPE适配后CPU两图成功。首次MPS在输入搬运后出现掩码异常。固定本机Torch 2.7条件下，独立小测试异步搬运且替换CPU来源有50/50轮值改变，blocking预搬运50轮无改变；这是本机观察，不概括为所有MPS设备的问题。
3. 后续CPU与MPS均先完成阻塞输入搬运，核对全部14个实际张量字段前后值一致，再进入官方推理。两设备使用同一runner、适配器、权重和图片；元数据保存运行源码快照与适配器SHA。原CPU成功输出与增加阻塞搬运后的CPU输出另行逐数组比较。

S4评测以CUT3R_cpu_2frames_signedrope_sync为主输入。若MPS成功产生有限输出，使用CUT3R_mps_2frames_signedrope_sync并独立重算所有原数组的atol=rtol=1e-3；不因比较失败而调整容差。各步真实起止时间见模型元数据和研究日志。
