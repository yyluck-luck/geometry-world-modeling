# S14D-I：本机跑通不读取目标照片的几何查询

**这次实际运行了预训练CUT3R：读取20张历史实拍照片，只给定目标相机射线，就完成5次几何查询。目标照片和GT读取为0。** 独立数值核验通过。这里的4个目标相机是人工设置的，结果是接口验证；没有生成VMem视频，也没有评测预测准确率。

## 为什么先做这一步

以前S6/S8查询位置来自已经存在的目标照片。真正生成新画面时，目标照片还不存在；继续在旧查询特征上找相关，并不能解除这项输入依赖。本轮近邻原文和官方源码核查确认：CUT3R已有direct ray-only入口，因此先验证该入口在当前本机和权重上能用。它是现有能力的正确接入，不作为创新贡献。

普通目标覆盖/一致性设计保留在S14D_TARGET_VIEW_DESIGN_DRAFT.md，本轮没有重跑旧24查询或挽救S14C已否定的粗分散代理。近邻对照见S14D_TARGET_VIEW_NEAREST_METHODS.md，覆盖、MVS一致性、I3DM与VMem的目标视角机制均已有先例。

## 输入和实现的限制

- K采用官方viewer的pseudo intrinsics，f=sqrt(224²+224²)、主点112；不是TUM标定K。
- 射线沿用官方 `ro=t; rd=normalize(R K^-1[u,v,1]+t)`，含平移项。这不是通常的纯方向射线，本次没有私自改成另一公式。相机`camera_pose`字段用于记录，实际direct条件来自ray_map。
- query使用官方direct inference_step，不能默认等同mixed image/ray前向；没有新形状兼容补丁，仅复用之前验证的signed RoPE层。
- 独立公式使用预先规定atol1e-6/rtol1e-5；最大总体数值差6.022567333729967e-6来自pseudo K的FP32/FP64舍入，最大逐射线差3.509282475722131e-8，20相机解码最大差5.4028793883276194e-8。状态与dummy比较保持精确，不放宽门限。
- 当前相机位置为人工条件，没有相应的独立实测目标答案。输出能变、状态不变，只解决接口可用性，不证明选图/记忆算法变好。
