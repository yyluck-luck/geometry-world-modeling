# 每20分钟科研流程检查

用户于2026-09-06明确要求定期检查是否遵循skills、是否推进创新、是否记录、是否使用本地工具和网络检索，并继续科研；当前频率为每20分钟。此文件给当前聊天的定时接续提供稳定方法；计划频率由应用内定时任务管理，文件本身不是调度器。

## 每次先恢复真实状态

读取项目AGENTS、RESEARCH_MEMORY、最新RESEARCH_LOG，检查已有模型/实验/下载进程与未完成agent。不要根据旧交接快照重跑成功实验。主账位于本项目；用户材料在当前工作区outputs。若上次因服务错误中断，先检查产物是否已保存，再接着未完成工作，不能把中断当实验失败。

## 七项检查，必须有具体证据或不适用原因

| 检查 | 要核对的事实 | 不通过时如何处理 |
|---|---|---|
| Skills实际执行 | 当前阶段选择了哪些Supervisor技能、读了哪个SKILL/参考文件、执行了哪些步骤、对应产物是什么；Claude本地技能是否适用 | 补读适用内容、补齐缺失门；写清局部应用与未执行项。不为数量套无关skill，也不把阅读当完成。 |
| 创新与反证 | 假设是什么、相对最相近原文新增在哪里、什么结果能推翻、当前是已证实/待验证/否决哪一种 | 用原始论文定点检索找反例；同信息/同监督/同容量基线不足时先补协议。没有新颖性证据就保持待验证，不保证老师反应。 |
| 实验真实性 | 输入域、主设置/敏感性、候选/输出/计算预算、GT隔离、运行前冻结、失败保留、独立复核是否实际完成 | 记录偏差并修正后续流程；不回改旧冻结、删失败或用相关条件冒充独立样本。 |
| 本地工具使用 | 有无具体本地脚本、rg、Python环境、数值复算、LaTeX/Draw.io/绘图等可查产物；工具是否适合当前问题 | 优先复用现有依赖/权重；有明确需要再调用工具，不强制每轮开图形应用或重复模型。 |
| 网络检索 | 新颖性、近邻方法、时变依赖是否已有原文URL/版本/访问记录；哪些问题尚缺来源 | 有新事实需求时补查权威原文，保存查询和证据；没有新检索需求时记不适用及原因，不机械重复。 |
| 多agent与审计 | 有可独立并行的实质子任务时是否分派；实现、数值/文稿复核角色是否清楚；进程错误是否记录 | 任务边界清晰后并行；服务失败保留已落盘结果、合理接续，不能把同作者自检写成独立审计。 |
| 记忆与交付 | 每次开始/完成/失败/修正/转向均有实际发生及记录时间、动作、结果、证据、下一步；主记忆与最新输出一致 | 通过scripts/research_log.py追加；历史补记说明时间来源。同步交接和用户快照，不能把时间差当学生工时。 |

每项状态使用 `PASS`、`ACTION_REQUIRED` 或 `NOT_APPLICABLE`，附证据路径和判断依据。创新候选尚待验证不是流程失败；把它宣传成已成立才是问题。独立审计正在运行不等于没做，记录其真实进度。

## 记录与继续

每轮向 `workflow_checks.jsonl` 追加一条：实际UTC和北京时间、检查区间、七项状态/证据、发现、已做纠正、下一步。另用 `scripts/research_log.py` 记本轮检查结论与实质行动；RESEARCH_MEMORY只保留最新进展和待办。正常检查也留本地记录，但是否通知用户由本任务提醒偏好决定。

检查后执行最重要的本机可行下一步，不只循环生成检查报告。新实验按照独立审读、冻结、执行、复核、解释、交付顺序；结果已看过的探索要明示。失败或否定结果也可构成有效研究进展。

保留授权边界：可自主本地读写、实验准备、检索与研究报告；不发送导师消息，不填造会议/工时，不申请需个人信息的模型权限，不调用Claude模型（只使用其本地skills）。完整视频、课程提交和导师评价按真实证据验收。
